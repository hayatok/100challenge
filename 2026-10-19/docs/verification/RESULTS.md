# 残響の魔女 3分版のローカル検証

## 目的と範囲

Sol（gpt-6.1-sol、推論max）がGodotのゲーム本体、UI、戦闘と残像のモデル、効果音、productionテストを実装した。親エージェントがSVG原稿、Web起動、実行スクリプト、文書、ブラウザ検証を統合した。作業ブランチはcodex/echo-witch、開始コミットは7f844b90cb41d28f871482a72afdf93a419e6704。今回の範囲は実装・ローカル検証・レビュー・PRまで。公開とreleaseタグ作成は行っていない。

## コマンドの結果

- アプリの`npm run check`：Godot 4.7.2のインポート、productionテスト36項目、単一スレッドWeb出力が成功。
- ルートの`npm test`：38テストが成功。既存カタログと変更対象の選択を含む。
- `git diff --check`：成功。
- `npm run setup`：ローカルにあるGodotとテンプレートの版を確認。Linux用ダウンロードはCIで別途確認する。

productionテストは2秒の位置補間、遅延攻撃の境界、発射時の威力と弾数の保持、再照準、再帰しない残像、停止中の敵予告・弾・演出・履歴、強化、無敵時間、勝敗と初期化を実際のゲームモデルで確認する。

## 通常速度のWebプレイ

Chromeの実キー入力をPlaywrightで送信し、時刻・HP・位置を変更するAPIを使わず、180秒を生存した。これは自動操作による動作確認であり、人間が遊んだ面白さの評価ではない。

修正後の通しプレイは生存180秒、討伐550体、Lv.15、HP58。本体の発射304回、残像の発射299回、観測した同時敵数の最大は80体。計測ループの実時間は182.481秒で、強化選択の停止を含む。前半の移動・Esc停止、強化中の停止、勝利、Enterによる再挑戦、履歴の初期化を確認した。通常プレイのconsole errorは0件。

記録は[最終の通しプレイ](browser/final/results.json)、[終盤](browser/final/playing-late.png)、[勝利](browser/final/victory.png)、[強化選択](browser/final/upgrade.png)。最初の実行はゲームを完走したが、WASM取得失敗の案内が出ない問題を発見したため検証全体として失敗になった。[初回の記録](browser/initial/results.json)も保存している。

## 修正と画面の再確認

GodotのWASM取得失敗が未処理のPromise拒否になる場合を、Web起動中のエラーハンドラで受け、再試行ボタンを表示するようにした。WASM取得を中断してエラー画面を出し、遮断を解除して再試行するとタイトルへ戻ることを確認した。エラー画面は[読み込み失敗](browser/final/load-error.png)。

StyleBoxの余白によって罫線や経験値バーが指定より太くなる箇所を修正した。強化カードの内部座標に由来する表示を、太さ・射程・移動速度の増加率や、回収範囲が広がる説明に変更した。ルールと実際の強化量は変更していない。文言の最終変更後はWeb出力を作り直し、[最終画面の確認](browser/post-copy/results.json)でタイトル・強化・休止と、マウスによる月輪習得を確認した。

## 実際のChromeでの操作

Cuaによる通常Chromeのキー操作で、Enter開始、D移動、Esc休止、Enter復帰を確認した。Cmd+Tで別タブを開き、閉じて戻った画面には「画面を離れたため休止。続けるには明示操作が必要です。」が表示され、時計は02:58で止まっていた。TabとSpaceで「音 OFF」「演出軽減 ON」へ変更でき、フォーカスの枠も読めた。

自動ブラウザの`bringToFront`ではdocumentのvisible/focusが変わらず、実際のフォーカス喪失を観測できなかった。自動記録のfocus項目はnullとし、上の実タブ操作で補った。自動ブラウザで観測できなかったことを、ゲームの停止失敗として扱っていない。

## 画面幅と制限

1280×720、1920×1080、960×540でタイトル・本文・操作を表示し、横にはみ出さないことを確認した。390×844ではPCキーボードと横画面の案内を表示する。画像はbrowser/final/の各解像度を参照。文字、帽子、輪、武器、敵の予告を、[配置見本](../reference/play-layout.svg)と実画面で見比べた。見本は設計用の静止画で、実プレイとは別の資料である。

主対象はPC。タッチ操作、Safari、Firefox、スマートフォン実機は未検証。Headless ChromeはソフトウェアWebGLを使う場合があり、実GPUの速度測定とは扱わない。敗北はproductionテストで確認し、実キーの通しプレイでは勝利画面を確認した。難易度、残像による位置取りの楽しさは、ユーザーの試遊で引き続き確かめる必要がある。
