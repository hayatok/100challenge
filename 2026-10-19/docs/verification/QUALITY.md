# 第2版の評価と検証

## 目的と変更範囲

ユーザーの「グラフィック、ゲーム性、面白さを全て再評価し、クオリティアップする」という依頼に対応した。開始コミットはe4cc52d。ゲームのルールとモデル比較は引き続きSol maxが担当し、親が描画、素材、UI、音、Web検証を統合した。3分・1面・2武器・敵3種、移動と自動攻撃を維持した。公開、タグ、mainへの統合は行っていない。

## 評価と改良

| 初版で弱かった点 | 第2版で変えたこと | 確認方法 |
| --- | --- | --- |
| 長い射程と一撃の雷で、残像の位置を意識する利点が弱い | 射程と敵の耐久を調整し、離れた本体と残像の命中に挟撃の追加ダメージと経験値を付けた | 成立・不成立・再発動・経験値制限のモデルテストと実キー操作 |

## コマンドとモデル比較

`npm run check --prefix 2026-10-19`が成功した。Godot 4.7.2のインポート、92項目のproductionチェック、Web出力を含む。ルートの38テストと`git diff --check`も成功した。作業中に全体用の`npm run check`を誤って起動し、対象外の2026-09-01で未導入のoxlintにより停止したため、全体チェックを成功とは扱わない。対象を絞った検証へ戻し、対象外アプリの依存導入やソース変更は行っていない。

[モデル比較](model/balance-summary.json)は3種類の定型移動と3専門化を各3seedで比較した27本。[条件と選択方針](model/balance_compare.gd)、[全結果](model/balance-final.jsonl)、[productionの結果](model/production.log)を保存した。反応回避や実画面の操作は含まない。

大周回では雷2/3、月3/3、残響1/3が180秒生存。最終Lv.9〜11、120秒以降の強化間隔は17.1〜31.25秒だった。直線と固定の左右折り返しは各0/9だった。これは少数の固定条件の比較であり、人間の勝率、統計的な優劣、面白さの採点ではない。残響の専門化には引き続き難度の差が見られる。

## 通常速度のWeb操作

[通しプレイ](browser/quality/results.json)では時刻・HP・位置を変更するAPIを使わず、実キーの自動入力で180秒を生存した。月の魔女、討伐456体、Lv.13、HP2、挟撃158回・挟撃による討伐142体。計測ループは実時間181.626秒で、強化選択の停止を含む。観測した同時敵数は最大53体。実行中のconsole errorは0件だった。

6節と回収の間、専門化を一度選ぶこと、挟撃、Esc停止、強化中の停止、勝利後の再挑戦を確認した。音楽の開始は休止と強化を挟んでも1回だった。音OFFと演出軽減ONをマウスで変更し、その後は実キーで敵へ接近して18.8秒で敗北。HPゼロの結果画面と、再挑戦による履歴・専門化・挟撃回数の初期化も確認した。

1280×720、1920×1080、960×540の表示、390×844のPCキーボード案内、WASM取得の遮断から再試行してタイトルへ戻る流れを確認した。自動ブラウザでは実際のfocus喪失を観測できず、その項目はnullで残している。通常Chromeのフォーカス喪失は初版の実タブ操作で確認済みだが、第2版で実タブを切り替える再検証は行っていない。

## 音声メモリ問題と修正

第2版の[最初の通し確認](browser/quality-memory-failure/results.json)では32.7秒以降に進行が止まり、16秒BGMに対応するWeb AudioのcreateBuffer失敗が出た。検証用rendererのRSSは11,602,576 KiBに達したため、その検証用Chromeだけを停止した。

毎physicsの再生状態ポーリングから再生を繰り返す経路を、状態遷移と開始フラグに変更した。休止と強化では同じ音声を一時停止し、結果・音OFF・再挑戦では停止する。Web内部で再生状態がfalseを返し続けた理由までは確定していない。

画像と描画条件を保った再実行で180秒を完走し、開始回数1、音声エラー0を確認した。[10秒ごとのメモリ記録](browser/quality/memory-samples.jsonl)では、各計測で最大のrenderer RSSが846,944〜1,192,464 KiBの間で増減し、最後は978,176 KiBだった。実GPUの速度測定や、長時間の安定性を保証する試験ではない。

## 最終の画面確認

通しプレイの画像で、経験値バーと挟撃表示の重なりを見つけて配置を修正した。タイトルと停止中の同じ画面は再描画せず、ゲーム時刻・状態・演出設定・画面サイズが変わった場合に更新するようにした。ゲームのルールは変更していない。

その後のWeb出力で[最終UI確認](browser/quality-final-ui/results.json)を行い、タイトル、プレイ中のHUD、強化、専門化、ポーズと960×540の表示を確認した。マウスで残響の魔女を選び、復帰後の音楽開始も1回、console errorは0件だった。[最終のプレイ画面](browser/quality-final-ui/after-specialization.png)と[専門化の画面](browser/quality-final-ui/specialization.png)を保存している。カタログの画像は第2版の実タイトル画面へ更新した。

通常Chromeでも変更前の開始・移動・残像・停止を操作し、第2版の読み込みを確認した。その後はユーザー側の状態変更があったため操作を止め、残りは検証用ブラウザで進めた。ユーザーのChromeの別タブやゲーム進行を操作していない。

## 日本語・独立レビューと限界

今回変更した日本語を開始時の原文と比較し、yomiyasuのrunと実ファイルのverifyで照合した。GDScriptの構文と、意図して変更したゲームの数値・状態を区別する。詳細原稿は公開対象に含めない`.yomiyasu/`へ保存し、対象と保持理由は[japanese-review.json](japanese-review.json)へ記録した。Astraによる完了前レビューとCIの最終結果はPR #195と完了報告に記録する。

主対象はPC。Safari、Firefox、スマートフォン実機、タッチ操作、音楽の実機での聴感比較、長時間のプレイは未検証。Headless ChromeはソフトウェアWebGLを使う場合がある。エージェントの設計評価、モデル比較、自動操作、人間の試遊はそれぞれ別の確認であり、人間による面白さ・難易度の評価は今後の試遊で確かめる必要がある。
