# 残響の魔女 デザイン指針

## 目的と判断の基準

「夜の魔術書に残響を書き足す」を画面と演出の指針にする。戦う場面では魔女と敵の動き、選ぶ場面では魔法の変化、踏破した場面では夜を越えた達成を主役にする。配色、文字、枠、図柄、動きと音を同じ意味で使う。

基準の実装は3c43603。既存の三章、2秒前の残像、武器・遺物・専門化・進化・保存・敵AIと戦闘のルールを保つ。今回はタイトル、戦闘HUD、強化と宝箱、章間、結果、休止・設定・図鑑の構図と反応を作り直す。実装とローカル検証、独立レビュー、既存PR #197とIssue #196の更新までを扱う。

## 現行画面で見つかった問題

- 常時表示のHUDが横一列に広がり、HP、章、時計、討伐、目的の強弱が小さい。下段では空き枠の説明が繰り返され、戦場より文字が目立つ。
- 強化、休止、章間、結果が同じ大きさの暗い長方形を共有し、選択・休息・達成の違いが構図に出ていない。
- 図柄の描画が固定寸法のため、章印や図鑑の大きい枠でも図柄が小さい。
- タイトルの挿絵に対し、操作群が汎用ボタンの並びに見える。戦闘の瞬間と報酬の節目も、光を足すだけでは強弱がつかない。

## 共通の造形と役割

造形は頁の重なり、綴じ目、栞、二つの輪に絞る。細線を外周に足すだけで魔術書を表さず、紙・表紙・金具の面と余白で構造を見せる。暗い革の表紙と温かい紙面を使い分ける。文字の背後には読み取れる面を置く。

| 役割 | 色と扱い |
| --- | --- |
| 夜と表紙 | #0B1120 / #141E30。戦闘HUDと画面の外周を支える |
| 紙面 | #E9DFC7 / #F5ECD8。選択頁と見開きの記録に使う |
| 敗北の紙面 | #D1DCE1 / #E6ECEA、端#8497A5。休止の暖色と分ける |
| 紙面の本文 | #243038、補助#52606A。明るい面で白文字を使わない |
| 暗い面の本文 | #F5EAD4、補助#C4BDB0 |
| 本体・決定・獲得 | #E9C780。紙面では#8C652D。栞と印を伴う |
| 残像・時間差・強化後 | #94D8E9。紙面では#276A86。二重の輪と矢印を伴う |
| 敵・被弾・危険 | #FF8B76。紙面では#9D3D4B。予告線と文字を伴う |

共通UIの明るい操作面に対し、戦闘と表紙は夜の濃色へ変更する。紙面では共通UIと同じく濃い文字を使う。色だけで状態を区別せず、形・文言・位置を組み合わせる。役割色と寸法は`game/scripts/grimoire_theme.gd`へ集約する。

本文は同梱のNoto Sans CJK JP Medium、見出しはZen Old Mincho Bold。書体とOFLは既存のものを使う。1280×720で本文20〜22px、補助18px、画面見出し32〜36px、節目48px、タイトル70pxを基準にする。戦闘の装備名だけは18pxを下限とし、詳細は休止の装備欄へ置く。余白は8・16・24・32px。主操作の高さは56〜64px、その他も44px以上にする。

## 画面ごとの構図

| 画面 | 主役と配置 |
| --- | --- |
| タイトル | 左約520pxを題字と金の栞形の開始操作、右を挿絵の魔女と残像にする。開始魔法は図柄付きの小さい選択欄。図鑑と設定は軽い操作列、三章の進捗は小さい章印でまとめる |
| 戦闘 | 上段は左にHP、中央に章と時計、右に討伐と休止。通常時は上約84pxまで。固定の目的文は外し、導入案内は上段直下へ。下は魔法3枠の図柄・名前・Rank目盛り、小さい遺物札、細いXP線。空き枠の説明を繰り返さない |
| ボス戦 | 上段の下に幅約600px・高さ56px以内の名前とHP。ボス登場や第二形態の通知はさらに下の安全域に一つだけ出す |
| 強化・宝箱 | 三つの紙の頁を24pxの間隔で並べ、80〜96pxの魔法印、名前、効果、現在から取得後の変化、進化条件の順に読む。フォーカスは金の栞と輪郭。失うものと得るもの、枠、弱点を省略しない |
| 章間 | 三つの章印を道程線で結ぶ。踏破済みと次の章は印・大きさ・文言で分け、回復と解放を報酬欄へ置く |
| 勝利 | 夜明けの大きな印と見出し、主要記録、三章の踏破、実際の解放を見せる。内訳は静かな記録欄へ。表示するためだけの点数やランクは作らない |
| 敗北 | 冷たい夜の構図で最後の被弾原因と再挑戦を上げる。結果の読解や演出を待たず再挑戦できる |
| 休止・設定・図鑑 | 見開き。左に操作または索引、右に装備または詳細。綴じ目と頁の端で区切る。フォーカス、無効、保存失敗、戻る先を明示する |

通常戦では中央約1000×430pxを長文や大きいパネルから空ける。図柄はControlの実寸へ等比で拡大し、HUD48px、選択頁80〜96px、図鑑112px、章印96〜144pxを使い分ける。床の線と地紋はキャラクターより弱くし、障害物の縁・影と赤い予告は読める状態を保つ。キャラクターの大きさと衝突形状は変えない。

## 動きの文法と上限

「筆跡が現れる、二つの印が重なる、静まる」を共通の順にする。通常命中は0.08〜0.16秒の小さい芯、挟撃は0.3〜0.45秒の青と金、進化・ボス・章は大きい印と一つの通知で段階をつける。大きい画面全体の点滅は加えない。敵の攻撃予告を味方の演出より手前に描く。

頁は固定した位置で罫線・図柄・獲得印を0.14〜0.2秒で見せる。主操作は最初から受け付け、押す位置を動かさない。休止は即時表示。通常の画面移動より、章と勝利を大きい節目にする。戦闘中の動きは戦闘時刻に従い、選択とフォーカス喪失で止める。再挑戦と章変更で残留を消す。演出軽減では揺れ、伸縮、装飾の移動を止め、意味を伝える印と短いフェードを残す。

追加粒子は一度の描画で96枚、保持する演出は80件、消滅は24件、カメラは最大3.5pxを維持する。静的な紙面・枠・図柄は保持し、毎フレームの作り直しを避ける。音は既存の合成音と音量設定を使い、停止条件を保つ。

## 完了条件

1. 指針に沿ったタイトル・HUD・選択頁・章間・結果を、同じ1280×720の変更前後の実画面で比較する。配置見本と通常プレイの記録は区別する。
2. 表紙、戦闘、強化、勝利、休止が、文字を読まなくても構図で見分けられる。開始、選択、再挑戦の主操作が先に見つかる。
3. 通常・文字拡大の全画面で本文、長い名前、数値、条件、キーボードフォーカスに欠落・重なり・はみ出しがない。960×540と1920×1080でも操作できる。
4. 通常速度のWeb入力で成長・宝箱・ボス・章間・結果・再挑戦を通し、休止、設定、演出軽減、保存と失敗からの復帰を確認する。
5. 適切なGodot検査とWeb出力、日本語の原文保存・run・実ファイルのverify、Astraの独立レビュー、PRとCIの確認をそろえる。自動入力の成功を人間の初見の面白さや実機の性能保証にはしない。
