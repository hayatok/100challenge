# 残響の魔女の開発指示

ルートのAGENTS.md、docs/DESIGN.md、docs/FRONTEND.mdを併用する。

## 今回の目的

公開済み3分版を、庭園・書庫・塔を続けて攻略する本編へ拡張する。承認された計画はIssue #196とdocs/CAMPAIGN.md。今回の依頼は実装であり、ローカル検証、独立レビュー、PRまでを扱う。公開とmain統合はこの実装の完了後に扱う。

## 設計と範囲

- 2秒前の位置と発射内容を再現する無敵の残像を中心に、地形と敵の組み合わせで周回・切り返し・回収を使い分ける。
- 各章の通常戦は180秒。その後に固有ボスを倒し、装備と専門化を引き継いで次章へ進む。最後のボスを倒すと勝利、HPゼロで敗北。時間切れの自動勝利は使わない。
- 武器6種から3枠、遺物12種から3枠、武器進化、3系統の専門化、宝箱、拾った場で使うドロップ品を作る。図鑑、開始武器の解放、設定と記録のブラウザ内保存を扱う。
- Godot 4.7.2、Compatibility描画、単一スレッドWeb出力。PC横画面1280×720を主対象とし、小さい横画面と縦画面の案内も確認する。タッチ操作は対象に含めない。
- 外部通信とアカウント、新しいJavaScript依存は追加しない。画像とフォントは同梱し、出典とライセンスを残す。
- 残像の攻撃には元の発射時の種類、威力、形、遺物の補正を保存し、再生時に近い敵へ再照準する。残像の攻撃は再録しない。章を移ると攻撃と位置の履歴を消し、新しい2秒分を記録する。
- 移動、攻撃履歴、敵、予告、演出は、ポーズ・強化・宝箱・章間・フォーカス喪失で一緒に止める。復帰には明示操作を要し、再挑戦で戦闘の状態を初期化する。
- 地形の描画と衝突は同じ定義を使う。必須の進路に袋小路を作らず、敵の経路と安全な出現位置を確認する。
- テスト用の状態読取はWebの読み取り専用状態に限定し、時刻、HP、進行を変える機能を出荷UIへ追加しない。
- アプリ固有のコード、素材、文書、テストと検証記録はこの日付フォルダ内に置く。原文と日本語の検査記録は公開しない.yomiyasu/へ置く。

## 検証

npm run checkでインポート、ルールテスト、Web出力を実行する。通常速度で庭園の導入からボス、本編3章の進行、敗北、再挑戦、図鑑と保存を実際の画面で確認する。画面と数値の検査、自動入力、人間の試遊を区別してdocs/verification/へ残す。日本語はyomiyasuのrunと実ファイルのverifyで照合する。完了前にai_slop_reviewer（gpt-6-astra）のレビューを受け、修正後も確認する。
