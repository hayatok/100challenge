# 音声の切り出し

音声ファイルを端末内で読み込み、必要な範囲を選んで試聴し、MP3またはM4A（AAC）で保存する静的Webアプリ。Issue [#188](https://github.com/hayatok/100challenge/issues/188)。

## 使い方

1. 音声ファイルを選ぶか、画面にドロップする。8秒の生成サンプルでも試せる。
2. 波形をドラッグして残す範囲を選び、両端のつまみ・時刻入力で調整する。
3. 選択範囲を試聴する。ループ再生、波形の16倍拡大、キーボードでの調整も使える。
4. MP3 / M4A、128 / 192 / 256 kbps、保存名を指定して書き出す。
5. 結果の音声を確認し、「ファイルを保存」を押す。

時刻は `01:23.456` または `83.456` 秒で入力する。つまみにフォーカスすると、矢印キーで0.01秒、Shift併用で1秒、Alt併用で0.001秒ずつ調整できる。フォーム外ではSpaceで試聴・停止する。

## データと対応範囲

- 音声・ファイル名・編集内容を外部へ送信しない。解析・広告・外部フォント・外部CDNを使用しない。
- ページ表示時に同梱コードとMP3/AACエンコーダーを準備する。「準備完了」の後は、通信を切ったまま読込・範囲選択・試聴・両形式の保存を行える。オフラインでのページ再読み込みや再訪問は保証しない。
- ファイルをブラウザの永続ストレージへ保存しない。必要な出力だけ明示的にダウンロードする。元ファイルは変更しない。
- 入力は64MiB・10分以内、モノラルまたはステレオ。ブラウザとコンテナ解析が対応する音声が対象。MP3 / M4A / WAVの実ファイル読込を確認済み。
- 編集・出力は48kHz。M4AはAAC-LCをMP4コンテナへ格納する。出力に元ファイルのタグを引き継がない。
- 圧縮形式のエンコーダーの遅延や末尾のパディングにより、出力には数十ミリ秒程度の余白が付くことがある。結果欄の「選択範囲」は編集時の区間長で、圧縮後の厳密なファイル長ではない。
- 主対象はデスクトップChromium。375/768/1440pxの表示を確認。Safari・Firefox・実機スマートフォンは未確認。

## 実行と検証

Node.js 24を使用する。

```bash
npm ci
npm run setup
npm run dev -- --port 4188
```

```bash
npm run check        # 単体7件、lint、型、build、実ブラウザ10件
npm run test:e2e     # distを使った実ブラウザ検証のみ。事前にbuildする
npm run preview -- --port 4189
npm run verify:aac   # AACの対応ソース・ローカルパッケージ・同梱WASMを照合
```

公開先を検証するときは、`AUDIO_TEST_URL=https://hayatok.github.io/100challenge/2026-10-18/ npm run test:e2e`を使う。ローカルサーバーを起動せず、指定したURLで同じブラウザテストを実行する。

`setup`は検証用Chromiumをインストールする。アプリの利用者にはインストール不要。`check`のブラウザテストはローカル限定プレビューを起動する。ビルドした`dist/`を任意の静的HTTPサーバーで配信でき、サブディレクトリ配信に対応する。

## 実装と依存

React + TypeScript + Viteで実装した。デコードと試聴にはWeb Audio、エンコードにはMediabunny 1.61.6とMP3/AACエンコーダー拡張を使う。AACはFFmpegの固定ソースから再ビルドし、ローカルパッケージとして同梱する。ブラウザごとのAACエンコーダー実装の違いに依存せず両形式を保存するため、両WASM拡張を採用した。workerとWASMはアプリに同梱するため、外部の処理サーバーや追加ダウンロードを必要としない。

| ファイル | 役割 |
|---|---|
| `src/App.tsx` | 状態と一画面の操作 |
| `src/components/Waveform.tsx` | 波形、範囲、拡大、ハンドル |
| `src/audio/engine.ts` | 入力上限確認、デコード、実エンコード、キャンセル |
| `src/audio/usePlayback.ts` | 選択範囲の試聴と停止/後処理 |
| `tests/browser/` | オフライン・保存内容・失敗復帰・画面幅の実操作 |
