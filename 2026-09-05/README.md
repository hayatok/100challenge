# ホコリ無双 — 深夜のおそうじ隊

移動だけでホコリの大群と戦う、6分間の3Dサバイバル。v0.2では掃除した道を戦術に使います。

## 開発

```sh
npm ci
npm run dev
npm run check
```

React / TypeScript / Vite / Three.js / Vitest / oxlint。外部APIやアカウントは不要です。

## 遊び方

- WASD／矢印キー、または画面スティックで移動。攻撃は自動。
- 通った床を掃除。すでに掃除した道を走り直すと速度＋18%。汚れた床では従来の速度です。
- 出発地点から清掃機まで掃除した道をつなぎ、2秒保つと設備が復旧。HP20と経験値5を受け取り、清掃機が周囲を自動清掃します。復旧は副目標で、勝利の必須条件ではありません。
- 45秒から現れる茶色い靴の敵は、通った道を汚します。復旧前の接続は切れますが、一度復旧した設備は停止しません。
- 電池でレベルアップ。3択から装備を選択（数字1/2/3にも対応）。武器は各5段階、最大3枠。
- **泡＋吸引：泡バキューム**。泡の敵を引き込み、周囲も攻撃。
- **泡＋モップ：泡の滑走路**。回転モップが広い清掃帯を作ります。装備を持つと自動成立します。
- 5分でボスが登場。6分までに撃破すると勝利。HPゼロ／時間切れで終了。
- 結果では清掃前後の地図と、残した清掃面積・設備の復旧状況を確認できます。
- Esc／停止ボタン／タブ非表示／フォーカス離脱で停止。再開は明示操作。
- 音は初期OFF。演出軽減では装飾バウンス・回転を抑制し、攻撃範囲・予告は維持。
- 最高討伐数とクリア実績は従来の `hokori-best-v1` に保存。保存できなくてもプレイ可能。

## Blender制作と再出力

**`assets/source/cleaning-kit-v2.blend` が現在の正本**です。v0.1のGUIレビュー済み `cleaning-kit.blend` も保持しています。v2では既存15モデルを引き継ぎ、泥足・清掃機・店舗の3モデルを追加しました。

`extend-assets-v2.py` で部品を組み立て、Blenderをcomputer-useで開いてv2原本をロード。泥足の左右の靴をZ方向に1.4倍へ調整し、木材/泥の材質をHex `AD8260FF` に変更して保存しました。ロボの面取りと材質、店舗と清掃機をゲーム画面でも確認しています。

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --python scripts/export-assets.py
```

エクスポートは保存済みのv2原本を読み、一時コピーの部品を材質ごとに統合してGLB化します。正本を上書きせず、GUIで変更した色や形状を維持します。全18モデルは自己完結したGLBで、合計約1MBです。`public/models/manifest.json` にサイズと三角形数を記録。

`create-assets.py` はv0.1初期制作履歴、`extend-assets-v2.py` はv2初期拡張履歴です。どちらも原本が存在する場合は停止します。v0.1スクリプトの `--rebuild-base` はGUI編集を破棄するため、通常は実行しません。

## 検証と確認画面

`npm run check` はlint・22テスト・型チェック・本番build。移動・勝敗・成長・清掃接続・再汚染・設備報酬・連携・GLB・保存に加え、既存構成3seedと泡を使う2構成各3seedの通し走行を検査します。

DEV限定（本番は無効、確認画面では記録を保存しません）：

| URLパラメータ | 確認対象 |
|---|---|
| `?qa=route` | 汚れた床から通常動作で道を作る |
| `?qa=cleaning` | 清掃済みの道と泥足 |
| `?qa=station` | 設備復旧後の清掃範囲 |
| `?qa=synergy` | 泡＋吸引＋モップの連携 |
| `?qa=upgrade` | 3択と連携予告、数字キー |
| `?qa=boss` | 最終装備のボス戦 |
| `?qa=stress` | 200体を固定した描画負荷（シミュレーション停止） |
| `?qa=won` / `?qa=lost` | 結果画面と再挑戦 |
| `?qa=error` | 初回失敗→再試行→正常読み込み |

確認画面の移動ボタンは入力方向だけを保持し、通常と同じ固定時間のシミュレーションを動かします。移動停止・メニュー遷移で解除。勝利/敗北などのプリセットは実際の通しプレイと区別してください。

仕様は `docs/SPEC.md`、実装計画は `docs/V02-PLAN.md`、検証記録は `docs/V02-VERIFICATION.md`。スマホ実機の通しプレイとGPU context lossの実機検証は未実施です。
