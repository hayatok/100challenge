- ルート `npm test`：38テスト成功。23件のカタログと新規アプリ登録を確認。
- `git diff --check`：成功。
- アセット準備を複数回実行し、固定サイズとSHA-256の検証・再利用を確認。
- OpenCV内のNode用分岐についてfs/path/cryptoのビルド警告が出る。完成ビルドのブラウザ操作では当該分岐の実行エラーなし。

## 実画像とOCR

| 入力と環境 | 実際の結果 |
| --- | --- |
| 日本語サンプル1120×510、開発版、自動選択 | 5行×4列。16非空セルと4空白セルすべて一致。検出/文字認識ともwebgpu、約1.9秒 |
| 同サンプル、x20/y20/幅1080/高さ470で切り抜き、強制WASM | 20セル一致。検出/文字認識ともwasm、約1.3秒 |
| 配布ビルドを `/2026-10-15/` で配信、別の日本語表スクショを画像ペーストして切り抜き | 商品名/りんご/ノート/合計の4行×4列。13非空セルと3空白セル一致。検出/文字認識ともwebgpu、約1.0秒 |
| 配布ビルド、375pxでサンプル画像をドラッグして切り抜き、強制WASM | 5行×4列と空白位置を維持。検出/文字認識ともwasm、約1.4秒 |
| 配布ビルド、1440pxでサンプル全体、自動選択 | 20セル一致。検出/文字認識ともwebgpu、約0.7秒 |
| 同じdistをPython標準HTTPサーバーで配信（COOP/COEPヘッダーなし） | 自動選択は検出/文字認識ともwebgpu、約0.6秒。強制WASMはともにwasm、約1.4秒。両方20セル一致 |

実行時間はこの端末とキャッシュ状態での観測値であり、他端末やGPU間の性能比較ではない。選択セルの元画像内の認識領域を強調することも確認した。

## 入力・編集・出力・回復

- 画像ペーストを配布ビルドで確認。ファイル選択ダイアログからPNGを名乗る不正ファイルを選び、形式検証で拒否し、既存の画像・編集表を保持した。
- ドラッグ範囲指定を実操作し、元画像座標x20/y19/幅1080/高さ470への変換を数値欄でも確認。数値指定・全体へのリセットも確認。
- `ノート`→`リングノート`の編集、Undoで元に戻ること、Redoで再適用することを確認。空欄へ`0012`を入力できる。
- 行追加で6行、Undoで5行へ戻す。列追加で5列、追加した空列の削除で4列へ戻す。既存の値と空白位置を維持した。
- TabでA2→B2、EnterでB2→B3へ移動。375pxで右端D5を選べ、編集表内部の横スクロールを確認。最終UIではD4→A4へ戻るとscrollLeftが0に戻り、固定した行番号が先頭文字を隠さないことも確認。
- 「表をコピー」成功後、実クリップボードのtext/plain（TSV）とtext/html（table）を読み、5行×4列、空欄、`0012`、編集値を確認。[実データ](clipboard.json)。式`=SUM(1,2)`のアポストロフィ保護と、改行を含むセルのTSV引用も確認。
- CSV保存ボタンで実際に133byteのファイルをダウンロード。UTF-8 BOM、カンマ区切り、CRLF、空欄、編集値、`0012`をバイト列から確認。
- 幅16pxの範囲では「範囲が小さすぎます」と表示し、既存の表を保持。範囲を直して再認識できる。
- 認識中のキャンセルで入力・表の操作に復帰し、新しいWorkerによる再認識成功。古い結果は適用しない。
- 白一色640×360のPNGでは「文字が見つかりませんでした」と表示。空の4行×3列表を作成し、手入力とコピーへ復帰できる。
- 作業リセットで画像・表・履歴が初期状態へ戻る。ページ移動後も画像・結果の自動保存はない。
