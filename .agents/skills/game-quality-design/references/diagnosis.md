# 診断と試験

## どの関係が体験を妨げているか

すべての項目を採点する表ではない。狙う体験と、実際に弱さが起きる場面を結ぶために使う。企画段階では成立しそうな関係と破綻しそうな条件を示し、遊べる版では同じ場面を操作して確かめる。

| 関係 | 調べること | 原因を分けるための問い | 変更の候補 |
| --- | --- | --- | --- |
| 狙う体験と行動 | 実際に多くの時間を使う行動が、目指す体験につながるか | 緊張を狙うのに移動ばかりか。穏やかさを狙うのに締切ばかりか。人物を知りたいのに報酬の回収ばかりか | 行動の順序と頻度、繰り返す長さ、場面の目的 |
| 状態とルール | 状況が変わると、できること・考えること・解釈が変わるか | 規則が増えただけか。何をしても同じ結果か。同じ操作でも異なる技能や発見を使うか | 状態の組合せ、行為の効き方、情報の段階、制約の強さ |
| 入力と反応 | 意図した操作ができ、行動の結果を感じ取れるか | 何が可能か分からないのか。押しても反応が遅いのか。反応はあるが主役や進路を隠すのか | 入力受付、誤操作からの復帰、音・動き・文字の強さと時刻、操作後の待ち |
| 学習と次の行動 | 初めての状態を理解し、結果を次に生かせるか | 未知の規則か、見えない状態か、誤解した因果か。失敗後に何を変えられるか | 導入する順序、練習できる場面、結果から原因へ戻る表示、やり直す範囲 |
| 短い活動と長い進行 | 今したことが次の目的・準備・場面へどう渡るか | 稼ぎ直しだけか。成果はあるが用途が分からないか。先の目的が現在の遊びを作業にしていないか | 成果の用途、目標の見せ方、活動の切替、失敗後に残る変化 |
| 人物とプレイヤー | 相手を知る場面、選んだ意図、返る応答がつながるか | 選択肢の口調と実際の台詞は合うか。人柄を知る前に重大決断を迫るか。反応はその人物らしいか | 相互行為、台詞の表現、間や視線、過去の関わりへの応答 |

入力・反応の時間的な評価はこの14作品の静止画調査からは得られていない。実機で確認するための診断項目である。動画の数フレームだけを見て「気持ちよい」「テンポがよい」と結論しない。

## 一つの場面を記録する

評価の根拠を次の関係で短く残す。予算や危険がない場面では、無理に代償を作らず、何を試し、何を発見し、どう意味が変わるかを書く。

> プレイヤーの目標と、本人が今知る状態 → 意図して行うこと → 入力と反応 → 実際の結果 → 次の行動・理解・感情への影響

推理なら「どの語句を疑う→どの証拠で説明する→応答でどの解釈を改める」。人物交流なら「何を覚えている→どう接するつもりで選ぶ→相手がどう応じる→相手や自分をどう見直す」。最適化できる二択だけを判断と呼ばない。

必要な情報が出ていない問題と、規則を理解しても退屈な問題を分ける。後者へ説明文を増やしても、行動の単調さは直らない。前者へ新しい仕組みを増やすと、理解の負担が増える可能性がある。

## 根拠の役割を限定する

| 根拠 | 支えること | それだけでは支えないこと |
| --- | --- | --- |
| マニュアル・公式のルール説明 | 記載された処理、入力、表示の意味 | プレイヤーが理解したか、楽しかったか |
| 開発者の説明 | 目指した体験、設計上の苦労、変更理由 | 意図どおりの体験が全員に起きること |
| コミュニティのルール資料 | 記述された手順や仕様の候補。対象版と出典を残す | 公式仕様であること、現行版での一致 |
| 公開静止画・編集映像 | その画像に読める文言、配置、表現 | カット間の連続、選択後の結果、操作感 |
| 入力と前後を追ったプレイ | その条件で起きた結果、処理や操作の確認 | 他の条件やプレイヤーにも同じ体験が起きること |
| プレイヤーの試遊と聞き取り | その人の行動、解釈、体験の評価 | 対象層全体での効果、変更の因果の確定 |

物語の攻略で分かる将来の死亡や分岐を、プレイヤーに事前表示される条件として書かない。未知でも、選択肢の言葉や現在の状況から意図を持てるか、結果が後から納得できるかを調べる。

転載や同じWikiからの集約を、複数の独立した裏付けと数えない。第三者の設計記事がデータ解析を称していても、公式の現行仕様へ格上げしない。細かな数値が転用に不要なら省き、確かめたい関係だけを条件付き仮説として使う。

## 変更案を比べる

最初に原因の仮説を一つ置き、直接変える部分を選ぶ。たとえば「仕事を見送る結果が分からず、交流を避ける」なら、仕事を増やす前に、見送った結果を説明する案を試す。「交流相手を知る場面がなく興味が持てない」なら、報酬の説明でなく相互行為を試す。

代案を比べる際は、狙う効果だけでなく、新しく増える負担と壊す良さを述べる。予告を増やすと驚きを失う、再挑戦を短くすると覚えた経路が不要になる、誤答ヒントを詳しくすると推理を代行する、などを失敗候補にできる。これらは対象で確かめる仮説であり、普遍的な悪さではない。

## 小さく試す

1. **対象と条件をそろえる。** 遊び手の経験、本人の目的、開始状態を記録する。主要な変更を絞り、効果が出るはずの状態と、出ないはずの状態を用意する。同じ人が答えを覚える課題は、同一問題の再試行を比較材料にせず、別の同程度の問題や別の参加者を使う。
2. **行動と体験を分けて見る。** 理解や原因の予測、操作の成功、選んだ理由、発見・愛着・達成・苛立ちなど狙いに合う受け止め、次に自分から何を試すかを記録する。考えを声に出すと操作や感情を妨げる場面では、直後の振り返りを使う。
3. **説明を崩す結果を決める。** 「表示は理解したが人物に関心を持てない」「正答したが根拠は総当たり」「勝てたが入力が不快」「反復を短くしたら落ち着く時間もなくなった」など、狙いの達成を確認できない結果も書く。
4. **外れ方から次を選ぶ。** 変更が届いていないのか、原因の仮説が違うのか、狙いに合っていないのかを分ける。少人数の感想を一般的な効果とせず、次の変更や調査の判断材料にする。

選択比率を均等にすること、説明を速くすること、勝率を上げることを、どの作品にも要求しない。正解にたどり着く推理では納得した根拠を、人物への決断では覚えた関係と言葉にできる意図を、操作の気持ちよさを狙う遊びでは入力と反応を中心に評価する。
