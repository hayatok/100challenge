# 夜勤タイピング 固有方針

## 作業範囲

2026-09-28にユーザーから開発着手の指示を受け、Web + Three.js の初版を実装中。README と docs を読んでから作業する。公開は未指示。数値目標と実測値、生成参考画像と実ゲームの画面を区別する。
実行: npm ci / npm run dev。検証: npm run check（コアテスト、lint、型チェック、production build）。ブラウザでの操作結果は docs/RESULTS.md に記録する。

## 品質の優先順位

1. 入力判定が自然で、正しい表記を誤答にしない。
2. 一文字のヒットと単語の撃破が気持ちよい。
3. 敵・出題・危険度が最高演出中も読める。
4. 静止画でも魅力のある舞台と、予備動作・重さのある敵の演技。
5. 短い一周の緊張、解放、ボス、結末。

## 制作・技術

- 推薦は Web + Three.js。Godot を採用し直す場合は TECH_DECISION.md の条件で理由を更新する。
- 入力・戦闘状態を演出の再生完了に依存させない。キーイベントを途中で失わない。
- 毎フレームUI全体を作り直さない。入力と戦闘の状態は純粋ロジックとして描画から分ける。
- The Typing of the Dead等の既存作品の名称、キャラクター、音声、台詞、ステージ、ロゴは流用しない。汎用の3Dモデル・動作・テクスチャ・音源は利用条件を確認して活用し、作品固有の舞台構成・文章・UI・演出を制作する。
- 承認画像 art/reference/gameplay-approved-v1.png を品質目標にする。街・ゾンビ・銃は立体として描画する。画像を一枚貼った背景や、敵の板ポリゴン化を既定の完成方式にしない。
- 質感と造形の目標はリアル寄り。以前の活字銃・スタンプ撃破・値札コウモリ等の案は採用しない。
- 仮素材での起動成功と、完成素材での見た目・操作確認を分けて報告する。
- アート・音源の制作元、利用条件、加工内容は本フォルダ内に記録する。
- 操作UIはルート docs/DESIGN.md / FRONTEND.md に従う。作品画面の色・字形・演出と、操作部分のテーマ対応は ART_AUDIO.md に定義する。
- Godot を選ぶ場合はシーン・演出を Inspector で編集可能にし、GUI変更→保存→再実行を検証する。

## 検証

- VALIDATION.md の試作ゲートを順に通す。一場面が弱いまま敵・面数・収集要素を増やさない。
- 実ブラウザの物理キーボード、IME、フォーカス、音、最高演出、低モーションを確認する。
- 計測目標、実測値、主観評価を区別する。buildと自動テストだけでゲーム品質を完了扱いにしない。
