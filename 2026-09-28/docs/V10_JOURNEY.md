# v0.10 探る・迫る・解き放つ・息をつく

## Goal / Context
2026-09-29承認の[4場面コンセプト](../art/reference/journey-approved-v10.png)へ向け、単調な直進と同じ距離の戦闘を改善する。画像は生成された品質目標で、実装済みの画面と扱わない。既存Three.js、入力判定、人物/銃/音源を基盤にする。

## Plan
1. 裏路地の進路選択。店内/搬入口で景色・敵構成を変え、移動と戦闘を分離。
2. 場所と向きが変わるカメラ経路。狭い店内、開けた荷捌き広場、階段から屋上の眺望へ。
3. 敵の接近距離・踏み込み・撃破移動を調整。FEVERは一語で3体を吹き飛ばす4連戦、ショットガンへ切替。
4. 静かな環境音、接近予告、発砲と着地で音の強弱。低モーション、休止、入力優先を維持。
5. 両ルート、FEVER成功/失敗、再出勤、屋上、結果を検証。PR/CI/Pagesと公開確認。

## Constraints / Ownership
新規依存なし。生成画像を背景へ貼らず立体構築。既存の人物原型を活用するため造形の品質差は別途報告。サブ担当: district.ts（街）、audio.ts/weapon.ts（音・武器）、game.ts（進行）。主担当: scene.ts/main.ts/UI/経路/統合。既存の通常エンジン挙動は保持し、UIは新しいchapterを使用。採点ルール版を更新して旧記録と比較しない。

## Done when
実入力で分岐→異なる景色→接近戦→集団撃破→屋上→結果を通過。移動中の入力や休止で進行を壊さない。文字と標的が見える。画面の検証、人間の楽しさ、生成コンセプトとの品質差を区別する。まず短い一区画を対象とし、自由歩行/長編/収集要素は追加しない。

## 実装
- `district.ts`で接続した区画を構築。既存の路面/シャッターPBR6枚に、自作Canvasの煉瓦・汚れ・水たまり・看板・空を組み合わせる。配管、棚、青果箱、階段、時計台を立体配置。新規外部素材・依存なし。
- `rail.ts`で進路別の移動と屋上への上昇。戦闘開始とカメラ到着を同じ進行値へ同期。自由歩行ではなく、進路を選ぶレール進行。
- 中庭のFEVERは中央1体の文を完成して左右2体も吹き飛ばす。左右の敵は別の出題/攻撃を持たない。中央失敗時の被害は1体分だけ。成功4群で8体の巻き込み。
- 照明は固定4灯を再利用、開始時に両武器・人物・演出を描画準備。撃破は飛散方向と着地を強調し、敵を隠す正面リングを抑制。
- 雨/風の環境床音、探索/戦闘/FEVER/眺望の音量差、接近音、ショットガン音を追加。既存音素材＋自作Web Audio。銃の追加形状は自作簡易メッシュで、完成した高精細モデルではない。
- 採点版6。旧スコアを新しい章のベストと比較しない。ラッキー報酬はチェックポイントへ保存。

## 次の品質課題
人物の造形と衣服、握り姿勢、ショットガンの曲面、建物の不規則さと遠景密度、自然な照明/反射は承認画像との差が大きい。今回の短い章を人間が試遊し、緊張・解放・もう一度遊びたいかを評価して次の改修を決める。
