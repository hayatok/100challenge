# v0.13 二つの夜勤を、最後まで遊べる長さにする

2026-09-30 / Astraによる実装設計。実装状態・実測結果とは区別する。契約は [V13_CONTRACTS.md](V13_CONTRACTS.md)、受入基準は [V13_ACCEPTANCE.md](V13_ACCEPTANCE.md)。

## Goal / Context / Constraints / Done when

Goalは、既存の商店街の一周を拡張し、別の景色と文章を持つ駅の一周を追加すること。タイトルから両方を選べる。どちらも導入、分岐、緊張、解放、Boss、静かな終わりがある。

Contextはv0.12のThree.js/純粋Game/固定レール、店内立体造形、スキン付き衣装、同時初期キーの分離、四群FEVER、3段階Boss、Lucky、区間retryとブラウザ保存。現行は通常8文、FEVER4文、Boss5文で17必須文。Lucky成功時は20文。主担当のseed12/練習/210KPM一定入力シミュレーションは店内249キー・85秒、搬入口239キー・82秒だった。これは読解/狙いの迷いを含まない計算で、実プレイ時間ではない。

Constraintsは同じ一文字一発の操作、PCキーボード、練習勤務、低モーション、既存素材/ライブラリを維持すること。新ステージのための自由歩行、ジャンプ、時刻待ち、列車乗降、鍵集め、アンロック条件、新武器、新敵AIは追加しない。既存の店内/衣装/銃を簡略化しない。複数面の汎用ゲームエンジンや大規模シナリオDSLは作らない。

Done whenは両面×両routeを本物のUIと入力で完走でき、各43必須文、Lucky成功なら46文、場面と内容の違いを確認できること。保存/seed再挑戦/区間retryで別面や報酬が混ざらない。画面/音/操作の検証は自動テストとは別に記録する。

## 遊びの芯と長さ

一文字の発砲を積み重ね、文章を読んで敵の優先順位を選び、短い集団一掃で解放し、最後に静けさへ帰る。この動詞を変えず、同じ位置で敵だけを増やす区間を避ける。

各面の必須文は通常34、FEVER4、Boss5の43。短いrunnerと場面のあるoffice、少し長いworkerを混ぜる。全てを短い命令にすると文数だけ増えて体験が薄くなり、全てを長文にすると緊張が均一になる。

尺の設計値は1周約3〜5分。ただしUIに保証値として出さない。標準キー総数の目標は560..900、複数seed/routeの中央値650以上。入力速度180〜210KPMなら入力だけで160〜300秒程度、ここへ移動・敵の認識・休息操作が加わる。実測は任意休息を別記し、3〜5分から外れた理由が読解・速度・失敗ならそのまま示す。Luckyはさらに約30〜60キーの任意分。3〜5分に届かせるための待機や遅い移動は追加しない。650以上に届かなければoffice/worker文の具体性を増やす。速く打てる人が短時間で抜けることは不具合ではない。

同時敵の最大数は3。2体のときはdeadline順に打てば無理なく間に合い、短いrunnerを先に狙うか長いworkerを先に片づけるかが読める。波間の待ちは既存約0.6秒。敵が去るまで数秒待たせる尺稼ぎはしない。

## Stage 1: 午前零時の商店街

既存店の品質を保ち、到達するまでの商店街と、店を抜けた後の戦闘を一周の大きさへ広げる。

| 順 | 場面と入力 | 体験の意図 | 景色/音の手掛かり |
|---|---|---|---|
| 選択 | 表通り入口、1搬入口/2店内 | この夜勤の通り方を選ぶ | 既存の時計台が奥、左右の看板が進路を示す |
| 1 | 新しい表通り6文 | 1体→2体。最初の発砲はすぐに | 雨、二軒の閉店看板、歩道、街灯、アーケード骨組み |
| 2 | 既存裏路地6文 | 視界が狭まり、短いrunnerが割り込む | 既存の自転車・室外機・雨樋を保持 |
| 3A | 店内12文 | 重い敵と速い敵を読み分ける近距離戦 | v12の棚/商品/冷蔵ケース/天井/奥室を維持 |
| 3B | 搬入口12文 | 細い屋外の道で短文を素早く処理 | shutter/配管/箱/対向壁。文数は店内と同じ |
| 任意 | Lucky 3文 | 戦闘を一旦忘れ、踊る息抜き | 紫/金と既存音。スルー可能 |
| 休息 | 荷捌き広場へ移動、Enter待ち | 視界が開き、次の一掃を自分で始める | 雨と風を前面、銃を下げる。checkpoint確定 |

## Stage 2: 終電後の黒猫駅

雨に濡れた入口から、静かな改札、左右の通路、線路に沿った長いホームへ進む。商店街の造形/名前を色だけ変えて再利用しない。新駅は隣接world x=80..120、z=22..-70に独立rootで構築する。実際の列車動力や乗降は不要。停車中の無人車両を大型の立体ランドマークにする。

| 順 | 場面と入力 | 体験の意図 | 必須の立体要素 |
|---|---|---|---|
| 選択 | 駅前、1保守通路/2待合通路 | Stage1をクリアせずに選べる | 自立した駅舎庇、駅名標、入口 |
| 1 | forecourt6文 | 広い雨の入口から入る | 濡れた石/タイル、軒、壁厚、券売機の側面 |
| 2 | concourse6文 | 閉じた天井と改札の奥の異変 | 奥行きのある改札機、券売機、蛍光灯梁、時刻板 |
| 3A | waiting12文 | 座席とガラス越しに近い敵 | 手すり付きベンチ、窓枠、鞄、案内板、長い庇 |
| 3B | maintenance12文 | 狭い職員の道で軽い敵が先行 | 配電盤の扉/取手、露出配管、工具箱、黄黒の床端 |
| 任意 | Lucky3文 | 切符や退勤を題材に一息 | 既存Lucky、駅専用文 |
| 休息 | platform、Enter待ち | ホームの長い見通しと電車が現れる | 空間幅、線路、停車車両、天井梁 |
| 4 | FEVER4群 | ホームの集団を横一列に押し返す | 駅のまま同じ一語3体の快感 |
| 5 | platform10文 | 人数/距離で最後の圧力を作る | 接近ゾーンを柱やベンチで遮らない |
| 休息 | platform奥、Enter待ち | 「終電の駅長」を予告 | 一つだけ点いた信号と保守室の灯り |
| 6 | Boss5文 | 「出発」「忘れ物」「終業」の語彙で決着 | 既存Bossの立体/衣装、駅専用文とUI名 |
| 終わり | dawn、Enterで精算 | 列車の向こうに朝。勤務完了 | ホーム端から線路が消失点へ、遠景の暖かい空 |

駅の具体的な建築条件:

- concourseはx=92..108、z=0..-16を基本とし、中央改札の通過帯x=96.4..103.6を空ける。改札機は左右の帯へ寄せ、中央へ横木/閉じたゲートを置かない。天井の最低下面y=3.2、目線上に蛍光灯器具と梁。
- z=-12には左右x=88/112へ曲がる連絡通路を設ける。段差なし。幅最低2.2m、壁の開口を実際に切る。看板を貼った壁へカメラを突き抜けさせない。
- waiting/maintenance戦闘空間はそれぞれx=108.8..115.2、84.8..91.2、z=-15..-27。前方5.7mと横幅5.2mを敵のため空け、小物は側壁へ寄せる。戦闘時の天井/光に差を付ける。waitingは鈍い青緑のガラスと白いベンチ、maintenanceは錆と暖色の作業灯。
- z=-28で左右から中央へ合流する実在する連絡帯を作る。この線分上に後壁を置かない。
- platformの歩ける床はx=94..106、z=-28..-68、y=0。線路は東側x=106.8..112.8、y=-0.65。踏み外し/ジャンプは無い。床端、点字ブロック、二本のレール、枕木を別の立体として読めるようにする。
- 停車車両はx=108..111.5、z=-35..-60程度。屋根の丸み、車輪/台車、窓の凹みと扉、側面帯を持つ立体。車両を背景板や窓テクスチャだけにしない。車両床へ入らず、乗車演出も作らない。
- ホーム柱はx<=95またはx>=105、z間隔8m程度。幅方向の敵の入場域と交差しない。駅名標/時計/信号は狙いの中心から外す。奥のBoss出現z=-55.2に後壁/列車前面を置かない。
- 眺望stopは地上と同じ目線。橋/跨線橋/駅屋上は今回作らない。高低差による敵の影/着地/接近の修正を増やすより、ホームの長い奥行きと車両を完成させる。

素材は現在の雨/metal/concrete/手続きCanvasの再利用。文字板はCanvasでもよいが、額縁/支持体/壁厚は3Dで作る。駅の形を1枚の画像へ焼き込まない。外部新規素材や課金/登録が必要な取得は行わない。静的な同材質小物は既存の結合方針でdraw callを抑え、照明数は固定枠を再利用する。

## タイトル・進行・休息の文章

タイトルは横並び二枚の勤務票。1枚目「01 / 午前零時の商店街」「雨の表通りから、店の奥へ。」、2枚目「02 / 終電後の黒猫駅」「改札の向こうで、終電が待っている。」。両方最初から選べる。選択で3Dプレビューが変わり、既存の「勤務開始」で入力確認へ進む。ラジオグループ等の適切な選択状態とキーボードフォーカスを付ける。小さな画面では縦積みし、開始ボタンを画面外へ追い出さない。選択で勝手に開始しない。

画面のStage番号、面名、route、Boss名、area名と移動captionはstages.tsから読む。進捗は「12 / 43文」と場所の二段。Lucky中は「BONUS / 1 OF 3」を優先し、本編進捗は増えない。結果の完走時間に任意休息時間を含めないので、長く眺める人を順位で罰しない。

caption例はmarket「明かりの残る通りを、奥へ。」、alley「店の裏で、足音が重なった。」、store「棚の向こうから、誰かが来る。」、service「配管の下に、抜け道がある。」、court「空が開けた。広場へ出よう。」、roof「階段の先に、朝の気配。」、forecourt「改札の明かりだけが残っている。」、concourse「誰もいない改札を、奥へ。」、waiting「ガラスの向こうで、影が動いた。」、maintenance「作業灯を頼りに、ホームへ。」、platform「止まった列車の横に、人影が並ぶ。」、dawn「線路の先が、少し明るい。」。

vistaはshopping「夜明けまで、生き延びた。」「商店街の勤務を終えて、帰ろう。」、station「始発の気配がした。」「誰もいないホームに、朝が戻ってきた。」。現在の「次は、時計台へ。」は時計台Boss後の不整合なので置き換える。

## 検証で確かめる仮説

第一に、必要入力の増加だけでなく、移動・分岐・二度の安全な休息が一周を大きく感じさせるか。第二に、駅が看板の差分ではなく、改札の狭さからホームの長い奥行きへ広がる空間として読めるか。第三に、長い文が的を見失わせず、短いrunner/FEVERの気持ちよさを引き立てるか。

これらは設計仮説。自動全クリアやスクリーンショットで楽しさの証明にしない。実操作後に「似た波が続いて長く感じる場所」「読みにくい文」「待ち時間」を場所名で記録し、そこを具体的に調整する。

参照したskillはリポジトリのgame-design/level-designと、そのframeworks/pacing-and-flow。承認済みのコンセプトを用い、再承認は求めない。skillが参照するroot docs/GAME_DEV_SKILLS.mdは現checkoutに存在しないため、新しく共通文書を作らず、このアプリの既存指示を適用した。
