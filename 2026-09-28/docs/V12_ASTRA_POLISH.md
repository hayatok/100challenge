# v0.12 Astraによる店内品質改善

## Goal
目標画像に対して粗さの目立つ店内を集中的に改善し、実ゲームで比較できる成果を作る。ユーザーがAstraによるデザインと実装を指定。

## Context
v0.11実画面 `art/verification/v11-store.png` と `art/reference/store-v11-target.png`、`journey-approved-v10.png`。既存Three.js、入力、採点、分岐。Issue #130。

## Constraints
3Dと読みやすい入力を維持。無料・登録不要・ゲームへの再配布が可能な素材。既存作品固有の素材を流用しない。未承認の有料サービスは使わない。今回は現行の短い一勤務の品質改善に絞り、長尺化・面の追加は別扱い。

## Plan / Ownership
1. Astraが実装と目標/実画面を読み、現在のブラウザ画面を操作して確認。
2. Astraが最も効く改善を選び、人物・手元・店内の造形/質感/照明を一体として実装。src全体と必要アセットを専有。
3. Astraが実画面を比較し修正。主担当が統合検証、バージョン/README/RESULTS、PR、CI、Pagesを担当。

## Done when
店内で変更前後の差を確認でき、入力/戦闘/分岐/低モーションが破綻しない。自動テストとブラウザ操作、品質判断を分けて記録。残る画像との差も明記。

## 比較と回帰確認
- 同じ1280×720の店内、近距離の人物/手元と棚を比較。beforeは `art/verification/v12-before-store.png`。生成画像と実画面を取り違えない。
- 衣装の歩行/接近/被弾/死亡への追従、髪のシルエット、銃と手の接触、銃口光の位置を観察する。
- 練習と通常勤務、店内と搬入口の分岐、ショットガンへの切替、低モーション、Escape/go復帰、屋上から結果までの進行を確認する。
- アプリcheckと共有test、公開後の配信ファイル/console/操作を別々に記録する。フレーム時間や人間の爽快感は未計測なら達成扱いにしない。
