# ゲーム仕様 v0.2

## 1. 体験と題材

仮称「夜勤タイピング」。午前零時、閉店できなくなった商店街。プレイヤーは夜間の怪異処理係として進む。
一人称視点で、ゾンビに付いた言葉を打つたびに銃が発砲する。最後まで打ち切るとゾンビを撃ち倒せる。街・ゾンビ・手と銃は3D、文字やHUDは2Dの重ね表示とする。

目指す感覚は「怖い、急げ、打てた、吹き飛んだ、もう一体」。核心となる緊張は、急いで倒すことと正確にコンボをつなぐことの両立。
承認された画像に近い、リアル寄りの街・ゾンビ・銃を目指す。奇妙な生活感と出題文でコミカルさを残す。着弾、身体ののけぞり、倒れる動き、衣服や小道具の反応で撃破を表す。

The Typing of the Dead は迫る敵を文字で倒す体験の参考。既存作品の再現や続編ではない。
ドパドリルからは即時反応、段階演出、音と絵の連動を参考にする。今回はコンボが演出を左右するので、進行だけで最大演出に達する設計にはしない。

## 2. 対象と初版の範囲

- PCの物理キーボード、1人用、ブラウザで開始。日本語を読み、英数モードでローマ字を打つ。
- 主画面は横長。スマホは紹介・設定の閲覧を可能にするが、ソフトキーボードによる本編操作は初版対象外。
- 一本道の1ステージ。所要3〜5分を目標とし、固定時間で強制終了しない。
- 商店街の3地点、通常敵3種、ボス1体、手作りの短文80〜120件。
- 通常敵は一周24体を初期案とする（店先6、アーケード8、裏通り10）。辞書から各回の語を選び、全件を一周で出題するわけではない。
- 初回導入は安全な敵を3体。難度は「ゆったり」「標準」「猛打」。初期選択は標準。
- アカウント、オンライン順位、装備強化、収集、日課、複数ステージ、自由移動は初版に含めない。

## 3. 一周の進行

| 区間 | 目安 | 内容 |
| --- | --- | --- |
| 店先 | 30〜45秒 | 1体ずつ登場。文字を打つ、打ち切る、危険表示を見ることを教える |
| アーケード | 60〜90秒 | 最大2体。先に倒す敵の選択とコンボの段階変化 |
| 裏通り | 45〜75秒 | 最大3体。短い急襲語、長い敵、休符を組み合わせる |
| 閉店ボス | 45〜75秒 | 大柄なゾンビ店主。3つの攻撃区間を打ち切り、店を閉める |

各地点の敵を処理すると短いカメラ移動で次へ進む。戦闘中に大きくカメラを振らない。
移動中は敵の攻撃期限を進めず、入力欄を閉じる。入力しなくてよいことを画面で伝える。
操作不要の移動は0.7〜1.2秒を初期目安とし、繰り返しの足止めを避ける。
難度や速度で時間は変わるため、上記時間は保証ではない。

## 4. 一文字と一体の関係

1. 敵が奥から登場し、入力可能になると日本語と読みを示す。
2. プレイヤーが先頭の有効な英字を打つと、その敵にロックする。
3. 正しい英字ごとに一発のヒット。入力済み文字を保持し、敵の身振りと小さな着弾で返す。
4. 最終入力で敵を即座に撃破扱いにする。見た目の倒れる演技中も次の敵を入力できる。
5. 無傷・ノーミスで語を完了するとコンボが一つ増える。

各英字のヒットは見た目の反応。入力経路の長短で敵の攻撃期限や撃破条件を有利にしないため、英字ごとのノックバックで移動や攻撃時刻を延長しない。
敵は期限の最後0.8秒に明確な予備動作を行い、期限で1ダメージを与えて離脱する。同じ敵による連続ダメージはない。期限後に追加の猶予は与えない。
入力と攻撃は同じ戦闘時計で順序付ける。キーを受信した戦闘時刻が攻撃期限以下で、その入力で撃破が成立する場合は撃破を優先する。期限後の入力は、その敵の攻撃・離脱を先に確定してから扱う。同一時刻の攻撃同士は固定の敵ID順に処理する。

## 5. ターゲットの選択

- 待機中は、各敵が受け付ける先頭キーを表示する。文字入力だけで選べる。
- 同時入力可能な敵は「受け付ける先頭キー集合」が重複しないように出題を割り当てる。`し` は s だけでなく許容経路を全て確認する。
- 重複しない語がなければ生成を延期し、別の語を選ぶ。危険な敵を勝手に選ぶ曖昧な自動処理にしない。
- ロック中は最後まで同じ敵。初版に手動ターゲット切替は設けない。途中放棄しなければ救えない組合せは出現計画で避ける。
- 非ロック敵も近づくため、短い敵から倒すか、残り時間の少ない敵を先に倒すかが判断になる。
- 入力開始前から各敵の残り猶予を長さ＋形で表示。ロック中の敵は輪郭、番号、固定入力欄との接続で区別する。
- 最終打鍵を次の敵への入力として再利用しない。直後の別keydownは通常通り受理する。

## 6. 日本語・ローマ字入力

### 表記と許容

表示文、読み、読みから生成する受理グラフを分離する。表示文の例は「領収書は棺桶へ」「本日も成仏できません」「閉店したはずなのに」。本文は独自制作する。
漢字を含む表示文と、ひらがなの読み、現在有効なローマ字経路を同時に確認できる。

- `し: si/shi`、`ち: ti/chi`、`つ: tu/tsu`、`ふ: hu/fu`、拗音、促音、小書き、撥音を扱う。
- `しゃ: sya/sha/silya/shilya/sixya/shixya` など、分解入力と通常入力を同じ読みの候補として扱う。
- 促音は次の子音の重ね打ちと `ltu/xtu/ltsu/xtsu` を許す。`っち` の `cchi` と `tti` などをテストする。
- `ん` は次が母音/y/nなら曖昧さを解消する `nn` または `n'`。子音の前は文脈で `n` も受理。語末は `n` と `nn` のどちらを採るかを固定し、初版は誤った次敵ロックを避けて **nn / n'** に統一して明示する。
- 「長音記号」は `-`。初版のその他の句読点・空白は自動通過し、数字は読みの仮名へ変換した出題データを用意する。
- a〜zは大文字小文字を区別しない。記号は半角を使う。
- 上記は初版の対応契約。全IME方式を保証しない。出題辞書が使う読みを全て検査し、非対応文字を含む語は出題しない。

複数経路を生かした状態機械で、一打ごとに到達可能状態集合を進める。単にローマ字文字列を一つ保存して比較しない。
候補がなくなるキーだけ誤打。誤打時は読みの進捗と受理状態を維持する。受理グラフ全体の終端に到達したときだけ撃破。
ローマ字ガイドは実入力に従って分岐するが、日本語の位置は動かさない。

### 操作ルール

| 入力・状態 | 挙動 |
| --- | --- |
| 有効な英字・指定記号 | 一度だけ判定。正解なら進む |
| 誤った英字・指定記号 | 進捗保持、短い誤打表示、コンボ解除 |
| Backspace | 進捗を消さず、誤打にも数えない |
| 長押しrepeat | 無視。連打として加算しない |
| Shift単独、修飾キー、ブラウザショートカット | 判定対象外。ブラウザ操作を奪わない |
| Escape | 即時ポーズ。設定操作中はダイアログ側へ渡す |
| IME組成、Process/Dead、対応外の文字入力 | 誤打・攻撃進行を止め、英数入力への切替を案内する |
| 貼付け、IME確定による文字列 | 打鍵として採点しない |
| フォーカス喪失・非表示タブ | 即ポーズ。戻っても明示的な再開まで進めない |

IMEをプログラムから強制的にオフにはしない。開始前に短い入力確認を置く。
IME組成の開始、Process/Dead、全角などの判定対象外の文字を検出した時点で、警告付きポーズ状態に遷移する。敵、期限、入力、コンボ減衰、音を通常ポーズと同じ規則で止める。組成終了だけでは再開せず、英数モードの入力確認後に明示的に再開する。修飾キー単独などの「無視するキー」はこの警告を発生させない。
ポーズからはクリックまたはEnterで再開し、その操作を弾や誤打に流用しない。入力待ちを0.8秒表示してから敵と入力を同時に再開する。

## 7. コンボと得点

**コンボ＝誤打・被弾なしで完了した入力課題の連続数。** 通常敵は1体で1課題、ボスは攻撃区間ごとに1課題。本仕様の「ノーミス課題」はこの両条件を満たすものと定義し、ゲーム内の説明にも両条件を示す。
各キーではヒットを返し、敵を倒す節目でコンボを祝う。`shi` の方が `si` よりコンボを稼げる設計にしない。

- 誤打した瞬間にコンボ0、現在課題はノーミス対象外になる。打ち直しは不要。
- 被弾もコンボ0、現在ロック中の課題が残っていればノーミス対象外。
- 誤打ゼロでも、その課題を入力中に被弾した場合はノーミス加点・コンボ加点とも0。正確率は文字入力の正誤だけなので、被弾では下げない。
- 次のノーミス課題の完了で1から再開する。
- カメラ移動、ポーズ、敵がいない時間ではコンボが切れない。別途短い打鍵タイムアウトを設けず、敵の接近が時間圧になる。
- 得点は課題ごとの固定基礎点＋ノーミス加点＋コンボ加点。初期案は100＋ノーミス時50＋`min(新コンボ,15)*10`。誤打を含む課題のコンボ加点は0。
- 初版に打鍵数・キー入力速度による得点加点は置かない。速度は敵を間に合って倒す利点と、別の結果指標で評価する。
- 結果は得点、最大コンボ、正確率、クリア時間、正しく打ったキー/分。正確率の分母は判定対象の正打＋誤打だけ。
- ゲーム内の自動移動・ポーズ時間は入力速度の計測時間から除く。速度の時間は最初の敵が入力可能になってから、各戦闘終了までの合計。

演出レベルは0〜2、3〜5、6〜9、10〜14、15以上の5段階。詳細は ART_AUDIO.md。
誤打で得点倍率に相当するコンボは即解除するが、視覚と音は滑らかに戻す。演出表示と採点用コンボの値を別に管理する。

## 8. 敵とボス

| 敵 | シルエット・行動 | 入力課題・判断 |
| --- | --- | --- |
| 会社員ゾンビ | 破れたスーツ、緩んだネクタイ。奥からふらついて歩く | 標準的な語。最初に完成品質を目指す基本敵 |
| 配達員ゾンビ | 細身の作業服。明確な予備動作の後に急接近 | 短い語。表示から攻撃までの猶予を短くし、優先順位を作る |
| 作業員ゾンビ | ヘルメットと厚い作業服。重い足取り、強い被弾反応 | 長めの語。途中の英字数で攻撃期限を延長しない |
| 閉店できない店主 | 大柄な人型ゾンビ、古い前掛けと店の小道具 | 3区間。各区間1つのフレーズで攻撃阻止、3区間で決着 |

ボスは読みと打鍵の戦いを保ち、突然のマウス操作や別ジャンルの謎解きは追加しない。
ボス中に通常敵を同時出現させない。ロック中に処理できない短い期限を別に発生させない。
ボスの未達区間は1ダメージの後、同じ区間を新しい語で再提示。成功するまで次区間へ進まない。標準モードは体力で有限にする。

## 9. 難度と敗北

体力は3。誤打だけでは体力を減らさず、敵の攻撃で減る。体力0で区間リトライ／タイトルを選べる。
区間リトライは体力3、コンボ0、当該区間の開始前スコアへ戻して再開する。試行回数を記録し、通しクリアと区別して結果表示する。
入力練習用の「攻撃なし」は同じ演出を体験できるが、標準の記録とは別に保存する。

攻撃期限の初期案：入力可能時点から `1.2秒 + 標準経路のキー数 / 難度CPS * 1.6`。
難度CPSは、ゆったり2.0、標準3.5、猛打5.0を仮置き。表示された攻撃猶予の最後0.8秒を予備動作とし、期限の後に隠れた追加時間を与えない。
課題長と敵種の係数はデータ化する。長い許容経路も不当に間に合わなくならないよう試作で調整する。

同時出現時は、この式を個体ごとに当てるだけでは不十分。既存の残り入力負荷、読替え時間、最初のロックを完了する時間まで含めて、成立する撃破順がある出現計画だけを採用する。
初版の出現タイミングは手作りの小ウェーブ。シードで語の候補を変更するが、無制限ランダム湧きはしない。
上達した瞬間に敵を速くする自動難度調整は初版に入れない。難度変更はステージ開始前に行う。

## 10. 画面・保存・終了

タイトル → 入力確認/初回導入 → 本編 → 結果。設定とポーズは重ね表示。
結果から再挑戦を1操作で開始できる。長い強制リザルト演出は置かない。
保存は端末内の設定と難度別ベスト・直近10回の結果。入力した生キー列は永続保存しない。
保存失敗時もその回は遊べる。保存できていないことを結果に知らせる。途中セーブと端末間同期は初版対象外。

本書の数値は仮説。面白さ・適正難度・ゲーム時間は実プレイで未検証。
