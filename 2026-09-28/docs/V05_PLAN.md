# Alpha 0.5: 打ってためる、狙って一掃、FEVERで解放

## Goal
ユーザー承認のFEVER短文ラッシュ、爆発ゾンビの連鎖、音と撃破の階層、一周の緊張と解放、次の一回の目標と同じ出題への再挑戦を実装し、Pagesへ公開する。

## Context
既存のThree.js/WebAudioと純粋な入力・戦闘状態。v0.4の実画面とRESULTS、Issue #130。game-designのguidance-and-feedback/principlesを使い、可読性と選択の結果が伝わることを優先する。実際の爽快感と難度は人間のプレイ評価まで仮説。

## Constraints
英字の入力経路差でコンボやゲージを稼がせない。入力中の文章や期限を差し替えない。文字帯・危険予告を揺らさず、低モーション対応。アカウント、通貨、日課は追加しない。既存の許諾済み音源と立体素材を利用。性能p95は厳しい完了条件にしないが、停止の原因を調べて軽減する。

## 実装順と担当
1. 純粋ロジック: 完了課題でゲージ加算、通常wave境界で4短文ラッシュ（最大2回）、workerの爆発差分と隣接レーンの巻き込み、ボス第2段階を3短文カウンターへ。期限・ポーズ・checkpoint・決定的seedを維持。
2. 音: 一文字/一体/集団撃破の音を区別。FEVERの音楽強調と締め、爆発の短いダック。ノードと同時発音を制限。
3. 記録: 得点規則のversionを分け、旧記録を保持。同じseed再挑戦、実績から一つだけ達成可能な次目標。
4. メイン統合: ゲージ/ラッシュ残数/巻き込み予告、タンクを背負う立体差分、爆発とラッシュ演出、UI更新と描画負荷見直し。Web実画面確認は統合担当のみ。
5. 検証/公開: 自動テスト、型、lint/build、通常/ミス/連鎖/FEVER/ボス/再挑戦/低モーション、PR CIとPages配信、公開URLでキー操作して結果まで確認。

## Done when
最初の約1分でラッシュと新しい判断を体験できる構成。採点・入力・期限に回帰がなく、何が起きたか画面から読める。新旧スコアは混同しない。公開URLで開始〜結果の進行と素材を確認し、未確認事項と安全ポーズの再現有無を記録する。
