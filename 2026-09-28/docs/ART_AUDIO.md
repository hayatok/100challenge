# 画面・演出・音の仕様案

## Alpha 0.2 の実装差分

初期仕様の音楽ステム案は、今回165 BPMの既製ループと段階的なフィルタ開放へ変更。実録銃声・打撃・ガラス・低域をコンボに応じて重ねる。映像は金→橙→紫→青緑の5段階、局所の火花・撃破衝撃波・吹き飛び・側方の到達表示。下記の未実装案（小道具の飛散、看板連動、独立音楽ステムなど）は完成済みと扱わない。通常の人物に加え人型の変異ゾンビを採用。詳細は ALPHA_PLAN / ALPHA_CHARACTER_ASSETS / ALPHA_AUDIO / RESULTS を参照。


## 1. 画風

2026-09-28、ユーザーが[生成画面](../art/reference/gameplay-approved-v1.png)を「イメージぴったり」と承認。この画像を主たる見た目の基準にする。
深夜の日本の商店街を舞台にした、一人称の3Dゾンビタイピングシューター。リアル寄りの造形と素材、曲がった看板、湿った舗道、暖色の店内灯と冷たい路地の光。コミカルさは文章・看板・芝居で出し、明るい玩具調へ変更しない。
敵は表情、手足、小道具で個性を出す。輪郭のない発光球や直方体だけを最終キャラクターにしない。
ネオンと霧を使うが、全画面を常に高彩度で埋めない。敵の予備動作と目・手・口が分かる造形にする。

画面右下に手と実銃らしいハンドガン。正しいキーで発砲、銃の反動、銃口の炎、排莢、ゾンビへの着弾を返す。単語を打ち切ると強い被弾演技で倒れる。
敵は全て人型のゾンビ。青白い肌、疲れた顔、破れた普段着、迫る手を作り込み、画像の会社員・店員・作業員という生活感を生かす。
冗談は文章だけに頼らず、動きでも伝える。

必要な実素材：商店街1セット、基本ゾンビ1体の完成造形と歩行・攻撃予備・ヒット・撃破、そこから展開する敵2種、ボス、手とハンドガン、銃口の炎/排莢/着弾素材、書体、BGMステム、効果音。調達と自作の区分は[ASSET_PLAN.md](ASSET_PLAN.md)を参照。
制作順は基本敵と一区画を最優先。モデル、リグ、テクスチャ、音源の確保を技術選定だけで解決済みと扱わない。

## 2. 画面の優先順位

プレイ画面は戦場を主役にする。上端は体力・得点・コンボ、中央は敵と短いラベル、下部はロック中の日本語・読み・ローマ字ガイドを置く。
入力ガイドは固定帯に配置し、世界のカメラ揺れと分離する。敵ラベルは重なり回避し、短縮しても完全な本文は固定帯で読める。
通常時も入力対象が分かるため、アクティブ敵の輪郭と番号を入力帯に対応させる。
未ロックの各敵ラベルの左に、受理可能な先頭英字を角括弧付きで全て表示する。例：`[T] [C] ち…` のように同じ読みの有効候補を省略しない。ラベルが収まらなければ本文側を短縮し、キー候補は残す。出題検査で候補数の上限を3とし、それを超える語は初版に採用しない。ロック後は選択中の印へ切り替え、固定入力帯で以降のガイドを示す。

### 16:9の配置案

```text
┌ 体力 ●●● ───────────── 得点  8 COMBO ┐
│          商店街の奥行き・照明・霧          │
│    [O] 2:おつり…        [H] 3:へいてん…   │
│            [1: ロック中の敵]             │
│                                         │
│    アクティブ敵への照準     手と銃        │
├─────────────────────────────────────────┤
│ 領収書は棺桶へ                           │
│ りょうしゅうしょはかんおけへ              │
│ RYOUSYUU | SYOHAKANOKEHE                 │
└─────────────────────────────────────────┘
```

これは配置案で、完成画面の品質証拠ではない。
主検証は1280×720、1440×900、1920×1080。1024×768では戦場を調整しても入力帯と操作を維持。
狭い画面ではPC/物理キーボード向け案内を出し、タイトル・設定・説明・戻る操作を維持する。

### 共通UIからのテーマ対応

設定、ポーズ、結果の操作はルートの44px以上の操作面、フォーカス、ラベルを守る。ゲームの没入感のため、同じ意味役割を次の暗色テーマへ対応させる。

| 役割 | この作品の値・使い方 |
| --- | --- |
| canvas / surface | #121A25 / #1D2938 |
| ink / muted | #FFF4DA / #C2CAD1 |
| line | #70808D |
| accent | #FFD166。濃色文字との組合せで主操作・フォーカスを示す |
| success / error | #7EE0BF / #FF9CA8。必ず形または文言を併用 |

ゲームの見出しは太い日本語書体を検討し、入力文字は読みやすい書体を別に選ぶ。書体ファイルと収録文字・利用条件を確かめる。
上記色のコントラストはまだ実測していない。最終の背景透過と合わせて確認する。

## 3. 演出の5段階

コンボは誤打・被弾なしの課題完了数。演出の段階は撃破判定後に更新する。

| レベル | コンボ | 映像 | 音 |
| --- | --- | --- | --- |
| 0 | 0〜2 | 銃口の炎、局所の着弾、敵の短いのけぞり、排莢 | 基本ビートと低音、短く切れのよい銃声 |
| 1 | 3〜5 | 弾の軌跡が太くなり、倒れる敵の小道具が跳ねる | 打楽器を追加 |
| 2 | 6〜9 | 店の電飾が順に点灯、撃破に局所的な衝撃波と破片が加わる | ベースの厚みと和音を追加 |
| 3 | 10〜14 | 撃破時に看板が反応、敵が大きく吹き飛ぶ、銃撃の光が周囲を照らす | ブラス/オルガンのフレーズを追加 |
| 4 | 15以上 | 強い撃破のポーズ、金色のコンボ表示、局所の火花と街の電飾。承認画像の暗さと奥行きを保ち、入力帯は静止 | 全ステム＋短い祝福フレーズ。音量を無制限に上げない |

最大演出は点滅の速さや画面揺れを上げ続けるものにしない。量、奥行き、演技、構図、楽器編成で変える。
Lv4到達の見せ場は一度。維持中は通常撃破に戻し、5コンボ刻みの小さな変奏を使う。
最高段階まで出せなかった回も、ボス撃破の結末は明確に祝う。ボスの結末とコンボ達成は別の演出ラベルにする。

### コンボが切れたとき

採点上のコンボはその場で0。演出は現在レベルを1.5秒だけ保持し、その後0.8秒ごとに1段ずつ戻す。
回復したコンボが要求する段階より下には落とさない。連続誤打で保持時間を延長しない。
再び上位段階へ到達すれば、次の拍/小節から音を積み直す。画面を急に暗くせず、ミス直後も正打の気持ちよさは残す。

## 4. 一回の反応の時間設計

数値は試作時の目安。入力判定を画面/音の完了待ちにしない。

| イベント | 即時 | 続く演技 | 次操作 |
| --- | --- | --- | --- |
| 正打 | 文字を進める、発射音、小さな着弾 | 40〜100msで敵の局所ヒットを戻す | 常時受付 |
| 誤打 | 該当位置の下に短い印、低いクリック | 120ms程度で消す。大きく文字を揺らさない | 常時受付 |
| 撃破 | 採点、対象解除、次敵を選択可能 | 150〜500msの吹き飛び/小道具演技 | 撃破演技中も受付 |
| コンボ昇格 | コンボ数字を小さく弾ませる | 250〜450msの側方演出、音は次の拍から | 常時受付 |
| ボス決着 | 戦闘終了確定 | 1〜2秒の結末。結果操作は早期に使える | 再挑戦入力を明示 |

打鍵ごとの全画面フラッシュは使わない。ヒットストップを入れるなら敵の描画ポーズだけに最大約40ms、入力・攻撃時計・BGMは止めない。重複時に延長しない。
ヒットや小道具の同時数に上限を設け、古い装飾から消す。敵と入力文字は品質低下時も省略しない。

## 5. 音楽と効果音

怪しい夜のスウィングと、銃声を邪魔しない打楽器を合わせた曲を想定。音源も条件の合う既製素材を使える。
初版は固定テンポ約124 BPM、同じ小節長・調・開始位置を持つ4〜5ステム。コンボでテンポまで変える実装は初版から外す。
打鍵音は即時。BGMレイヤーの切替は拍/小節に合わせる。操作反応を音楽のタイミングまで遅らせない。
撃破音には打撃、破片、短い和声音を組み合わせる。素材数よりも、距離感・低音・余韻・繰り返しの自然さを優先する。

- BGM/効果音の音量とミュートを独立設定。
- 背景はステムの足し算でクリップしないよう各レベルのゲインを設計。
- 正打が高速に続いても同じ音を無制限に重ねない。最大同時発音数、ゲイン、短いエンベロープを調整する。
- 最初のユーザー操作で音を有効化。音が開始できない時は再試行と無音プレイを選べる。
- フォーカス喪失で音もポーズ。再開時に同じ小節位置へ整合させる。音源を二重再生しない。
- 完成音源と仮の電子音を区別する。音源の制作元と利用条件を記録する。

## 6. 読みやすさと動きの設定

設定は「演出：標準/控えめ」「画面揺れ：0〜100」「BGM」「効果音」。OSの reduced-motion を初期値に反映する。
控えめ設定ではカメラ揺れ、急なズーム、全画面の輝度変化、大きな粒子を止める。必要な敵移動、攻撃予告、文字の進捗、コンボ段階は残す。
最高段階でも入力帯と敵ラベルに粒子・ブラー・色収差を重ねない。合成順序で保証する。
色だけで正打/誤打/危険を伝えない。点滅を主手段にせず、形、予備動作、バー、短い文言を併用する。
無音でも危険が読め、控えめでもコンボの段階が分かることを検証する。

## Alpha 0.9 承認UIへの更新

2026-09-28、ユーザーが [筐体UIコンセプト](../art/reference/ui-approved-v09.png) を承認。以後、操作画面は煤けた黒・生成り・朱赤のホラー筐体へ統一する。過去の青灰/金アクセント案より本項を優先する。

- canvas `#10100f` / surface `#211d19` / ink `#fff1d9` / muted `#d5c9b4` / line `#9d8e77` / accent `#c53723` / success `#b9dfbd` / error `#ffaf9d`。フォーカスは金 `#f3cb72`、主操作は朱赤と生成りの文字。
- タイトルは中央の太い文字と赤黒の硬い影で作る専用ロゴ。画面に出す文字はDOMであり、生成画像をUIや背景に貼らない。
- 入力プレートは下部固定。現在文字は下線と背景、打ち終えた文字は色に加え位置で区別。スクリーンの揺れと独立。
- 金色の切り抜き文字は実際のFEVER/連撃/ラッキー/連鎖イベントに対応。重複していた旧milestone表示を非表示にし、主要表示のshowtimeへ集約。
- 勤務精算票は実測の得点/評価/正確率/記録差を表示。評価印はクリア/中断/練習を区別し、被弾記録のない状態で「無傷」を断定しない。
- 設定・休止・装填確認は鋲と赤い上端を持つサービスパネル。44px以上のボタン、Tab循環、Escapeでの設定保存を維持する。
- 参考画像の人物/反射/環境密度は品質目標。v0.9では3Dモデルと環境描画は変更しない。
