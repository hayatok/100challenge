# Alpha 0.6: ゾンビの芝居と踊る幸運

## Goal / Context
v0.5の入力と戦闘を維持し、既存クリップの使い分け、被弾・撃破の身体反応、専用ダンス2種を持つラッキーゾンビを追加。Issue #130の継続作業としてPagesへ公開する。game-designのguidance-and-feedback/systemsを参照済み。

## Constraints
通常敵の期限を演出に合わせて変更しない。入力欄は固定。ラッキーは通常集団とFEVERの境界に単独出現し、通常戦の時計を進めない。1勤務最大1回、出現はseed固定。通常は約半分の勤務、練習では動きを確認できるよう必ず登場。見逃しや誤打で体力・コンボを失わない。3短文を完成すると固定ボーナスと体力1回復（最大3）。ラッキーの打鍵・時間は通常の正確率/KPMに混ぜず、ボーナスを別表示。リトライで報酬を二重取得させない。既存素材と自作アニメを使い、アカウント・依存ライブラリを増やさない。

## Plan
1. 純粋ロジックと専用文章、seed再現・期限・checkpoint・報酬のテスト。
2. モーション担当: 原型ごとの歩行/攻撃選択、複数被弾・撃破、足腰と重心のあるダンス2種と決めポーズ。基準骨の単位・向きを検証する。
3. 音担当: 専用の短い自作伴奏、正打/文完了/大当たり合図。即時入力、既存音量・ミュート・休止に追随。
4. 統合担当: 3Dの登場・照明・ジャケット差分・紙吹雪、HUDと結果保存、実画面確認。既存の画面とチェックを維持。
5. 通常/練習、成功/見逃し、低モーション、pause/retry、同seed、通常ボス完走を実画面と意味のある自動テストで確認し、PR/CI/Pages/配信照合を行う。

## Done when
モーションの違いが実画面から読める。ダンスの脚・接地・重心、撃破後の姿勢を複数時点で確認。ラッキー遭遇は通常戦と区別でき、結果と報酬が一致する。実機聴感や人間の爽快感評価と自動操作を区別して未確認事項を記録する。
