# 実装順序と検証計画

## 今回の状態

プレイ可能な初版を実装した。実施済みの結果と未確認事項は [RESULTS.md](RESULTS.md) を正とする。下記は品質目標と検証計画であり、すべての合格を意味しない。

## ゲート1：一体を倒す30〜45秒

制作物：一区画、完成品質に近いゾンビ1体、手とハンドガン、少数の実出題、キーの正誤、撃破、5段階の映像/音を試せる調整操作。
通常プレイと演出確認を分け、調整操作は記録に加算しない。

確認：
- 日本語を読み、入力し、敵がのけぞり、最後に倒れるまで実キーボードで通す。
- `si/shi`等の切替で誤判定がなく、連続入力が演出に飲まれない。
- Lv0とLv4の静止画と実際の動きに差がある。入力文字が読める。
- 絵だけでも場所と敵が魅力的で、音を足すと打撃が強まる。
- 承認画像と同じ構図で実ゲームを撮り、ゾンビの顔/服、銃と手、街の密度、濡れた路面、暖冷の照明、HUDを比較する。見た目の差と性能上の妥協を項目ごとに記録する。
- 最高演出から誤打し、再びコンボをつなぐまでを試す。

基準に届かなければ、敵種類・面数を増やさず、アート/入力/音/時間設計を直す。
画像モックや自動入力デモだけを操作感の合格にしない。

## ゲート2：一周を最後まで

3地点、通常敵3種、ボス、体力、リトライ、結果を統合する。
初回導入から結果まで実際に遊び、所要時間・誤打・被弾・最高コンボ・失敗地点を記録する。
遅め/普通/速めの打ち手で、常に最大コンボにも、永遠に最低演出にもならないよう調整する。
「ミスをしたらもうやる気が戻らない」「演出を見たくても文字から目を離せない」「後半で読みづらい」を聞く。
反応速度だけでなく、敵を倒す爽快感、次の危険の理解、もう一周したさを別々に評価する。

## ゲート3：配布前の実機

- Windows/macOS、JIS/US配列、Chrome/Edge/Firefox/Safariは利用可能な実機で確認し、未確認を列挙する。
- 入力確認、IMEオン/途中切替、CapsLock、連打、長押し、Backspace、修飾キー、貼付け、キー取りこぼし。
- 最後の打鍵→次の敵への最初の打鍵、敵が攻撃する時刻と同時の入力、ポーズ直前の撃破。
- 非表示タブ、ウィンドウ切替、設定変更、復帰、AudioContext中断、GPU喪失、読み込み失敗、保存不可。
- 1280×720 / 1440×900 / 1920×1080を主確認。1024×768、375×812は説明/設定を含め操作不能を避ける。
- 無音・控えめ演出・画面揺れ0でも、危険/正誤/コンボ段階を見分けられる。
- 有線/内蔵音声を基準にし、Bluetoothの遅れをソフトの処理時間と混同しない。

## 自動検証の焦点

実行コマンドは本アプリの package.json を正とする。`npm run check` でコアテスト、lint、型チェック、production buildを実行する。

1. 受理グラフ：全出題の全許容経路、途中分岐、促音/拗音/撥音、終端、誤打後の復帰、非対応の読み。
2. 不変条件：一回のキーで二体を倒さない、誤打で進捗が戻らない、長い入力経路で得点/コンボが増えない。
3. 敵の割当：先頭キー集合が重複しない、候補不足の時に待機する、表示されるガイドが実際に受理可能。
4. 状態遷移：ポーズで全期限が止まる、攻撃の一回性、死亡/撃破の競合、区間リトライで得点を二重加算しない。
5. 演出：コンボの即解除と演出の減衰が分離される、連続ミスで演出保持が延長されない。
6. 出題/出現データ：基準速度で成立する撃破順があり、ロック後に強制的な詰みを発生させない。
7. 保存：破損/旧版/容量不足に耐え、無関係な保存キーを消さない。

## 計測

キー受信→状態更新→次の描画までを計測し、基準PCでp95 50ms以内を暫定目標とする。これは物理キー押下からディスプレイ発光までの総遅延ではない。
最高演出でフレーム時間p95 20ms以内を目安にし、長い停止も別途記録する。端末/ブラウザ/解像度/素材量を付記する。
音はAPIが返す遅延値と実際の可聴遅延を分ける。入力音を拍に遅延させていないか実プレイで確認する。
音切れ、クリップ、二重発音、ポーズ後のステムずれを記録する。
初回起動はキャッシュの有無と回線条件を明記し、転送量と操作可能になる時刻を記録する。
