# 制作計画

## Goal

メモ・手順書を書きながらMarkdownを学べる最初の版を作る。

## Context

ユーザーはメモ・手順書の作成を重視している。ルートの共通デザイン・フロントエンド指針に従い、日付フォルダ内に独立したアプリを作る。参照する記法の仕様は[CommonMark](https://spec.commonmark.org/0.31.2/)と[GitHub Flavored Markdown](https://github.github.com/gfm/)。表とタスクはGFMの拡張として説明する。

## Constraints

ブラウザで本文の編集、プレビュー、練習が完結する。サーバーへの本文送信、アカウント、共同編集、生成AIによる代筆は今回の範囲に含めない。本文中の記法の使用は練習の完了と区別する。原文の安全なHTML表示にはMarkedとDOMPurifyを使う。Marked単体ではHTMLを無害化しないため、サニタイズを別に行う。

## 実装順

1. 8記法の説明・挿入処理・構文木による練習判定と保存形式を作る。
2. メモ・手順書・空白の開始方法、編集、プレビュー、学習ガイドを組み合わせる。
3. 下書き保存、UTF-8ファイルの読込、コピー、Markdown保存を接続する。
4. 自動テスト、PCと狭い幅での実操作、日本語推敲、Astraレビューを行う。

## Done when

- 編集したMarkdownがプレビューへ反映され、記法の意味を確認できる。
- 見出し、太字、箇条書き、リンク、引用、コード、タスク、表を挿入できる。
- 練習は本文を変更せず、条件に合う回答だけを完了とする。
- 下書きを再読込でき、`.md`を開いて保存できる。
- 危険なHTMLやリンクを実行せず、保存・読込失敗から次の操作へ進める。
- 主要な実操作と幅ごとの表示を確認し、未確認事項を明記する。
