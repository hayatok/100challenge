# 全力退勤：仕様策定と制作計画

## 今回の目的

「消火器でオフィスチェアを走らせて退勤する」という題材を、ユーザーが望む派手な演出とバカゲー感で作る。仕様と画面イメージの策定後、クラウド開発の依頼を受けてオフィス一面の初期実装へ進んだ。

## 参照と制約

- 元のアート：`../art/zenryoku-taikin-concept.png` と `ART_DIRECTION.md`。
- ユーザーの追加要望：噴射・衝突・成功で強い気持ちよさを感じる派手な演出、グラフィックでも分かるバカゲー感。
- リポジトリの共通デザイン方針、game-design と level-design の資料を参照する。
- PCブラウザ・横画面を暫定の中心とし、ユーザーの希望が届けば操作仕様へ反映する。
- コア操作を旋回と噴射に絞り、最初は一面の完成を目指す。
- 遊びやすさと面白さは試作で確認する。仕様の数値は調整開始用の仮値。

## 今回の進め方

| 工程 | 決めること | 成果物 | 確認基準 |
| --- | --- | --- | --- |
| 1. 体験とルール | 操作、移動、連鎖、退勤と破壊の関係、初期範囲 | `SPEC.md` のゲーム仕様 | 操作で何が起き、何を目指すか説明できる |
| 2. 画面と演出 | カメラ、HUD、衝突・連鎖・成功の反応、演出の強弱 | `SPEC.md` の画面・演出仕様 | 派手な瞬間にも進路と主役を読める |
| 3. 画面イメージ | 通常プレイ、大衝突、退勤成功 | `../art/screens/` 内のPNG | 画風とHUDが仕様に対応し、3状態の差が分かる |
| 4. 整合性確認 | ルールの抜け、表示値、素材と文書のリンク | README・アート方針・Issue更新 | 決定事項と試作で確かめる仮説を区別できる |

コアループと報酬、画面と演出を独立した設計レビューで確認し、メイン担当が統合する。同じファイルは並行編集しない。

## 実装へ進む際の順番

| 段階 | 作るもの | 次へ進む判断 |
| --- | --- | --- |
| A. 操作試作 | 仮の椅子、噴射、旋回、残圧、壁との衝突、復帰 | 3分触って進行方向が理解でき、ぶつかった後に自分で戻れる |
| B. 気持ちよさの縦切り | 壊せる小道具1種、連鎖表示、音、短い衝突演出 | 同じ小道具で無限に稼げず、連続破壊と立て直しの違いが分かる |
| C. 一面のブロックアウト | 学ぶ区間、破壊区間、旋回区間、出口 | 初見で迷わず到達でき、タイムを縮める工夫がある |
| D. グラフィックと演出 | 主役、家具、小道具、漫画文字、定時ラッシュ、成功画面 | 小さな画面と低演出でも主役・障害物・出口を読める |
| E. 公開準備 | ローカル記録、入力・表示の確認、適切なcheck・Webビルド | 主要操作を実機確認し、生成物と検証をそろえて一覧へ登録できる |

日数や最終的な数値は操作試作の結果で見積もる。制作計画は工程の依存関係を示すもので、未検証の完成日を約束するものではない。

## クラウド開発：初期実装

- [x] Godot 4.6.3とWeb export templatesをそろえ、セットアップとcheckを用意。
- [x] A：慣性、旋回、噴射、残圧、固定家具との衝突、安全位置への復旧。
- [x] B：有限の加点、前進を条件にする2秒の連鎖、最大×3、音と漫画表示。
- [x] C：約108mの進路、2つの家具の島、床の矢印、エレベーター。
- [x] D：主役の4状態、3種の破壊物、同僚と小ネタ、紙・粉・立方体、ラッシュ、結果判子。
- [x] E：結果の保存、ポーズと非アクティブ時の停止、Rでの再挑戦、Webビルド、主要解像度のスクリーンショット。

ルール・実物理・経路と統合のテスト、実ブラウザのキー入力による退勤と保存を確認した。固定家具と主役のメッシュをまとめ、主役の影を少数に絞った。ポーズ時に親のALWAYSを継承して残圧が回復する不具合を修正し、統合テストに加えた。

実画面と測定値は [VERIFICATION.md](VERIFICATION.md) に記録する。初見の面白さ、実GPUでの60fps、生成モックに近づける造形・背景の仕上げは、次の調整項目。
