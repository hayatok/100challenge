# 全力退勤：演出とHUD v0.5

2026-10-15（Asia/Tokyo）。ユーザーの依頼は「演出を派手にし、画面内の文字と枠もゲームらしく作り込む。エフェクトのイメージを先に作り、それに沿って実装する」。アセットv0.4の玩具の会社員とオフィスに、職場の紙・判子・タイムカードを題材とする漫画調の演出を組み合わせる。

## 目的と制作順

まず現在の実画面と弱い演出を確認し、画像の設計資料を作る。その画像を見てからGodotに実装する。完成条件は生成画像の共有、実画面で分かる変更、操作・記録・ポーズと低演出の確認、WebビルドとGitHub Pagesの更新。

1. 変更前の実画面を保存し、噴射・破壊・連鎖・成功の見た目を棚卸し。
2. エフェクトと文字・枠を一枚の見本に生成。
3. 見本に沿ったラッシュ中のプレイ、衝突、退勤成功、タイトルの画面イメージを生成し、会話内で表示。
4. 画像を見たうえで、世界内のエフェクトとHUD・メニューを実装。
5. 実画面の前後比較、実キー入力での退勤、設定・再挑戦・ポーズ・フォーカス喪失、負荷を検証。
6. PRとCIを通し、公開版を更新。

生成資料は `art/screens/v0.5/`、実画面と検証は `docs/verification/v0.5/`。生成画像を実際のゲーム画面として扱わない。

## 現在の弱い部分

- 粉と紙が小さく、噴射の方向・勢いと衝突の瞬間が見分けにくい。
- 噴射・衝突・ラッシュに同じ小さな粒子と黄色の通知を使い、盛り上がりの段階が弱い。
- 白い四角いパネルと細い文字が中心で、ゲームの題材と漫画的な造形が枠へ反映されていない。
- 成功通知はresultへ遷移した後にplaying専用の通知へ送られており、判子を動かす演出が発火しない。
- ラッシュ中の破壊ごとに同じ「定時ラッシュ！」を再表示し、突入とその後の連鎖の差がない。
- 噴射で粒子上限を使い切ると、衝突と成功に必要な粒子を出せない。

## 共通の画風

「丸い玩具の職場 × 太い漫画 × 退勤の判子」。濃紺 `#223443` の厚い輪郭、生成り `#FFF4DC` の紙、朱赤 `#F4433E`、金 `#FFD45B`、青緑 `#159B9C`。ラッシュと衝突の短い差し色にマゼンタ `#F36A99`、噴射の縁に淡い水色を使う。

文字は太い日本語の字形、読みやすい白または金の塗り、濃紺の輪郭と短い影で作る。主要な数字は水平に保つ。傾きと変形は通知・ロゴ・判子・金額の短い跳ねへ絞る。枠には紙の切れ込み、色の見出し、二重線、パンチ穴、罫線、短い濃紺の影を使う。

大きい画面全体の発光やぼかしに頼らず、はっきりした形と面積、方向、リズムで派手さを作る。描画はGodot Compatibilityと単一スレッドWebで動くものにする。

## 演出の段階

| 状態・条件 | 見た目 | 時間と発生の基準 | 音 |
| --- | --- | --- | --- |
| 噴射開始 | ノズルから後方へ伸びる白い粉の錐形、淡い水色の縁、後方の細い軌跡、小さな始動の塊 | 初動100ms以内。離すと150ms程度で弱まり、残った粉は短く漂う | 短い噴射の立ち上がり＋ループ |
| 高速噴射 | 粉の塊が後方で広がり、画面端の速度線が伸びる | 噴射中と実速度で増減。前方の進路へ出さない | 既存の噴射音を維持 |
| 小道具の破壊 | 衝突位置の金色の星形、マゼンタのずれた縁、薄い衝撃輪、紙の扇、少量の金色立方体 | 星のピーク120〜180ms、紙は0.65〜1.25秒。重要な破壊へ粒子を優先配分 | 乾いた衝撃と紙の破裂 |
| 固定家具への衝突 | 接触点の星形と衝撃輪、短い文字「ドガァン！」または対象の通知 | 従来の停止80msと復旧条件を維持。既存の発生間隔を守る | 低い短音と紙の音 |
| 連鎖の増加 | 右上の大きい連鎖数字が一度跳ね、加算額を小さな別札で表示 | 約120msで戻る。複数の同時破壊は最終の連鎖音にまとめる | 上限付きの上昇音階 |
| 3連鎖のラッシュ突入 | 金・マゼンタの帯「定時ラッシュ！」、画面端の金色の速線、噴射の強調 | `rush_started` の一回だけ突入を通知。既存の1.2秒、再発生5秒間隔 | 短いラッシュ専用ジングル |
| ラッシュ中のその後の破壊 | 対象ごとの漫画文字と加算札、連鎖数字の反応 | ラッシュの大見出しを毎回やり直さない | 最終の連鎖音 |
| 退勤成功 | 赤い二重線の巨大判子が着地し、金のランク印、左右の紙・リボンの花道 | 判子は約140msで着地し短く戻る。祝福は1.2秒以内。結果と再挑戦は最初から使える | 判子の打撃＋短い勝利音 |
| 自己ベスト | 実際の更新時だけ青緑の小判子と星 | 一回だけ。記録の値を演出用に書き換えない | 成功音の補助 |

## HUDと画面

| 要素 | 題材と造形 | 情報と優先順位 |
| --- | --- | --- |
| 左上の時計 | 濃紺のタイムカード、赤い見出し、紙の差し込み、短い影 | 退勤TIMEと白い大きい時刻。衝突やラッシュでも位置を変えない |
| 右上の金額 | 生成りの被害明細、色のタブ、罫線、太い朱赤の金額 | 被害総額は副記録。大きい連鎖数字と倍率はその下に置く |
| 上中央の案内 | 小さな緑の案内札 | 出口方向と距離。大通知より上に置き、常に読める |
| 上中央の通知 | 切れた紙や尖った金色の帯、濃紺の輪郭、マゼンタの影 | 同時に大見出し一つ。加算額は別の小札。長い文字は縮小して収める |
| 左下の残圧 | 小さな消火器の絵、目盛り付きの黄色メーター、機械のような濃紺枠 | 数値と残圧の文字を維持。低残圧は色と文字、空では「離して回復！」 |
| 右下の操作 | 立体的なキーキャップと小さな操作札 | 旋回・SPACE・R・ESCを明記。残圧と出口を優先 |
| タイトル | 太い朱赤のロゴ、生成りの縁と濃紺の影、金の「定時だ。飛べ。」帯 | 左にロゴと主操作、右に3Dの主役。すぐ開始でき、設定へも直接入れる |
| ポーズ・設定 | クリップ付きの紙、控えめな判子、同じゲームのボタン | 停止中と次の操作を大きく示す。音量と演出の設定を維持 |
| 結果 | 退勤の明細、巨大判子、金のランク印、青緑の自己ベスト印 | 主記録の時刻を最大に。被害総額と最大連鎖は小さい行。再挑戦を赤い主ボタンに |

共通UI方針の意味色と44px以上の操作面を維持する。ゲームの題材と勢いを伝えるため、作品内の見出し・通知・パネルは濃紺の太い線と硬い影へ拡張する。ボタンは主操作の朱赤と副操作の生成りを一貫させ、フォーカスを見えるようにする。

## 可読性・設定・負荷

- 主役の顔、ノズル、前方の曲がる進路、出口、時計と残圧を隠さない。大きい帯は上の余白、速度線は画面端、粉は後方、祝いは主役の左右へ分ける。
- 画面の中央下に不透明な大通知を重ねない。前方が覆われる時間は200ms未満を目標に、実画面で確認する。
- 控えめでは速度線・画面揺れ・数字と判子の跳ねを止め、情報を伝える文字と形は残す。粒子を従来の約25%に保つ。
- ポーズとフォーカスを外した際は、物理・時間・残圧と新しい演出の時計を止める。再挑戦で粉・紙・通知・ラッシュ・判子の前回状態を残さない。
- 同時粒子の既存上限は80／52／20。噴射で全枠を埋めず、衝突と成功に予約枠を残す。重要なイベントでは古い噴射を置き換えられるようにする。
- 粉・紙・立方体は共有メッシュを使い、可能なら種類ごとのMultiMeshへまとめる。星・衝撃輪は少数の共有メッシュ、画面の飾りは一枚のCanvasで作る。物理ボディ・影・大きい全画面ポスト処理を増やさない。
- 1280×720と1920×1080、最低限960×540で、文字・枠・ボタンの欠けと重なりを確認する。クラウドのソフトウェア描画を実GPUの測定と扱わない。

## 検証する振る舞い

噴射の開始と停止、破壊の扇、連鎖の成長、ラッシュの一回だけの突入、衝突、成功の判子、実際の自己ベスト、Rと結果ボタンからの再挑戦、ポーズ中の停止、復帰後の再開、設定と消音。既存のルール・記録・物理・コースはこの改稿の演出に合わせて変えない。

## 実装と描画の仕上げ

粉・紙・立方体・星形・輪・軌跡・リボンを7種類のMultiMeshへまとめ、紙の縁はモデルの罫線や判子を押し出さない専用の輪郭にした。局所演出の形を見やすくしたネイティブの固定時点は [噴射](verification/v0.5/fx-jet.png)、[衝突](verification/v0.5/fx-impact.png)、[祝い](verification/v0.5/fx-success.png)。これらは演出単体の撮影用シーンで、通しプレイの記録ではない。

紙の模様や輪郭を個別に描く最初のHUD実装は負荷が大きかったため、色付きの三角形を部品ごとのArrayMeshへ集約した。点・バーコード・クリップ・罫線・輪郭を保ち、静的な形をキャッシュする。HUD単体の描画回数はタイトル549→27、プレイ576→39、結果472→30、ポーズ747→48。文字と操作部品は実際のGodot UIのまま。測定条件と比較は [hud-render-report.json](verification/v0.5/hud-render-report.json)。一面全体の操作結果は [VERIFICATION.md](VERIFICATION.md) に記録する。

## 実装と描画の確認

共有メッシュの粉・紙・立方体に、元から作った星形・輪・軌跡・リボンを加え、7種類のMultiMeshへまとめた。紙の印字まで押し出す輪郭では黒い破線が出たため、紙の外周だけに薄い濃紺の縁を作る。輪は白い共有形状を金・水色へ着色し、色の掛け合わせで濁らせない。

[噴射](verification/v0.5/fx-jet.png)、[衝突のピーク](verification/v0.5/fx-impact.png)、[成功のリボン](verification/v0.5/fx-success.png) は実行用のコードを使ったネイティブの演出単体レンダー。見やすい距離・明るい確認用照明と固定した演出時間で撮影し、通しプレイとは分ける。

HUDは輪郭・点・バーコードなどを頂点色付きの一枚のメッシュへまとめる。単体の同じ場面で、描画回数はプレイ576→39、タイトル549→27、結果472→30、ポーズ747→48に減った。文字・ボタンは実際に操作できるControlを使い、静的な形だけをキャッシュする。比較の条件と実画像は [hud-render-report.json](verification/v0.5/hud-render-report.json)。全ゲームの速度とは区別する。

生成イメージとの対応、実ブラウザの可読性・通しプレイ・設定と停止の結果は [VERIFICATION.md](VERIFICATION.md) に記録する。
