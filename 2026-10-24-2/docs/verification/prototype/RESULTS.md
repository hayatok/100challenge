# 90秒試作の検証記録

2026-10-25、Godot 4.7.2、macOS、Apple M5のCompatibility描画で確認した。企画資料の確認と、今回の実装・実描画の確認を分けて記録する。Web公開、マージ、リリースは行っていない。

## 実装した範囲

常時前進、A/D旋回、Sブレーキ、Spaceジャンプ、Shiftブースト、追従カメラ、下段の完走路、上段のジャンプ経路、照準灯機5機、ゲート得点、落下復帰、ポーズ、設定、結果、再挑戦を実装した。タイトルは人物を見せる固定カメラ、走行は後方カメラで描く。

今の上段はジャンプの練習と得点の経路であり、下段より短い近道ではない。3分の完成見本、他の敵2種、追加コース、物語の演出は実装していない。

## Tripoの生成と導入

ユーザーの選択に従い、ChromeのTripo Studioでサブスクリプションのクレジットを使った。APIの有料生成は実行していない。5点ともH3.1で非公開生成し、入力と生成先を[manifest](../../../art/source/studio/manifest.json)に保存した。

| 対象 | 生成・処理の消費 | ゲームへ導入したGLB |
| --- | ---: | --- |
| 澪 | 55＋標準リトポロジー5＋Mixamoリグ20＝80 | 40,000三角形、65関節 |
| ボード | 55 | 12,000三角形 |
| 照準灯機 | 55 | 10,000三角形 |
| 遺跡アーチ | 55 | 16,000三角形 |
| 浮遊庭園 | 55 | 17,999三角形 |
| 合計 | 300 | 5点 |

小物4点は生成されたメッシュをBlenderで減面・方向と寸法の調整・再出力した。元のダウンロードは変更していない。テクスチャ、材質の割当、UV層、寸法を再取り込みで確認した。アーチの開口は元と出力の両方で25本のレイが通過した。[数値記録と比較画像](../../../art/source/studio/)を残す。

澪はユーザーが保存した`anime+girl+3d+model.glb`をそのまま導入した。40,000三角形、28,133頂点、65関節のウェイトと逆バインド行列を検査し、非有限値と不正な関節番号はなかった。Blenderの骨表示用helperを人物の検査対象から除外し、元GLBとのSHA256一致を確認した。

姿勢は実リグの骨から方向を求め、膝・腕・首を動かす。脚のIKは足首の位置を保ち、[10枚の姿勢画像と計測値](poses/pose_metrics.json)を保存した。布や表情のアニメーション、曲面ボードとの厳密な足裏の接触は未検証である。

ボードの線や足パッド、小物の細い彫刻・溝・葉には、減面で歪みや省略が残る。コースと衝突は調整用のブロックアウト、路面と雲海はシェーダーによる表現であり、Tripoで作った部品とは区別する。

## 自動検査

`npm test`でGodotの検査を実行した。時計や得点の単体条件だけでなく、実コースの衝突とRiderの物理処理も使った。

| 検査 | 確認した範囲 |
| --- | --- |
| course_geometry_test.gd | 1,681回のレイ検査、段差、開口、衝突チャンクの境界 |
| rider_behavior_test.gd | 27項目。常時前進、ジャンプ、ブレーキ、入力バッファ、コヨーテ、ブースト、被弾、落下通知 |
| main_flow_test.gd | 46項目。状態遷移、ポーズ、復帰と加算時間、得点の重複、上段の加点条件、記録保存 |
| course_run_test.gd | 13項目。実コースの下段完走と第1上段ギャップの踏切・着地 |
| sentry_zone_test.gd | 全5機の245地点で描画三角形と命中範囲を照合し、25地点で実際の接地と命中を検査 |

下段の無入力走行は5,444物理tick、90.733秒で前進座標1,650.177mに到達し、落下は0だった。上段は315mから旋回入力で入り、455.823mで跳躍、474.475mで着地した。踏切からの最大上昇は2.078m、落下は0だった。検査を加速しても、観測した物理deltaは1/60秒だった。第2ギャップは同じ条件での到達性を未検証として残す。

Mainの一部の状態・加点検査はdeltaや信号を直接渡す。これらの成功を、実コースでのジャンプや実UIの検証として扱わない。記録ファイルは検査用の保存先へ分け、実ユーザー記録のバイト一致を確認した。

## 実操作と実画面

1280×720の実ゲームで、タイトル、カウント、旋回、ジャンプ、着地、ブレーキ、落下復帰、完走、再挑戦、ポーズ、設定を操作した。ブレーキ中の8.1m/s、ジャンプ中の人物とボード、落下回数1、結果の91.68秒・900点・落下0を、それぞれ別の走行で確認した。ブレーキの画像は敵の警告修正前の記録である。修正後の警告は[Webの実走画面](web-warning-retina.jpg)で確認した。

ポーズ前後で時計と位置が変わらないことを[状態比較](native-pause-comparison.json)で確認した。設定の「動きを減らす」と音量50%は保存ファイルへ反映され、検査後は元の設定へ戻した。フォーカスを失うと走行がポーズへ移ることも確認した。

実画面では路面が白く飛んでいたため、照明・空・石の継ぎ目を調整した。曲線上の敵の警告は表示と命中範囲がずれていたため、道路と同じ断面の座標で警告メッシュと命中判定を作るよう修正した。実路面の曲線・勾配・バンク・幅と境界の検査を追加した。

走行中のQA出力で120fps、約38万プリミティブ・68 draw callsを観測した。これはApple M5での一時点の値であり、他のPCやWeb版の性能を保証しない。ネイティブ操作ツールはShift単独の保持を送れなかったため、ブーストの実キー確認はWeb版へ分ける。

## 残る確認

音の生成と固定数の再生ノードは検査したが、聴感でのミックス確認は未実施。ヘッドレスの短い強制終了ではAudioStreamWAV関連の4インスタンスについて終了時の警告が出る。物理検査とMainを破棄して待つ検査では同じ警告が出ていない。実機パッド、長時間の繰り返し、他ブラウザ、ゲームとしての難易度と面白さは今後の試遊で確かめる。

日本語の推敲、Astraレビュー、PRとActionsの結果は、[完了記録](delivery.json)に記録した。

## Webと画面サイズ

ChromeのWebGL 2で5アセットを読み込み、1280×720で開始・Shiftブーストを操作した。33.1m/s、風力13/100を実画面で確認した。960×540へ変更した走行は88.51秒・900点・落下0で完走し、結果と保存表示を確認した。

画面サイズに合わせて文字と枠を拡縮するため、Godot標準の`canvas_items / expand`を採用した。日本語の文字・枠の画風を保ち、操作面を64px、960×540では48px相当にした。全7画面を1280×720と960×540で描画し、文字切れ・重なり・操作面のはみ出しを確認した。[レイアウト用の実描画記録](ui-scaling/metrics.json)は状態と値を用意した検査である。実際の完走操作の記録とは分ける。設定の根拠は[Godotの画面サイズと高DPIの説明](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html#hidpi-support)を参照した。

## レビュー

Astraのコアレビューで、落下復帰の途中にポーズして再開すると、チェックポイントへ戻る前に人物が動き出す問題を指摘された。カウント終了時も復帰中は人物を無効のままにし、回帰検査7項目を追加した。復帰の残り時間中は実physics tickで位置・進捗が固定され、時間を消化して665mから前進を再開することを確認した。最終UI、文書、検証記録も同じレビューの対象に含めた。最終レビューでは追加指摘はなかった。

日本語の[読み込み画面](web-loading-1280.jpg)と[起動失敗画面](web-boot-error-960.jpg)を用意した。失敗画面はエンジンのJavaScriptを404にする検証用サーバーで確かめ、「再読み込み」による再リクエストも確認した。通常のサーバーは同じファイルを正常に配信している。

検証ブラウザの通常撮影では、960×540のページ全体が0.75倍で記録される現象を確認した。[HTML上の実寸](capture-scale-loader-960.json)と[通常撮影](capture-scale-loader-960.jpg)を照合し、ゲーム以外のHTMLも同じ比率で縮小されることを確かめた。全体撮影へ切り替えると[960×540の全面表示](web-title-960.jpg)を確認できた。ゲームの縮小不具合として加えた回避処理は取り除いた。

日本語はREADME、アプリ方針、実装計画、検証記録、画面文言、カタログ、Webの読み込み・失敗表示を対象に原稿と資料を照合した。yomiyasuの構文候補を読みやすさの点数にはせず、実ファイルとの照合記録を残した。
