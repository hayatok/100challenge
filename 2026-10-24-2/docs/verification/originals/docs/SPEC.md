# 雲海サーファー / CLOUDSEA SURFER 企画仕様 v0.1

本書の数値、操作感、所要時間、合否基準はすべて試作用の未検証値である。ゲームは未実装。現在の成果物は企画仕様と生成画像に限り、画像は実際に動く画面の証拠ではない。ゲーム実装、3Dモデル制作、公開は今回の作業範囲に含めない。

## 1. 目指す体験と制作範囲

雲海に浮かぶ遺跡の斜面をホバーボードで滑り、遠くに見えた足場へ跳び移る三人称の3D滑走アクション。加速の気持ちよさと、次の曲がり角・着地点を読んでラインを選ぶ楽しさを中心にする。敵との遭遇でも滑走を止めない。

主人公は凪原 澪（なぎはら みお）、17歳の高校2年生。凛としてクールで、可愛らしさもある。キャラクター、世界、文字、枠、画面の美術仕様は [ART_DIRECTION.md](ART_DIRECTION.md) を参照する。

主対象はPC。macOS版を操作・表示・性能の品質基準とし、Web版も同じ内容で遊べることを目指す仮案とする。エンジン、配布方式、ブラウザごとの性能は未決定。

制作段階を次のように分ける。

1. 現段階：仕様と生成アートを照合し、制作対象を具体化する。
2. 次段階の候補：90秒の灰色ブロック試作で、滑走・旋回・ジャンプ・カメラを検証する。
3. 操作の評価後：第1コース「白環の通学路」を約3分の完成見本にする。
4. 完成見本の評価後：通学路、風車水道、夕凪天文台の3コース、各3〜5分をフルゲームの候補として再検討する。

約3分は完成見本の目安であり、初見・速度・ルート・落下で変動する。制限時間ではない。フルゲーム全体を3分に確定したものとして扱わない。

## 2. 遊びの流れと判断

「先の地形を見る → 進入速度とラインを選ぶ → 曲がる・跳ぶ・加速する → 着地と通過の手応えを受け取る → 次の地形を読む」を繰り返す。

広い完走路と、狭いが成功すればタイムを縮められる高速路が短く分岐して合流する。完走路は最後まで有効な選択肢とし、高速路の成功をクリア条件にしない。進入速度と残りブーストによって選び直せる分岐を置く。タイム競争で熟練者の最速経路が定まること自体は問題としない。

収集品、成長強化、装備、武器、狙撃、二段ジャンプ、コンボ技は入れない。敵を倒す必要はない。後述の連続成功倍率は得点処理であり、追加の技入力ではない。

3Dは、斜面とバンクの傾き、上下に重なる足場、空中から見える次の進路を読むために使う。奥行きのある背景だけで成立扱いにせず、試作で高さと傾きが操作判断に寄与するか確かめる。

## 3. 操作と移動

| 行動 | キーボード | パッド |
| --- | --- | --- |
| 左右旋回 | A / D | 左スティック左右 |
| ブレーキ | S | LT |
| ジャンプ | Space | A |
| ブースト | Shift | RT |
| ポーズ | Esc | Menu |

常時自動前進。Wやマウス操作を必須にしない。パッドのボタン名は標準的な表記で、実装時には接続機器に応じた表示へ切り替える。操作表示は現在使っている入力方式に合わせる。

| 項目 | 試作値・条件 |
| --- | --- |
| 標準速度 | 18 m/s |
| 下りの速度上限 | 28 m/s |
| ブーストの速度上限 | 34 m/s |
| ブレーキ時の最低速度 | 8 m/s。後退はしない |
| ジャンプ初速 | 上向き8.5 m/s |
| 重力 | 18 m/s² |
| 同高度の理論値 | 滞空約0.94秒、上昇約2.0 m、水平18 m/s一定なら約17 m |
| 必須ギャップ | 同高度で12 m以内。ブーストを要求しない |
| 入力バッファ | 接地前0.12秒のジャンプ入力を保持する仮案 |
| 足場端の猶予 | 離地後0.10秒までジャンプを受け付ける仮案 |

ジャンプは押下1回で高さを固定し、長押しで伸ばさない。空中は弱い左右補正のみ。バッファを消費したら次の押下まで再ジャンプせず、着地時の長押し連続ジャンプも起こさない。踏切ランプは別のジャンプ曲線として管理し、通常ジャンプの到達距離と混ぜない。

理論値は水平速度一定・同高度の場合だけに適用する。8 m/sでは同高度の到達距離が約7.5 mとなるため、12 mの隙間を全速度で渡れるとは扱わない。必須の踏切前には減速から標準速度へ戻れる助走を置き、低速時には短い隙間または連続した路面へ進めることを設計条件にする。高度差、旋回、空中補正、接地判定を含む実到達性は実装後に再計測する。

旋回はコースに沿って前進しながら左右へ進路を変える方式とし、敵の周囲を自由に逆走・周回できる構成にしない。旋回半径、横方向の最大補正、加減速の時間、空中補正量は試作で決める。基本ルートはゲージ0でも完走できることを必須とする。

## 4. ブースト

ゲージ上限100、スタート時60。使用中は毎秒40を消費する。満タンから連続2.5秒が理論上の最大使用時間。押している間だけ使用し、0になったら終了する。一度離して再入力するまで再始動しない。

| 回復条件 | 回復量 |
| --- | --- |
| 非使用中、新たに進んだ距離 | 6 mにつき1 |
| ゲート通過 | 20 |
| クリーン着地 | 10 |
| 敵への近接通過 | 10 |

使用中は距離・イベントのいずれからも回復しない。イベントの回復分を後払いせず、使用中に発火したイベントIDも消費済みにする。得点はブースト使用の有無と独立して与える。

距離回復はコースの前進座標の最高到達位置で判定し、チェックポイント復帰後の同じ区間や、分岐の再通過では増えない。分岐ごとの座標は合流先と対応付け、横移動や経路の往復を新しい前進距離に数えない。各イベントIDも1走につき1回だけ有効とし、チェックポイント復帰で復元しない。

ゲージを使い切る下り直線と、次の分岐に残す選択を用意する。押しっぱなしが全区間の最適解になっていないか試す。ゲージ消費のためだけに必須操作を増やさない。

## 5. 第1コース「白環の通学路」

遠くに見える巨大な輪状遺跡を一貫した目印にする。各区間境界をチェックポイントとし、開始地点を含めて進捗を記録する。区間の尺は標準的な走行を想定した目安である。

| 目安 | 区間 | 体験・配置 |
| --- | --- | --- |
| 0〜30秒 | 雲の坂道 | 広い下りで旋回、ブレーキ、小ジャンプを順に試す。失敗しても下段の道に着地できる。操作表示は必要になる直前に1つずつ出す |
| 30〜75秒 | 守りの回廊 | 完走路と短い高速路が分岐・合流。敵3種を順に単独紹介し、横へ避ける、跳ぶ、止み際を通る判断を安全な場所で試す |
| 75〜100秒 | 白雲の大湾曲 | 敵のない広いバンクで景観を楽しむ。非使用時の走行でゲージを回復でき、見える着地点への跳躍を置く |
| 100〜150秒 | 環状遺跡の連絡橋 | 坂、分岐、敵を組み合わせる。同時に対処する敵は最大2種。先の出口と着地点を見せ、着地直後に攻撃を重ねない |
| 150〜180秒 | 白環への跳躍 | 安全な短い直線で態勢を整え、巨大な輪を通る連続滑走と最後の跳躍。新しい操作を追加せず、覚えた行動で締める |

各敵は単独で安全に学んでから複合区間へ移る。45秒の紹介区間では予告と回復の間隔が不足する場合があるため、実装時に敵間隔を優先して区間尺を延ばす。3分に合わせるために初見の反応時間を削らない。

## 6. 敵3種と公平性

敵は遺跡の守護機械。HPを削る戦闘や追い回しは行わず、通過時の判断に役割を限定する。

| 敵 | 予告 | プレイヤーの判断 | 禁止する配置・挙動 |
| --- | --- | --- | --- |
| 照準灯機 | 片側の路面に細い照準線を示し、固定してから直線照射 | 早めに横へ抜けるか、照射前に短いブーストで通過する | 固定後の追尾、通路全幅の封鎖、曲がり角の陰からの即照射 |
| 掃雲機 | 低い棒の伸びる範囲を輪郭と機械の動きで示す | ジャンプで越えるか、外側へ迂回する | 着地点への追撃、空中での追加攻撃、迂回先が崖だけになる配置 |
| 風門番 | 旗と帯状の粒子で横風の方向・範囲・開始・終了を示す | ブレーキで止み際に合わせるか、風のない細い側道を選ぶ | 全幅を塞ぐ風、出口や崖際への攻撃、予告と異なる範囲 |

風門番の風は視覚上の表現と攻撃判定であり、被弾で進行方向を強制変更しない。敵3種の被弾処理は共通にする。

- 速度をその時点から30%減らす。減速後の地上速度は8 m/sを下限とする。
- 操作を維持し、方向を勝手に変えず、敵のヒット自体で崖から押し出さない。
- ヒット後1.5秒は追加ヒットを無効にする。連続成功は最初のヒットで切る。
- 次の予告までに、立て直す距離と通行可能な出口を確保する。

予告は最高接近速度でも最低1.5秒を確保する仮案とし、横へ逃げる時間が長ければさらに延ばす。34 m/sなら1.5秒で約51 m進むため、見通しと配置距離もこの条件から求める。反応時間だけを満たしても、必要な横移動が間に合わない配置は不可とする。

色や音だけに頼らず、輪郭・形・動きでも範囲とタイミングを示す。カメラ内で予告を読めない敵は攻撃を始めず、画面外から命中する攻撃を禁止する。複合配置は個別に回避できるだけでなく、同時にも最低1本の逃げ道があることを確認する。

## 7. 得点と記録

| 成功イベント | 基礎点 |
| --- | --- |
| ゲート通過 | 100 |
| クリーン着地 | 100 |
| 敵への近接通過 | 150 |

成功時に連続数nを増やし、その成功の基礎点へ `1 + 0.25 × min(n - 1, 4)` を掛ける。初回1.0倍、5回目以降は上限2.0倍。最後の成功から6秒経過、またはヒット・落下・着地失敗で連続を終了する。次の成功はn=1から始める。

判定は編集時に割り当てたイベントIDごとに1走1回。通常走行の細かな離地や着地を得点源にせず、指定ジャンプ区間の着地だけを対象にする。近接通過も敵ごとに1回だけとし、接近し続けたり、再通過したりして稼げない。クリーン着地の姿勢・接地速度・受付領域、近接通過の距離は未調整で、見た目と判定の一致を試作で決める。

タイム、スコア、落下回数は別々に表示する。未検証の基準で優劣を断定しないため、初期はSなどのランクを付けない。タイム短縮と得点の両方を単一の総合値へまとめない。

ローカルに保存するものはコース別のベストタイム、ベストスコア、設定のみ。走行中の永続成長や収集進捗は保存しない。中断した走行はベスト記録にしない。保存失敗時も走行と結果閲覧は続けられ、保存できなかったことを結果画面で示す。

## 8. 落下、復帰、再挑戦

HP、残機、タイムオーバーは設けない。何度失敗しても完走を目指せる。

落下時は連続成功を消し、約1秒で直前チェックポイントへ戻す。復帰演出中も時計は進め、さらに3秒を追加ペナルティとして加算する。したがって1回の落下による時間増加は追加3秒だけではなく、復帰に要した実時間も含む。表示上も追加ペナルティと走行時間を混同させない。

復帰時は速度18 m/s、ゲージは落下直前の残量と40の大きい方にする。通過済みイベントIDと前進の最高到達位置は巻き戻さない。落下した区間では、その走行の残りについて着地・近接の得点とゲージ回復を無効にする。未通過ゲートは通常どおり1回だけ有効。次の区間へ進めば、そこで未消費のイベントは有効となる。

復帰用のゲージを故意落下で使い回すことが最速にならないか検証する。区間ボーナスの無効化は得点稼ぎを防ぐが、ゲージ補給によるタイム短縮まで保証するものではない。無落下より有利になる場合は、この復帰値やペナルティを見直し、未解決のまま完成扱いにしない。

「最初から再挑戦」はタイム、得点、連続数、イベントID、前進距離、落下回数をすべて初期化し、スタート速度18 m/s・ゲージ60へ戻す。保存済みのベストと設定は保持する。

## 9. カメラ、音、操作の手応え

追従カメラは進路の先と次の着地点を優先して映し、マウスで補わなくても遊べることを条件とする。速度で視野角を急変させず、旋回時にも地平線と足場を読み取れるようにする。自機や遺跡の柱で重要な予告が隠れる場合は、カメラと配置を修正する。狭い場所をカメラ任せで通過させない。

速度に応じた風音、接地中の滑走音、踏切、着地、ブースト開始・終了、敵の予告、被弾を区別する。クリーン着地とゲート通過は短い音と画面内の小さな反応で返す。成功演出は進路を覆わず、同時発生時も敵予告の音を優先する。BGM・効果音は個別音量を設ける仮案とし、消音でも必要な判断を行えることを確かめる。

画面揺れと速度線は強度を抑え、動きを減らす設定で停止または縮小する。設定変更で敵の予告時間や当たり判定は変えない。演出がなくても加速と接地を判別できるか確認する。

## 10. 画面と状態遷移

タイトルからコース選択または走行開始へ進み、短い開始カウント後に入力と時計を同時に有効化する。カウント中のジャンプやブーストを開始直後へ持ち越さない。コース読み込み中は進捗または処理中表示を出し、失敗時は再試行とタイトルへ戻る操作を用意する。

走行中は速度、ブースト、タイム、得点、連続成功、区間進捗を優先順位に沿って表示する。詳細な画面構成はART_DIRECTION.mdに従い、実際の文言と大きな値で読みやすさを確認する。

EscまたはMenuでポーズし、物理、走行時計、連続成功の6秒、敵、音の進行を止める。フォーカス喪失でも自動ポーズする。復帰時にすぐ走り出さず、続ける操作の後に3秒の再開カウントを置く。カウント中も時計と敵を止める。ポーズ、フォーカス喪失、再開時に入力バッファと押下状態をクリアし、再入力を求める。

ポーズ画面には「続ける」「最初から再挑戦」「設定」「タイトルへ戻る」を置く。再挑戦とタイトルへ戻る操作では現在の走行が破棄されることを確認できるようにする。設定から戻る場合は走行状態を保つ。中断してタイトルへ戻った走行を後から再開する機能は初期範囲に含めない。

ゴール通過で時計と得点判定を止め、入力の残留を消して結果へ移る。結果は今回のタイム・スコア・落下回数と、それぞれのベスト更新を示す。「再挑戦」「コース選択」「タイトルへ戻る」から選べる。セーブ失敗でも操作を塞がない。

## 11. 試作と合否条件

以下は今後の検証計画であり、実施済みの結果ではない。楽しさ、操作感、性能、Webとの同等性は未確認。

90秒の灰色ブロック試作は、最初の約30秒で旋回と減速、次の約30秒で斜面とジャンプ、最後の約30秒で分岐と敵1種を試す。敵3種や完成アートを一度に入れず、移動だけでも再走したくなるか確認する。実装する際の仮合否条件は次のとおり。

- 初見5人中4人が口頭補助なしで完走でき、失敗した人が原因と次に試す対処を自分の言葉で説明できる。
- 着地点や敵予告がカメラの都合で見えずに失敗する事例がない。発生したら配置またはカメラを修正して再確認する。
- ゲージ0で基本ルートを完走できる。低速進入、ヒット直後、チェックポイント復帰からも回復して進める。
- 最大速度で予告を見てから対処が間に合い、敵2種の複合でも逃げ道が残る。無音・動きを減らす設定でも判別できる。
- ブーストを押し続けるだけの走りと、狙って残す走りを比較し、少なくとも試作内の1か所では後者が有利になる理由を説明できる。
- 再走で別ルートを自発的に試す人がいる。自由な周回、分岐の再通過、故意落下で得点や回復を繰り返し稼げない。
- 故意落下の補給走行が、同等の操作をした無落下走行よりタイムで有利にならない。復帰後のイベント無効化とID保持も確認する。
- ポーズ、フォーカス喪失、再開、再挑戦、クリア、中断で、時計、敵、音、入力、連続成功の停止と初期化が仕様どおりである。

完成見本ではさらに、敵3種の学習順序、約3分の緊張と休息、全画面の文字と枠、実際の音、保存成功・失敗を確認する。macOSの主対象解像度と小さい画面、キーボードとパッドを実操作で確認し、Web版の表示・入力・音声開始・性能も別に記録する。使用機器、画面サイズ、ビルド、走行結果を記録し、どの環境で確かめたかを明示する。
