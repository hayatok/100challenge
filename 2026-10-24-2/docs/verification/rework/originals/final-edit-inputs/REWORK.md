# 雲海サーファーの再設計

旧90秒試作はユーザーからゲーム性、モーション、演出、コース、人物の奥行きについて不採用の評価を受けた。完走と機能の動作を確認しても、遊びとしての評価にはならなかった。旧検証記録はその時点の動作記録として残す。

## 目的と範囲

自分で進路を作り、カーブでためた風を解放して跳ぶ、短い滑走コースを作り直す。人物の動き、足元の反応、音、カメラ、操作表示をこの一連の行動へ合わせる。新規コースの量を増やす前に、この操作を繰り返したくなるかを試す。

対象は `game/` と本作の資料。Godot 4.7.2、macOSとChrome、1280×720と960×540を使う。制作モデルには引き続きTripoを使う。旧モデルと生成元を残す。Tripoは承認済みのStudioサブスクリプションのクレジット枠を使い、別料金の開発者APIは利用しない。Web公開、マージ、リリースタグの作成は行わない。

## 遊びの変更

| 行動 | 操作と結果 | 判断 |
| --- | --- | --- |
| 向きを作る | A / Dで実際の進行方向を回す。離すとその向きを保つ | 遠くの曲がり角を見て入り、出口へ向きを戻す |
| 風をためる | Sを押しながら旋回する。速度を落として深く曲がる | 長くためるほど加速は強くなるが、進路を外しやすい |
| 解放する | 十分ためてSを離すと、ためた量に応じて加速する | カーブの途中で使うか、出口や離陸まで保持するか |
| 跳ぶ | Spaceで路面の切れ目を越える | 離陸位置、速度、向きを着地点へ合わせる |
| つなぐ | 進路に合わせた着地で風力を回復する。Shiftは風力を消費して加速する | 次のカーブへ備えるか、今の直線で使うか |

再設計版では自動的に道へ向く処理と、直線を走るだけで風力が回復する処理を外した。初心者が学べる幅と復帰地点は用意する。無入力で落ちること自体は面白さの根拠にせず、失敗の理由と修正する操作が見えるかを確認する。

コースは900m。広い最初のカーブ、解放して跳ぶ区間、逆向きのカーブと敵、雲を見渡す短い休息、連続カーブから最後の跳躍へつなぐ。3か所の切れ目は245–257m、530–546m、825–849mで、実際に路面がない。手前18mに高さ1.5mの発射台を作り、形と衝突を同じ式で生成する。小さい2か所は十分な速度ならSpaceなしでも渡れ、最後の24mにはSpaceが必要になる。離陸前から着地点と黄色い端部が見えることを、実画面で確認する。旧コースの記録とは別に保存し、設定だけ引き継ぐ。

## 人物と反応

成人19歳の人物設定を維持し、[新しい4方向の参照画像](../art/source/mio-v2/ref/)からTripo StudioのH3.1で生成した。生成ジョブは `c237fc39-019a-4cd9-893b-38dd459aed4f`。生成55、通常リトポロジー5、Mixamoリグ20の合計80クレジットを使った。出力は39,999三角形、65骨で、元のGLBを保ったままゲームへ取り込んだ。

[旧モデル・新モデル・参照画像の比較](../art/source/mio-v2/previews/fullbody-comparison.png)と、顔・左右・背面、80姿勢の検査を保存した。ゲームでは反射を抑えたToon材質を複製して適用し、元の形状と画像は変更していない。隣接する雲の印、腰のタブ、髪の毛先や衣装表面には生成由来の粗が残る。モデルの技術互換と、見た目の最終評価は分ける。

澪は19歳の凛とした人物像と衣装を保ち、正面・左右・背面の画像から作り直す。顔の立体感、後頭部の髪、胴体と衣装の厚み、手足を各方向で比較する。生成成功や面数だけを採用理由にしない。

待機は腕を下ろして重心を休める。走行では膝を使い、視線と肩が先に向き、腰と腕が追う。ブーストは進行方向へ踏ん張り、旋回はボードの内側へ荷重する。身体の正面とボードの進行方向は別の軸として扱う。離陸、空中のまとまった姿勢、着地の圧縮と反動、被弾後の立て直し、終了の身振りを明示したキーフレームで作る。

後流、エッジの飛沫、解放時の音、着地の短い輪は、起きた操作を伝えるために使う。中央の進路を覆わず、固定数の描画・音声ノードで処理する。ポーズ、フォーカス喪失、再挑戦、動きを減らす設定を確認する。現モデルにない顔モーフや髪・衣装ボーンは、動かしたものとして報告しない。

## 制作順と確認条件

1. 旧画面と実装から、操作が結果を変えていない箇所を確認する。
2. 進行方向、カーブ、解放、切れ目を含む短いコースと、動き・音・画面の接続を作る。
3. マルチビューから作った人物を多方向で比較し、同じ操作へ取り込む。
4. 手動で曲がる、ためる、解放する、跳ぶ、失敗して戻るまでを試す。入力を与える自動検査は到達性の資料として分ける。
5. 実画面で分かりにくい操作や身体の不自然さを直し、日本語、Astraレビュー、CIを確認する。

次の評価では「何も押さなくても進んだ」「数値が増えた」「ポーズの画像ができた」を完成の根拠にしない。操作に対する身体とボードの反応、次の足場を見て選べる猶予、成功と失敗の分かり方を記録する。面白さについては実装者の評価とユーザーの試遊結果を区別する。
