# 店舗と人の動線の再確認

Goal: 道路から入店、売り場、会計、退店までの不自然な配置・移動を修正する。
Context: navigation.gd、simulation.gd、store_scene.gd、初期店と通常営業の画面。
Constraints: 経営機能や完成版の範囲を追加しない。配置・資金・在庫を維持し、既存の経路探索と待機列を使う。
Done when: 店員と会計客がレジの反対側に立ち、入口や待機列を棚で塞げない。住人が店内に突然出現せず、歩道と扉を通り、退店後に街の端まで歩く。通常営業と実画面で確認する。

開始時点のブランチには、壁沿いの冷蔵ケース、中央の背中合わせの棚、入口側のレジ、レジ裏の店員位置、売り場・会計の待機列が実装済み。初期店の実画面でもこの配置を確認した。

追加で見つかった問題は、道路の端から入口まで車道沿いを歩けることと、街の端で人物が25%の不透明度で突然現れること。車道から歩道へ接続する経路に制限し、端では完全に透明になるよう修正する。旧版の保存済み経路も、次の移動時に現在位置から再探索する。

## 検証結果

- 動線49項目が成功。全3段階の敷地で往復が歩道と扉を通ること、旧経路が隣の歩道へ移ることを確認。3日間の通常営業では入店85人・退店85人、会計中373分、最大3人の列を観測し、店内での出現・消失、壁抜け、会計客と店員の位置混同はなかった。
- 棚の順番待ち・追加購入・補充後の店員の退避を検証。コア347項目とUI50画面、Webビルド、差分の空白チェックも成功。専用のlintコマンドはなく、GDScriptはGodot実行・ビルドで確認した。
- macOS 1187×768で通常生成した棚の列から営業を進め、会計5人から16人への増加を確認。Webは375×812でレジの反対側にいる店員と客、1440×900で棚の前の買い物客と空いたレジ前の通路を目視確認した。確認画像は `screenshots/spatial-review-mobile.png` と `screenshots/spatial-review-desktop.png`。
- この記録は店舗の配置と動線の修正に限定する。ゲーム全体の完成版としての品質判定や、56日間の全攻略監査を完了したという意味ではない。

## 再発の原因と検証の追加

住人の購買判断を改善した後の本編比較で、49日目の朝に棚の先頭を目指す人が `(8,1)`、後ろへ並ぼうとする人が `(8,2)` で互いを塞ぐ状態を発見。空いた待機位置を予約するだけでは、そこへ行く途中で別の人の予約位置を通ることを防げなかった。さらに満杯の棚を待つ人が入口で `choose` のまま重なっていた。

経路は他人の列の位置を避け、既に逆転している場合は空いた隣へ一歩よける。棚の空きを待つ人には入口・売り場の利用面・レジ列を避けた個別の待機場所を割り当てる。欠品後に同じ棚を選び直す先頭客の順番も維持する。

見逃しを防ぐため、売り場の検証には「同じ方向から並ぶ」だけでなく、逆方向からの接近、追加購入、欠品後の再選択、満杯の棚を入口で待つ場合を含める。交差状態から実会計まで終えられる回帰検証と、冬までの通常方針比較を併用する。初期3日間の動線テストだけを本編全体の証拠にしない。

## 冬の混雑と歩道の再設計

初期3日間だけでは、増えた客が待機場所で通路を分断すること、歩道の端で入店と退店が循環待ちになることを見逃していた。歩道の絵と通行領域を3列へ広げ、車道は範囲外にした。自動ドアは2枚の扉で入店と退店を分ける。旧店の配置と在庫を維持し、隣の扉の位置に設備がある場合は建設から修復できる。

停止する客の場所は通路の連結性を保ち、棚・会計の列の周囲を空ける。会計待ちも棚の前から移動する。通路を歩く人は対向者と左右に分かれてすれ違い、列や入口の停止位置は共有しない。囲まれた客のために接近客が隣へよけ、歩道でも退店を妨げている待機客へ順に道を空ける要求を伝える。

再発検証には、実会計に加えて、両方向からの60人の集中来店、4人の循環待ち、棚の先頭が停止した列と接近客に囲まれる場合を含める。各人物の移動は隣接する床に限定し、店内の出現・消失、客側と店員側の混同、扉の共有を確認する。初期店の短い検証だけを本編全体の品質判定には使わない。

最終コードでは集中来店60人の残留0人、通常3日間の入店93人・退店93人、動線52項目が成功。冬の実営業を再開したmacOS画面でも会計14→81人と列の解消を観察した。目的のある買い物を終えた客が無関係な棚を回り続ける行動も改めたため、経営バランスへの影響は別途比較中。詳細と限界はBETA_PLANの進捗13へ記録する。

## 勤務時間外の重なりと端点の相互待ち

購入場面を拡大して確認すると、退勤する店員の下に客が隠れていた。勤務中の一部作業だけを衝突対象にする実装を改め、売り場の雇用済みスタッフ全員を含める。反対方向へ歩く店員と客は隣接床の間ですれ違い、描画も実際の移動方向に沿って左右へ分かれる。旧保存に残った重なりも空いた隣へ一歩動いて復帰する。

この修正後の12人の本編検証から、別の不具合も見つかった。到着と退店の最終地点が同じ歩道端だったため、到着者1人が退店者2人に囲まれると動けず、後続の来店を止めていた。端点を進入方向と退出方向の列に分け、古い退店経路も現在位置から新しい端点へ歩くようにした。物語の条件や所持金で結果を補正していない。

勤務中・時間外の同一床チェック、店員との対向歩行、古い重なりの復帰、端点での3人の相互待ちを回帰検証へ追加。現在の動線59項目、60人の集中来店と全員の退店が成功。12人全員の全36段階が本編で達成し、条件を満たした実レシートも確認した。`beta-stories-current.json`。これにより短い初期営業だけで見逃した勤務交代と長期の往来を検証範囲へ含める。

macOS 1187×768で旧保存の客を選択できること、レジを挟む双方の位置、パンと激辛商品の会計・持ち帰り、16:11→23:05の4倍速営業と交代を確認。画像と再現条件はBETA_PLANの進捗14。経営方針の成立範囲と音の実ミックスは引き続き監査中。
