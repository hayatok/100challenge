# ベータ版への再設計（進行中）

Goal: 住人に愛着が生まれ、品揃え・配置・人員の判断を試したくなる経営ゲームへ作り直す。完成版の土台として遊び通せるベータ版を実装・実画面で検証する。
Context: PROPOSAL.mdの4本柱と16章、現行の実装、Issue #74の動線修正。2026-09-06、ブラウザで初期店を再確認。前の目標ターンは配置・動線を実装して検証したため progress。現在のベータ版目標は未達。
Constraints: 難易度・コミカルさ・名前付き住人・斜め見下ろし・完全なドット絵を維持。Steam手続き、第三者試遊、セーブ保護の追加は対象外。素材や描画は既存方針より今回の明示要望を優先。過去アプリに触れない。数だけのテスト・同じ検証の重複で品質を装わない。
Done when: 以下の全項目が実装とプレイの両方で確かめられること。部分実装やチェック成功だけで全体を達成扱いにしない。

## 現状監査

- 人物は157×215の生成画像を36×49へ縮小。設備と床は可変倍率の連続座標描画。輪郭、色数、ピクセル密度が不統一。
- 商店の設備が木製の箱中心で、コンビニの金属棚・商品パッケージ・値札の識別が弱い。
- 80商品はカテゴリ内で価格・品質を等差的に上げる方式。嗜好もカテゴリ単位で、辛さ・健康・新味・満腹といった選択が弱い。
- 12人の物語は2/5/10回買うだけで進む。本人の事情を満たした結果になっていない。
- 曜日イベントが固定反復。中盤以降の新しい判断・予測・代償を要する変化が不足。
- 管理画面は横断的な一覧中心。店内で気付いた問題から対応するまでの距離が長い。
- 60方針比較は経済ルールの一部の証拠。面白さ・実操作・描画の品質を証明しない。

### 進捗 1: ピクセルと住人の事情

- 世界をSubViewportに分離。32×16タイルを整数1〜4倍で描く。文字は別レイヤーで読む。ズーム・クリック座標を変換する。
- 12人の主役に16×24原寸の髪・服・持ち物を定義し、4方向・歩行・商品を選ぶ・喜ぶ姿を描く。他の住人とスタッフも同じパレットと密度。画面と人物詳細が同じ姿を使う。`art/beta/sprite-board-native.png` は原寸の確認用出力。
- パレットは24基本色に環境用4色を追加した28色。低彩度の床と歩道を分け、商品はカテゴリに合う小さなパッケージで描く。B1は未完了: 夜・増床・多様な設備の魅力、外周の生活感は引き続き制作する。
- 全80商品へ個別の味・用途タグを設定。12タイプの嗜好でカテゴリ内の商品選択にも差が出る。
- 12人×3段階の願いを会計の実績で進める。組み合わせ・待ち時間・本人の予算・時刻・天候・イベント・異なる日数を使う。本人は不足した品を探し、予算付きの願いでは余分に買って予算を超えない。
- 「普通のプリン＋変わり種コーヒー」で「変わり種スイーツ」を達成したことにしない。複合条件は同じ商品で満たす。重複した2個は2種類と数えない。同日の複数会計は複数日と数えない。
- 願いと進捗を住人詳細に表示。好みと商品の特徴をプレイヤーが比較できる。旧保存の完了済み物語は巻き戻さない。
- 36段階の成立例・反例と、実際のレジ到着から会計までを検証。347コア・動線36・UI45画面・Webビルド成功。これは新しい経営バランスと全物語の本編内達成の証拠にはしない。
- 新しい購買規則を入れたため、従来の60ケースとリプレイは旧版の履歴。ベータ版の成立証拠として流用しない。方針比較の再評価を進める。

### 進捗 2: 実プレイと比較方法

- 最新の実画面（Web 1440×900 / 375×812、macOS 1187×768）を確認。人物の選択、整数倍率ズーム、狭い画面の商品特徴・発注操作が動く。原寸人物ボードも目視で確認した。
- 通常発生のQA保存から営業を進め、朝倉みのりがプリンを会計し、次のコーヒーとの組み合わせの願いへ進むことを確認。`screenshots/beta-wish-progress.png`。狭い画面の商品の特徴は `screenshots/beta-products-mobile.png`。
- 固定方針にも同じ増床・雇用・設備投資を認める比較を追加。資金に余裕を残して投資し、鮮度別に決めた固定目標在庫を維持する。単に何もしない相手との比較を「難しい」の証拠にしない。
- 初期seedの固定方針は所持金231,780円、星4、期間終了。利益率18.6%だが審査を満たす繁忙イベントが1種に留まった。需要に合わせる3方針は五つ星。探索的な1seedの証拠であり、全体の難易度は未確定。`beta-probes.json`。
- 比較実行からリプレイの保存を分離。`--record-replays` を付けたときだけ保存する。CIや探索実行で旧版の記録を黙って書き換えない。
