# まちあかりマート 検証記録

2026-09-06 / Godot 4.7.2。仕様自己レビューをコミット61fb596で先に記録し、実装後に以下を検証した。第三者試遊・Steam提出手続きは対象外。

## 自動検証

- コア347項目: カタログ全件、在庫保存則、納品の締切、毎分の期限、搬送・返品・廃棄、価格と会計、実働賃金、経路、シフト、休憩、装飾、星、審査、融資、期限後継続、保存再開。
- UI45画面: 375×812 / 768×1024 / 1024×768 / 1440×900 / 1920×1080で9画面の操作部品の横はみ出しを検査。住人ボタンを更新で作り直さない回帰検証も追加。
- `npm run check`: インポートによるGDScript構文・型検証、コア、UI、1seed×6方針、Webリリースビルド。専用の別lintツールは使わない。
- `npm run build:mac`: macOSリリース出力。
- `npm run balance`: 通常のプレイヤーコマンドによる10seed×6方針、想定外0件。状態への資金注入や星の直接変更は行わない。

| 方針 | 五つ星 | 結末 | 意味 |
| --- | ---: | --- | --- |
| 初期状態を維持 | 0/10 | 資金不足10 | 発注しない店は続かない |
| 一律の自動発注 | 0/10 | 期限10 | 自動発注だけでは終盤条件を満たさない |
| 全品高値 | 0/10 | 資金不足9・期限1 | 値上げは客離れと両立する |
| 定番重視 | 10/10 | 五つ星10 | 需要・在庫・シフト・教育へ投資 |
| 朝食重視 | 10/10 | 五つ星10 | 朝食の棚と価格で運営 |
| スイーツ重視 | 10/10 | 五つ星10 | 菓子の棚と繁忙日の処理能力で運営 |

これは作成した攻略方針の比較結果であり、すべての遊び方の成功・失敗や、人間の体感難易度を保証するものではない。詳細数値は[balance-results.json](balance-results.json)、成功操作は[定番](replay-staples.json)・[朝食](replay-morning.json)・[スイーツ](replay-sweets.json)。再現seedは20260906から73刻みの10個。

初回は高値が強すぎたため、個人の価格感応度を購買に接続。その後の適応30通しの2失敗は行列だった。審査を緩めず、直近実績に応じた勤務外教育で再検証し30成功になった。賃金の精算直前変更、期限検査間隔、搬送在庫の二重注文などの改善は[SPEC_REVIEW.md](SPEC_REVIEW.md)に記録。

## 実画面・操作

macOSのGodotネイティブ画面とCodex内蔵ブラウザのWebGL版を操作した。コアだけのテストを実プレイの代用とはしていない。

- 開店、時間停止/再開・倍速、来店・買い物・補充、品切れ、発注、商品・価格の管理、日次レポートを確認。
- 建設一覧から鉢植えを設置して900円減少、店内で選択、移動、15分の準備表示とモード終了を確認。
- スタッフのシフト一覧と上限エラーを実クリックで確認。通知がダイアログ内に表示される。
- 住人プロフィールの属性・購入履歴を確認。お気に入りを実クリックして解除ボタンへ変わることを確認。
- 設定の文字130%でレイアウトを確認。停止キーをKへ変更しSpaceへ復元。保存してアプリを終了・再起動し、営業日・所持金の一致を確認。
- Webで保存後にリロードし、6日目08:02・46,665円から再開を確認。
- 終盤は通常コマンドの再生から35日目のQA保存を作成。そこから実画面で営業を進め、37日目の五つ星結果と継続を確認。56日すべてを人手操作したという意味ではない。
- 375pxで右側詳細を別画面へ切り替え、操作列が折り返すことを確認。1280×720と1920×1080の店内・経営表示を確認。768・1024・1440幅も寸法検査と実描画確認を併用。
- 昼夜用オリジナルWAVを生成し試聴用音声を出力。CoreAudioの再生開始・ループ・音量系を確認。終了時の残存オブジェクト警告は停止と解放を追加した後に消失。

## 検証の範囲

Web版はWebGL2、デスクトップのマウス/キーボード操作を主対象とする。375pxの表示対応を確認したが、実機スマートフォン全機種の互換性試験はしていない。Windows/Linuxのネイティブ配布は作成していない。

多数のリロードを行った古いブラウザタブが一度終了した。原因は特定できておらず、これを修正済みとは扱わない。新しいタブでは営業6日分の進行、保存再開、複数回の画面変更を継続して確認し、同じ終了は再現しなかった。ネイティブ版では同じ現象は出ていない。基本セーブは1店舗の保存・再開のみ。
