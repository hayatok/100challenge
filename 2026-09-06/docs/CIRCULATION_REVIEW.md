# 空間と行動の修正計画 — Issue #74

Goal: コンビニとして不自然な配置・会計・出入りを修正する。
Context: navigation.gd / simulation.gd / store_view.gd。修正前をブラウザで確認した。
Constraints: 経営の難易度条件を緩めない。素材・配色を維持。保存した店舗のレイアウトは無断で置き換えない。
Done when: 道路から会計・退店までの連続した動作を画面で確認し、経路・列・会計・移設の回帰検証が通る。

## 原因

- 入口Nav.DOOR=(1,8)は境界ではなく店内。外観のOPEN看板も別位置で、移動できる道路がなかった。
- 棚は商品カテゴリを3列に並べる式のみ。壁面売り場・中央棚・レジ待機スペースが設計されていなかった。
- 店員も客も同じNav.accessを使用。行列はIDリストのみで位置を持たず、複数の客が同じマスへ集まった。
- 空経路を到着と見なす処理があり、到着確認が足りない。移設で入退店の状態が買い物へ戻される。
- 描画は経路が空になると補間をやめ、最後の一歩が跳ぶ。奥行きも補間前の位置だった。

## 変更

1. 西側の境界(0,8)に扉を置き、その外を歩道と道路としてナビゲーションと描画で共有。
2. 奥の壁に冷蔵、中央に背中合わせの棚、周辺に日用品、入口近くにレジとホットケース。客の入口通路・列とレジ裏を空ける。
3. レジの正面は客、反対側は店員、客は4つまでの別々の列位置へ。列の先頭が正面に到着し、店員が裏に到着した時だけ会計する。
4. 入店中と退店中の状態を保持。扉を通って道路端へ出た後に訪問を終了する。移設でも入退店の意図を維持。
5. 毎更新の前後位置を全員に記録し、最後の一歩・奥行きも同じ補間位置で描く。道路境界は短いフェード、店内での消失は行わない。
6. 元の初期配置がそのままの保存は、在庫・資金を維持して修正済み配置へ補正。ユーザーが変更した配置は維持し、必要なら移設案内を表示する。複数箇所の修正が必要な旧配置も順に直せる。

## 確認する場面

初期配置、道路からの入店、複数人のレジ列、無人レジ、会計後退店、購入なし退店、勤務切替、補充、移設、増床、旧保存再開。デスクトップと375pxで扉・道路が画面内に分かること。

## 実装後の確認と追加修正

- レジは(2,7)、客側は(1,7)、店員側は(3,7)。列は(1,6)〜(1,4)へ伸びる。入口(0,8)の内側(1,8)は列や設備に使わず、ホットケースは(2,9)へ。入口から店内へ進む横通路を維持する。
- 入退店の道路は店舗西側。道路から横断歩道・歩道・扉を通る。扉以外のガラス面を横切れない。増床でも扉は固定され、退店中の経路は道路端へ更新する。
- 待機列の予約だけで会計を始めない。実際に並んだ人を遠方の予約より前に扱い、棚から列へ向かって歩く時間を「並んで待った時間」に加算しない。
- 勤務交代で店員が離れた場合、会計中の表示を解除し、客は交代待ちになる。無人なのに会計処理だけが進むことはない。
- 商品を選ぶ人のところでは次の人と補充担当が待つ。通過するだけなら空いた別経路を探す。
- 倉庫はスタッフ専用区画。客は入らず、店員は売り場側の倉庫扉から入る。壁・扉・通れる場所を一致させる。
- 全員の前後位置で最後の一歩と描画順を補間する。移動方向で通路の左右を少し分ける。道路端のフェードは人物・影・持ち物にまとめて適用する。保存再開は保存された現在位置から描く。

### 自動検証

`npm run test:circulation` は36項目。通常の発生スケジュールで3営業日進め、87回の入店・87回の退店、4人までの列を確認した。会計条件は売上・原価テストに加えて、客と店員が実際に別側へ到着しているかを検査する。

検証対象: 初期の通路、全3増床段階の入退店、扉以外を横切らない、レジ裏・列・入口の建設禁止、遠隔会計の禁止、売上の二重計上禁止、移設中の退店維持、増床時の出口、旧保存の資金・ロット維持、カスタム配置の段階的な修正、1回の更新で隣のマスまでしか動かない、店内で消えない、客同士が同じ待機位置を占有しない、同じ棚の利用順、スタッフ専用区画に客が入らない。

コア347項目とUI45画面の検証も併用する。これらはゲーム全体の完成品質を認定するものではなく、今回の空間・行動修正の検証である。

経営比較の操作例は、新レイアウトに合わせて追加レジを(4,8)、追加棚を(9,2)へ変更。金額・需要・五つ星の審査条件は緩めていない。最終10seed×6方針の比較結果を `balance-results.json` に記録する。分割実行は `balance --seed-index 0 --seed-count 4` の形式で、出力先を分けて衝突を防ぐ。

- Web: 1440×900と375×812で店舗・扉・歩道を確認。狭い幅では外周の一部が画面外になるが、入口と店内は確認でき、ドラッグと拡大縮小が使える。
- ネイティブ: 1187×768の実画面で3人の列・店員の位置・会計後の退店を確認。最終macOS配布用アプリの起動も確認。

- 店内人数は道路を歩く人を含めない。

### 残る範囲

これはアルファ版の空間・行動修正。全体の完成品質を認定するものではない。変更済みの旧店舗は自動で並べ替えず、必要なら案内に従って移設する。人物同士の歩行は通路内の左右の描画オフセットと停止中の人を避ける経路で表現し、連続的な群集物理は実装していない。
