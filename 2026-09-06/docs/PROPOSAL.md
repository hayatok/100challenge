# まちあかりマート — ゲーム企画書

作成日: 2026-09-06（Asia/Tokyo） / 第4稿 / Steam作品に並ぶゲーム体験の品質を目標とする。タイトル・数値・制作範囲の詳細は提案

> あの人が、今日も来た。小さなコンビニから、街の暮らしが見えてくる。

## 1. 企画の要点

**斜め見下ろしのドット絵で描かれるコンビニを経営し、名前と生活を持つ住人たちの「いつもの店」に育てる、1人用の箱庭経営シミュレーション。**

朝は通勤客がコーヒーを取り、昼は弁当の棚が空になり、夕方は学生が新商品を探す。夜になると、昼には見なかった顔が入ってくる。プレイヤーはその様子を観察し、商品構成、棚の配置、仕入れ、価格、スタッフの働き方を変える。

目指す体験は「店の売上が増えた」に加えて、「朝倉さんが買えなかったプリンを、今日は買って帰った」と覚えていたくなること。経営上の成功と、一人ひとりへの愛着を結び付ける。

**標準難易度から、客層を読み、失敗の原因を調べ、経営を組み直す攻略を必要とする。** 初見で順番に設備を買うだけでは最高評価へ届かない。限られた資金・面積・人員でどこに強みを作るかを考え、需要の変化に対応して勝ち筋を育てる。

作風は、経営の手応えと、思わず笑うドット絵の生活劇を両立する。やたら長い商品名、妙なこだわりを持つ常連、売り場で起きる小さな珍事件を、実際の購買や経営結果に結び付ける。

**完成目標は、Steamで販売されているゲームに並ぶ、見た目・音・操作感・攻略性・遊びの充実度を持つ作品。** Steamという表現はゲーム自体のクオリティの譬えであり、販売先や公開手続きを指定するものではない。導入から攻略・結末まで一本の作品として作り込む。100日チャレンジの日付フォルダは制作の整理に使い、制作日数を品質の上限にしない。

## 2. 参考作品と、本作の中心

カイロソフト『開店コンビニ日記』の公式紹介では、棚と品揃えの編集、客の希望を満たすことによる常連化、スタッフの教育とシフト、店舗拡大などが紹介されている。本企画では、この「小さな工夫が成長と次の目標につながる」構造を参考にする。[公式ゲーム紹介](https://kairosoft.net/game/appli/convenience.html)

以下は本作独自の提案であり、参考作品の内部仕様を説明するものではない。公式ページの説明文を参考とし、実機プレイによる挙動検証は行っていない。

| 参考にする体験 | 本作での設計 |
| --- | --- |
| 店舗が少しずつ育つ満足感 | 増床、新しい売り場、混雑の変化を店内で見せる |
| 小さな人物を眺める楽しさ | 個人の顔・名前・来店時間・購入履歴が次回も続く |
| 品揃えを工夫する楽しさ | 嗜好、目的、予算、在庫、導線で購入結果が変わる |
| 次の解放を待つ楽しさ | 常連の要望、地区評価、仕入れ先との関係が商品を解放する |

本作の主役は、**店の変化に反応する街の住人たち**。まず一店舗を深く遊べるようにし、チェーン展開は将来構想とする。

### 既存「ぼんやりマート24」から深める部分

現行のREADME、顧客型、シミュレーション、描画、テストと実画面を確認した。既存作には5種類の客層、6商品、時間帯別の需要、自動発注・自動増築がある。人物情報は来店単位の構造で、名前や継続した個人の買い物履歴は持たない。

| 要素 | 新作で目指す内容 |
| --- | --- |
| 経営への関与 | 棚・品揃え・発注・価格・シフトを自分で設計する |
| お客さん | 来店をまたいで同じ人物として存在し、関係が育つ |
| 店内 | 配置を変えられる斜め見下ろし空間。通路やレジ列にも意味がある |
| 商品 | 個別の嗜好、賞味期限、棚容量、納品時間が結び付く |
| 成長 | 自分で選ぶ投資と、複数の経営スタイルによる地区攻略 |

固定seedによる再現性、描画とルールの分離、日次レポートは設計上の参考にする。既存の移動処理や描画をそのまま新作の土台にするかは、実装時に適合性を検証する。

## 3. ゲームを支える4本柱

1. **住人が暮らしている。** 来店のたびに別人を生成せず、同じ人が生活リズムを持って通う。
2. **配置と品揃えに答えが返る。** 棚を移すと歩く経路が変わり、商品を変えると買う人が変わる。
3. **経営には選択と代償がある。** 品切れを防ぐほど廃棄の危険が増え、スタッフを増やすほど人件費がかかる。
4. **眺めて事情が分かり、笑える。** 棚の前の大げさな迷い、レジ列、買い物袋、短いツッコミが数字と同じ結果を伝える。

「本格的」の基準は、機能数よりもこの4つがつながっていること。同じ客数でも、プレイヤーの判断で異なる店と結果が生まれる。

## 4. 基本の遊びと時間

**観察 → 仮説 → 店を変える → 営業 → 結果を読む → 再投資**を繰り返す。

| 周期 | プレイヤーがすること | 返ってくるもの |
| --- | --- | --- |
| 数十秒 | 客や棚を選ぶ、列を見る | 買えた理由・買わなかった理由 |
| 1営業日 | 発注数、価格、担当を調整する | 売上、粗利、欠品、廃棄、満足度 |
| 数日 | 売り場を組み替える、人を雇う | リピート率、処理能力、店の得意分野 |
| 数週間 | 増床や新設備を選ぶ | 新しい客、商品、住人の小さな物語 |

### 時間のルール案

- 店は24時間営業。1ゲーム日を実時間約6分とする仮設定。1時間は約15秒。
- 停止・1倍・2倍・4倍を用意。速くしても、移動・在庫・会計は同じルールで進める。
- 内装編集は時間を止め、まとめて確定できる。確定前なら費用なしで取り消せる。
- 毎朝6時に前日6時〜当日6時の営業レポートを発行。営業は継続し、初回説明や重大な資金不足のみ自動停止する。
- 発注やシフトは定常設定を保存できる。毎日同じ操作を要求しない。
- 別タブ移動・アプリ休止時は停止。初期版ではオフライン時間の経営進行を行わない。
- 1週間は7日。完成版は1季節14日、1年56日というゲーム用カレンダーを提案。曜日と季節の両方を需要に使う。

## 5. お客さんの設計

### 永続する人物と、その日の事情を分ける

全員に名前・性別・嗜好を持たせる。人口は初期版40人、完成版120人を基準とし、地域の発展に合わせて会える住人を増やす。全員が毎日来るわけではない。

| 分類 | パラメータ例 | ゲームでの役割 |
| --- | --- | --- |
| 個人情報 | 固有ID、名前、性別、年齢層、職業、外見 | 同じ人物として認識し、図鑑で追える |
| 生活 | 生活拠点、通る時間帯、平日・休日の習慣 | いつ、どの程度の頻度で来店候補になるか |
| 嗜好 | 甘い・辛い・温かい・冷たい・満腹・健康・新商品などの重み | 商品の魅力が人物ごとに変わる |
| 買い方 | 基本予算、価格への敏感さ、待てる時間、ついで買い傾向 | 値上げ、行列、棚の並びへの反応 |
| 関係 | 来店回数、満足の記憶、常連度、お気に入り商品 | 次回の来店意欲と個人イベント |
| 当日の状態 | 空腹、喉の渇き、急ぎ度、所持予算、今回の目的 | 同じ人物でも日によって買い方が変わる |
| 訪問記録 | 購入品、金額、待ち時間、不満の理由 | 店内表示と分析の根拠 |

性別は「女性・男性・ノンバイナリー・未設定」などの人物設定として保持する。購買能力や嗜好を性別だけで決めない。職業は来店時間の初期傾向を作るが、個人の好みと当日の状態を別に持たせる。

名前や外見は初回生成時に固定。服装や髪型の色違いだけでなく、帽子、眼鏡、鞄、体格、姿勢で見分けられるようにする。

これらの事情は解説文だけにせず、来店時間・選択商品・予算・反応の変化として表現する。

### 行動の流れ

街を通る → 入店を判断 → 目的の売り場へ移動 → 商品を比較 → 必要なら代替品・ついで買い → レジに並ぶ → 会計 → 退店 → 記憶を更新。

購入判断は、概念上は次の要素で決まる。

**購入の魅力 = 今回の必要性 + 個人の嗜好との一致 + 品質・鮮度 + 売り場での発見 − 価格の負担 − 移動と待ち時間の負担**

まず「在庫がある・取りに行ける・予算内」といった条件を満たす候補だけを比較する。魅力が低ければ買わない。少量のseed付き乱数で揺らぎを付け、好みが行動に現れる強さを保つ。内部係数は試作で調整する。

品切れの際は、代わりを買う、別の棚を見る、諦めるのいずれか。待ち時間に耐えられなければ列を抜ける。実際に到達した棚から買い、会計が完了して初めて売上にする。

### 人物を知る楽しさ

- 初来店から名前・人物設定は閲覧できる。好みの詳細と生活の事情は観察やイベントで少しずつ埋まる。
- 購買から推測した情報には「甘いものが好きそう」など推測表示を付け、確定した本人の要望と分ける。
- お客さんを選ぶと「目的：朝食」「気になる商品：鮭おにぎり」「今の事情：急いでいる」と直近の理由が見える。
- お気に入り登録した住人は来店通知・追跡表示を選べる。全員の名前を常時表示して店内を覆わない。
- 常連度は初来店 → 顔なじみ → 常連 → 店のファン。満足した再訪を重ねて上がり、欠品や長い行列が続くと下がる。
- ファンの紹介で新しい住人が来る。自動的な売上ボーナスだけでなく、人のつながりを店内に増やす。

完成版の120人のうち12人には、3段階程度の手作りエピソードを用意する。他の住人にも共通の行動・関係システムを適用し、名前だけの背景役にしない。

### 攻略のヒントになる、妙なこだわり

既存の住人設定に、行動として見えるネタを加える。個人エピソード12本の中で扱い、特別な住人を際限なく増やさない。

| 住人 | ネタと画面の動き | 攻略につながる性質 |
| --- | --- | --- |
| 朝倉 みのり | プリンを前に「今日は見るだけ」。いつものプリンと新味を両方かごへ | 新商品への関心とついで買いが強い。ただし朝は行列に弱く、予算を超えれば諦める |
| 田辺 まこと | 激辛麺の棚で「前回は引き分け」。買えた日は小さく拳を握る | 辛さへの嗜好が強いが財布は厳しい。高価格の新商品だけでは常連化しない |
| 松永 文雄 | 新聞より先に新作パンを確認し「見回りです」 | 決まった朝の定番と、ときどき買う新商品を両立すると満足が上がる |
| 久保 つむぎ | 締切前は飲料を並べて「本日の会議メンバー」 | 締切イベント中は夜のまとめ買い。予告後の補充と在庫配分で対応する |

吹き出しだけをランダムに出さず、実際に商品を比較・購入したときの状態から選ぶ。同じオチの頻発は抑え、再訪やエピソード進行で少しずつ変化させる。

## 6. 商品・仕入れ・売り場

### 商品の情報

各商品にカテゴリ、価格、原価、味・用途タグ、鮮度、賞味期限、保管条件、棚容量、納品単位、解放条件を持たせる。初期版24商品、完成版80商品程度を目標とする。

カテゴリ案は、おにぎり・弁当、パン、飲料、お菓子、スイーツ、即席食品、ホットスナック、日用品、雑誌。初期版はこのうち6カテゴリに絞る。

### プレイヤーの選択

| 操作 | 得られるもの | 代償・注意点 |
| --- | --- | --- |
| 売れる商品を多く発注 | 欠品を減らす | 売れ残り、保管場所、仕入れ資金 |
| 高品質商品を増やす | 好みの合う客の満足と客単価 | 安い商品を求める客との不一致 |
| 値引きする | 売り切りやすさ | 1個あたりの利益が減る |
| 同じ棚を増やす | 陳列容量と取りやすさ | 別の商品を置く場所が減る |
| 関連商品を近くに置く | 実際の通り道でついで買いが起きる | 人気売り場への集中と混雑 |
| レジを増やす | 行列が短くなる | 設備費、面積、担当スタッフ |

価格は初期版では「安め・標準・高め」の3段階と、期限前の値引きを提案。全商品へ細かな数値入力を要求せず、需要と粗利の違いが読めるようにする。

### 発注から販売まで

発注締切 → 決まった便で納品 → バックヤード保管 → 店員が棚へ補充 → 客が取る → 会計。

- 初期案は朝・午後の1日2便。発注数と到着時刻を見せる。
- 最初は手動発注で因果を学び、その後は商品別の目標在庫と上限予算で自動発注できる。
- 発注は棚・倉庫・発注済み数量を考慮し、発注途中の在庫を重複注文しない。
- 自動発注も、納品時間、倉庫容量、所持金、運転資金の制約を受ける。
- 古いロットから補充・販売する。棚に何個あるかと、店全体に何個あるかを分ける。
- 会計前の商品は買い物かごの在庫として保持。客が購入をやめた場合の返品・廃棄を一貫したルールで処理し、消失や二重販売を防ぐ。

隣接効果は「おにぎりの近くでお茶を見つける」など、移動と発見で説明できるものを中心にする。

### ネタ商品にも仕入れる理由と弱点を持たせる

初期版24商品に少なくとも4種、本編80商品には12種程度のネタ商品を含める。通常商品と同じ在庫・価格・嗜好ルールで扱い、万能な高利益商品にはしない。

| 商品案 | 見た目・ひと言 | 経営上の個性 |
| --- | --- | --- |
| 会議が長引くほど長いパン | 袋からはみ出す細長いパン。「議題はまだあります」 | 満腹需要に強いが陳列枠を2つ使う。棚面積あたりの利益を考える |
| ほぼ具おにぎり | 米より具が目立つ、崩れそうな断面 | 満足度は高いが原価が高く、値引きすると粗利が薄い |
| 明日から本気プリン | 蓋に小さく「本日中にお召し上がりください」 | 甘党のまとめ買いを狙えるが期限が短い。欲張った発注が廃棄になる |
| 静かなる激辛焼きそば | 落ち着いた包装に小さな火山印 | 辛党には強く、他の客には売れにくい。嗜好の見極めが必要 |

商品ごとの専用ミニゲームは作らず、陳列枠、原価、期限、嗜好など既存のパラメータで差を表現する。

## 7. 店舗レイアウトとスタッフ

### 店舗

初期店舗は12×10マス程度の敷地案。売り場、入口、レジ、バックヤードを含み、2段階の増床で最大20×16マス程度に広げる。

- 棚、冷蔵ケース、レジ、ホットスナック機、ゴミ箱などを設置・移動する。
- 棚は向きと商品を取れる面を持つ。棚の背中を通路に向けると使えないことが分かる。
- 建設モードでは床グリッド、占有範囲、費用、通行できる経路を表示する。
- 入口から利用面・レジ・出口までの経路が消える配置は確定できない。既に店内にいる客とスタッフの経路も検証する。
- 人同士は短い待機と譲り合いで処理する。通路の混雑は待ち時間を増やすが、永久に詰まらない。
- 増床では面積と経費が増える。資金と評判があっても、自動的には実行しない。

### スタッフ

名前・外見・レジ速度・補充速度・接客・体力・希望時間帯・賃金を持つスタッフを雇う。初期版では店長1人と雇用候補4人。店長が働くことで、雇用できない序盤も営業を成立させる。

朝・昼・夕・深夜の時間帯ごとに配置と優先業務を設定する。通常はレジ・補充を自動で切り替え、完成版で清掃・休憩・教育を加える。

「レジが速いが補充は遅い」「接客は得意だが長時間勤務に弱い」など、単純な上位互換にならない個性を用意する。疲労には事前表示と自動休憩を設け、1人ずつ指示し続ける作業を避ける。

店長にも稼働時間と処理能力の上限を設ける。店長1人の24時間労働で人件費を回避できないよう、初期版では時間帯ごとの担当可能枠、完成版では休憩・疲労で制約する。手が足りない時間を受け入れるか、雇用費を払うかが序盤の判断になる。

スタッフの個性も動きで見せる。補充上手は箱をきれいに揃えて満足げに頷き、レジ上手は会計後に短い決めポーズを取る。演出は業務完了後に重ね、見た目のために処理能力や待ち時間をこっそり変えない。

## 8. 経営と成長

### 数字の意味を揃える

| 指標 | 定義 |
| --- | --- |
| 売上 | 会計が完了した商品の販売額 |
| 粗利 | 売上 − 販売済み商品の原価 |
| 営業利益 | 粗利 − 廃棄した商品の原価 − 人件費・家賃・電気代など |
| 現金収支 | 入出金の差。仕入れ・設備投資を含み、営業利益とは分ける |
| 購買率 | 来店した人のうち会計した人の割合 |
| 欠品による機会損失 | 在庫があれば買う条件を満たしていた需要の推定。売上には加算しない |
| 常連の再訪率 | 定めた観測期間で再来店した常連の割合 |

仕入れた日に全額を利益から引き、さらに販売原価でも引く二重計上をしない。初期版は設備投資を現金収支に分け、減価償却・税務計算は扱わない。

ゲーム用の序盤例として、日商60,000円、販売原価36,000円、廃棄1,500円、固定費等15,000円なら営業利益は7,500円。別途30,000円を仕入れた日の現金増減は、設備投資等がなければ15,000円となる。これらは実店舗の収益モデルではなく、調整用の仮数値。

### 目標と経営スタイル

最終目標案は「1年以内に街の生活を支える五つ星店になる」。利益の継続、常連の定着、買い物の成功率を組み合わせて評価し、単一商品の大量販売だけでは最高評価にならない。

星は経過日数や累計売上だけでは上がらない。段階ごとに複数の課題を同時に満たし、最後は繁忙日を含む連続した営業期間で実力を示す。

| 方針 | 店の姿 | 工夫するところ |
| --- | --- | --- |
| 朝の特急店 | 朝食とコーヒー、短い動線 | 混雑時間の補充とレジ |
| 帰り道のごほうび店 | スイーツと新商品に強い | 好みの把握、鮮度、客単価 |
| くらしの安心店 | 定番商品と日用品が揃う | 品切れ防止、幅広い需要 |

固定クラスを選ばせるのではなく、プレイした結果として得意分野が生まれる。どの方針でも主要目標を達成できるバランスを目指す。

### 標準難易度の設計

攻略が必要な難易度を本編の標準にする。導入で操作を覚えた後は、初期設定を放置したまま、あるいは最も高い設備を順に買うだけではクリアできない設計を目指す。

| 局面 | 攻略課題 | 陥りやすい判断 | 改善に使える情報 |
| --- | --- | --- | --- |
| 序盤・黒字化 | 限られた棚と予算を、主な客の需要に合わせる | とりあえず全商品を並べ、在庫と資金が分散する | 時間帯別の購買、買わなかった理由、棚面積あたりの粗利 |
| 中盤・繁忙対応 | レジ、補充、通路のうち詰まっている場所を解消する | レジだけ増やして補充要員が足りなくなる | 業務別の稼働、待ち時間、倉庫と棚の在庫差 |
| 中盤・投資判断 | 増床後の経費と仕入れ資金を残し、需要を育てる | 買える瞬間に増床し、翌便の仕入れができなくなる | 投資後の残金、予定支出、固定費、需要の実績 |
| 後半・需要変化 | 季節・曜日・予告イベントで品揃えと人員を組み替える | 成功した夏の構成を秋も維持する | 天気・行事予告、客の目的の変化、週次比較 |
| 最終・総合審査 | 利益、常連、繁忙時の購買成功、廃棄抑制を同時達成する | 値引き・過剰仕入れ・大量雇用のどれか一つで押し切る | 審査項目別の実績と残り期間 |

序盤の資金は、初期設備・最初の仕入れに加え数日分の試行錯誤を支えられる量を仮基準とする。全設備を同時に買える余裕は与えない。需要には上限と価格反応を持たせ、人気商品を増やし続けるだけの成長を防ぐ。イベントの変化はカレンダーと住人の事情に従い、プレイヤーの成功に合わせて隠れて費用を上げる調整はしない。

### クリア条件のたたき台

本編の五つ星審査は、四つ星到達後にプレイヤーが開始する**14日間の連続審査**とする。56日目までに成功するには遅くとも43日目の営業開始時に着手する。開始前に条件・日程・繁忙イベントを全て確認できる。失敗後も日数が残れば再受験できるが、失敗した日の数値だけを除いて合格にはできない。

仮の合格条件は以下の全達成。数値はまだバランス未検証で、中核試作後に調整する。

- 審査期間の営業利益率が5%以上で、期末の現金が次の納品・返済・3日分の予定固定費を賄える。
- 期間中に来店した常連のうち、70%以上が別の日にも来店し購入する。対象となる常連は20人以上必要。
- 予告された性質の異なる繁忙日2回で、それぞれ来店客の購買率80%以上を達成する。
- 廃棄原価を「販売原価＋廃棄原価」の8%以下に抑え、予定支払いの延滞がない。

最低来客数などの成立条件も各審査に明示する。入口封鎖や一部の客の排除、営業規模を極端に縮める方法で分母を減らして通過できないよう検証する。必要な住人・商品・設備とイベントは期限に間に合う解放経路を保証し、希少客の抽選待ちを必須条件にしない。

1〜4つ星では、この審査に必要な技能を段階的に問う。1つ星は3日連続黒字、2つ星は対象客層の定着、3つ星は繁忙日の処理、4つ星は需要変化後の収益回復を主課題とする案。初期プレイ版は2つ星までを小さな攻略目標にし、本編と同じ在庫・購買・収支ルールを使う。

### 歯応えと公平さ

- 一時停止と情報閲覧は常に使える。素早いクリック操作をクリア条件にしない。
- 原因と実績は見せるが、最適な棚配置や発注数の正解は自動で提示しない。
- 自動発注・担当切替はプレイヤーの方針を実行する。季節への対応や審査条件を満たすための最適化は代行しない。
- 営業中の配置変更は一時停止で計画できるが、確定後は移設作業中の設備を一定時間使えなくする。客ごとに棚を瞬時に動かす抜け道を防ぐ。作業時間は確定前に表示する。
- 同じイベントに対し、品揃えを絞る、補充を厚くする、導線を短くするなど複数の突破方法を成立させる。
- 長時間待つだけの資金稼ぎ、理不尽な隠し条件、運の良い再読込の繰り返しを必須にしない。

### 失敗と立て直し

- 赤字、欠品、廃棄、行列を主要な課題とする。導入中は取り返しのつく規模で学び、その後は仕入れ過多や投資ミスで倒産する可能性もある。
- 所持金に対する予定支出と、何日分の運転資金があるかを表示する。
- 必要な支払いができない場合は時間を止め、仕入れ縮小・設備売却・シフト変更を選べる。
- 標準モードでは一度だけ、返済可能性など明示条件を満たす場合に限り救済融資を利用できる。利息・返済期限が付き、根本原因を直さなければ再び資金不足になる。自動給付や無制限の救済は行わない。
- 再建不能なら結果と原因を表示し、直前の節目からの再挑戦、最初からの再開を選べる。
- クリア後は継続経営できる。サンドボックスなどの別モードは完成版の後に判断する。
- 56日目に五つ星未達なら期限内攻略は失敗として記録する。続ける場合は「期限後の練習」と表示し、期限内クリアとは区別する。

## 9. 天候・街・イベント

初期版は住宅街の1地区で「晴れ・雨・暑い日」と曜日差を扱う。完成版で四季、学校や職場の予定、地域の催しを増やす。

| 出来事 | 店内で起きること | プレイヤーが備えられること |
| --- | --- | --- |
| 雨予報 | 傘、温かい飲み物を求める客が来る | 前日の発注と入口付近の売り場 |
| 暑い日 | 飲料の棚が減るのが早い | 冷蔵棚の容量と補充担当 |
| 地域の運動会 | 昼前に飲料・軽食需要が増える | 日程を見て在庫とシフトを調整 |
| 近所の新しい職場 | 朝昼に新しい住人が通る | 新しい時間帯への対応 |
| 常連の小さな転機 | 来店時刻や買う物が変わる | 観察して新しい要望に応える |

基本イベントは天気予報やカレンダーで予告する。予告なしの出来事は小さな変化に留め、乱数だけで急に破綻する展開を避ける。

### コミカルな繁忙イベント

| イベント案 | 画面で起きるネタ | 攻略課題 |
| --- | --- | --- |
| 商店街・激辛がまん大会 | 参加者が強気のポーズで入店。買い物かごには麺と大量の飲み物 | 麺だけでなく飲料の在庫・冷蔵棚・補充能力を用意する |
| 地元ヒーロー撮影日 | 衣装姿の住人が普通に弁当を買い「世界より先に昼休み」 | 予告された短い休憩時間に会計を集中処理する |
| プリン総選挙 | 住人が推しの味を買い、袋を掲げる。好みが割れて棚の減り方が違う | 前日の嗜好・購入実績を見て味ごとの発注を配分する |

イベントの衣装や演出にも通常の住人IDを使い、特別客も在庫・予算・行列のルールに従う。参加予定人数と需要カテゴリは事前に分かり、売上のために準備する価値と、過剰発注の危険がある。初期版からこのうち1件を含める。

## 10. アートディレクション

### 画面の主役は店内

画面中央に、斜めから見下ろす小さなコンビニを大きく置く。正面側の壁と屋根を外し、棚の前面、通路、レジ列、入口の外まで見える構図にする。カメラ方向は固定し、パンと段階ズームを用意する。

夕方には窓の外が橙色になり、夜は暗い道に店の明かりが残る。外周の歩道を人が通り、納品時には小さな台車が入る。「店が街の中にある」と感じる余白を作る。

### ドット絵の制作基準案

- 2:1の菱形タイルを基本とする斜め見下ろし表現。基準タイル64×32px、人物32×48pxを仮置きし、店内1画面で読みやすさを確かめて確定する。
- 人物は低頭身。歩行4方向×3フレームを基本とし、立ち止まり・商品選び・会計・喜びの動作を加える。
- 棚、冷蔵庫、床、人物のピクセル密度・光源・輪郭の濃さを揃える。大きい画像を粗く縮小しただけの見た目にしない。
- 足元を基準に奥行き順を決め、棚の後ろを歩く人が自然に隠れる。選択人物は輪郭表示などで見失わない。
- 拡大時はぼかさず、輪郭を鮮明に保つ。ドットの密度が異なる素材を混ぜない。
- 色の役割はアイボリーの床、青緑の店色、珊瑚色のアクセント、濃紺の輪郭、琥珀色の明かり。素材内の陰影色は専用パレットとして揃える。
- 表情は顔だけに頼らず、身体の向き、短い停止、買い物袋、商品アイコンでも見せる。
- 看板や短いラベルはドット文字を検討し、日本語の説明・数値・メニューは読みやすいフォントを優先する。

共通の `DAILY_APP_STYLE.md` に対して、今回の明示指定であるドット絵を優先する。ポスター風の傾きや巨大見出しは抑え、明瞭な輪郭、フラットな色面、操作に結び付く短い演出をゲーム内の表現として引き継ぐ。

### 見ていて楽しい瞬間

- 最後のプリンを買えた人が、袋を少し持ち上げて喜ぶ。
- 長すぎるパンが買い物袋から突き出し、人物のシルエットだけで何を買ったか分かる。
- 激辛好きの常連が棚の前で腕組みし、目的の商品を見つけると小さくガッツポーズする。
- ヒーロー衣装の住人がレジでお弁当を温めてもらい、真剣な顔で待つ。
- 新商品を迷っている常連が、いつもの商品と両方をかごに入れる。
- レジを増やすと列が分かれ、時計を気にしていた客が買って帰る。
- 納品された箱がバックヤードから棚へ運ばれ、空いていた棚が埋まる。
- 雨の日は傘をたたんで入店し、夜はドアが開くたびに明るい店内が見える。

吹き出しや効果音は同時発生数を抑える。BGM・環境音・操作音を個別に調整でき、倍速でも音を連打しない。入店チャイムはオリジナルを用意する。

### 笑いのトーン

日常のこだわりと小さな大げささを軸にする。商品のシルエット、客のポーズ、実績に基づく短い店長コメントで笑わせる。住人の性別・年齢・外見を笑いの理由にせず、行動や状況にオチを置く。

例: 廃棄が多かった日は「本日の常連：廃棄箱」と一言添え、その直下に廃棄商品・数量・原価を正確に出す。エラーや倒産の説明では必要な情報を先に置き、再建操作を冗談で曖昧にしない。

### 最初に作るアート確認セット

1. 昼の店舗を斜めに見下ろした、UI込みの完成イメージ1枚。
2. 同じ店舗の夜景1枚。
3. 個性が分かる住人8人の並びと、1人分の歩行見本。妙なこだわりが伝わるリアクションも含める。
4. 棚・冷蔵庫・レジの同縮尺セット。長いパンなど、棚と人物に持たせたネタ商品も確認する。

本実装に入る前に、このセットで構図・密度・かわいさ・文字の読みやすさをレビューする。人物名や棚の状態は動的に表示し、背景画像へ焼き込まない。アート生成・購入自体は今回の作業に含まない。

## 11. 画面と操作

| 場所 | 内容 |
| --- | --- |
| 上の細い帯 | 日付・時刻、天気、現金、停止と速度 |
| 中央の約70〜80% | 斜め見下ろしの店舗。客と棚を直接選べる |
| 下の操作列 | 建設・商品・スタッフ・住人・経営 |
| 右の詳細欄 | 選択した客や棚の情報。未選択時は直近の課題を少量表示 |
| 必要なときだけ開く画面 | 発注一覧、シフト、住人図鑑、日次レポート |

通常画面では店舗の動きが一目で分かることを優先し、統計を常時並べない。客を選ぶ操作と棚を配置する操作はモードで分離する。

### 日次レポート

売上・営業利益・現金増減を分け、その下に「起きたこと」と「原因」を3件程度表示する。

例: 「昼に弁当が8回買えなかった」「主因は棚在庫切れ。倉庫には6個残っていた」。プレイヤーは発注を増やすべきか、補充担当を増やすべきかを判断できる。レポートは実際の行動記録から作る。

### 画面幅と状態

- PC画面は1280×720、1920×1080、2560×1440を主要確認解像度とし、画面倍率とUI拡大時の読みやすさを確認する。以下の375〜1440pxのレスポンシブ案はWebで動かす場合に適用する。
- 1440px・1024px: 店内と右の詳細欄。768px: 詳細を引き出しにまとめる。
- 375px: 店内をパン・ズームできる領域にし、詳細は下から開く。PC画面全体を縮小して文字を潰さない。
- 設置はクリック選択→設置先→確定を基本にし、ドラッグだけに依存しない。
- キーボードで停止、取消、メニュー移動を行える。選択の輪郭、フォーカス、文字による状態説明を付ける。
- 読込中は進捗を表示。セーブなしは新規開始。資金不足・通路遮断には理由を表示。
- 保存成功は短く通知し、保存できなかった場合はその旨を表示する。
- 演出を減らす設定では跳ね・点滅を抑え、歩行位置と状態変化を読み取れる表示を残す。

## 12. 最初の30分

経営の全機能を最初から開かず、プレイヤーが見た出来事に合わせて解放する。時刻はプレイテスト用の目安。

| 実時間の目安 | 体験 | 覚えること |
| --- | --- | --- |
| 0〜3分 | 小さな店を受け取り、最初の客が商品を買う | 観察・選択・停止 |
| 3〜6分 | 朝倉さんが欲しかった商品を見つけられない | 人には目的と好みがある |
| 6〜10分 | 売り場を1つ変え、次の納品に間に合わせる | 商品・発注・棚の関係 |
| 10〜15分 | 同じ人が再来店し、今回は買って帰る | 工夫の結果と個人への愛着 |
| 15〜20分 | 昼の行列に補充とレジの競合が起きる | 担当とシフトの意味 |
| 20〜25分 | 仕入れすぎた商品の値引きを選ぶ | 売上と利益、廃棄の違い |
| 25〜30分 | 最初の常連と新しい設備候補ができる | 次に育てたい店を選ぶ |

初回導線では対象住人の再訪を保証し、待ちぼうけを防ぐ。購入成功はプレイヤーが品揃え・在庫・待ち時間を改善した場合に限る。直していなければ再び買えない理由を示す。通常プレイに移った後は生活リズムと満足度による来店判断に戻す。

最初の30分は操作習得の目安で、到達や成功の保証ではない。後半には「補充を増やすかレジを厚くするか」の選択を置き、次の営業結果で検証する。最初の10分からネタ商品と常連のリアクションを少なくとも1つ見せ、歯応えとコミカルさの両方を導入する。

## 13. 制作範囲と順序

本格版の構想を保ちつつ、最初の完成単位を「少ない商品でも、住人・売り場・経営がつながる一店舗」に置く。

Bで経営の面白さを検証した後、Cの一部を使い、**15〜20分の範囲でアート・音・UI・攻略・コミカルな演出を目標品質まで揃えた試作**を完成させる。その品質を基準に本編へ広げ、序盤から終盤まで同じ密度で仕上げる。

| 段階 | 内容 | 完了条件 |
| --- | --- | --- |
| A: アート・体験確認 | 店舗の昼夜、住人、設備、ネタ商品、UIの静止イメージ | 斜め見下ろしの方向と、画面から伝わるコミカルさが定まる |
| B: 中核試作 | 1店舗、住人12人、商品8種（ネタ商品1種以上）、レジ1台、補充、配置、1日の収支 | 誤った配分で問題が起き、観察と変更で改善できる。漫然とした発注で黒字が保証されない |
| C: 初期プレイ版 | 住人40人、商品24種（ネタ商品4種以上）、設備8種、雇用候補4人、天候3種、増床1回、常連エピソード3本、コミカルな繁忙イベント1件 | 2つ星まで60〜90分を仮目安に攻略できる。このうち15〜20分を目標品質まで仕上げ、実際の操作とプレイ内容から体験を確認する |
| D: 本編内容完成 | 住人120人、商品80種（ネタ商品12種程度）、設備20種、スタッフ候補12人、四季、増床2回、人物エピソード12本 | 1周4〜6時間を仮目安に、五つ星審査・期限切れ・再挑戦・継続経営が成立する。全編の内容と難易度を通して検証する |
| E: 全編の仕上げ | 全編のアート・音・操作感・演出・難易度・説明を調整 | 第16章のゲーム体験の品質基準を満たす。序盤だけでなく中盤・終盤も作り込まれている |

人物数・商品数は制作予算を見積もるための目安。B段階で面白さが出なければ、データ量を増やす前に行動と経営判断を調整する。完成日や「今日中に全部作れる」という見積もりは、この段階では置かない。

アート制作、実装、音、演出、難易度調整を別々に見積もり、Cの制作実績から残りの工数と素材制作量を算出する。D以降は新機能の追加を原則止め、問題の修正と全編の仕上げに集中する。品質未達のときは制作日程・内容量を見直し、仮素材や未検証箇所を完成扱いにしない。

### 初期版から必須

名前が継続する顧客、嗜好による購買差、経路を持つ移動、棚編集、在庫と補充、仕入れ、会計、レジ列、スタッフ担当、常連化、日次レポート、時間停止、セーブ。加えて、経営判断が必要な段階目標、失敗と再建、実際の購買に結び付くネタ商品・リアクションを必須とする。

### 本編完成後に検討するもの

複数店舗同時経営、地区選択、競合店、仕入れ先交渉、自社商品開発、宅配・ATM等のサービス。これらを初期版の前提にしない。

オンライン対戦、自由会話AI、現実の商品データとの連携は現時点の企画範囲外。住人の会話は状態に合った短文と手作りエピソードで成立させる。

## 14. 実装に向けた設計条件

技術選定は企画採用後に行う。既存リポジトリにはReact/Canvas製の経営ゲームとGodot製の2Dゲームがある。Godot 2Dを第一候補として、店内の描画、文字の可読性、ドット表示、入力とゲーム進行を小さな試作で検証する。Web・ローカルアプリの選択はプレイ体験と制作環境から判断する。現段階で新しい依存関係は追加しない。

- シミュレーション、描画、入力、商品・住人データを分離する。
- 永続する住人IDと、一回の来店IDを分ける。
- 固定刻みの時間更新とseedを使い、同じ入力列で結果を再現する。
- 歩行経路と店内描画を同じ配置データから作り、見た目だけ歩く客を作らない。
- 日付だけでなく、乱数状態、住人、在庫ロット、発注、シフト、レジ待ち、個人イベントを保存する。
- 一時停止中でも編集や情報閲覧は行える。シミュレーションと見た目の演出時間を分ける。
- 完成版の同時店内人数は最大40人を仮目標とし、外の来店待ちと入店を諦めた人数も集計する。負荷のために客を黙って消さない。
- PCで通常・最大店舗の混雑時とも60fpsを目標に、4倍速でも進行や操作がもたつかない描画と更新を目指す。対象機種・解像度・店舗条件を記録して確認する。現時点では未検証。

## 15. 品質の判定と主なリスク

| リスク | 早い段階で確かめること |
| --- | --- |
| ドット絵の密度・角度が揃わない | 1画面と同縮尺の素材セットでアートを固めてから量産する |
| 人物設定が説明文だけになる | 同じ売り場で嗜好の違う人が異なる商品を買うことを観察する |
| 配置が売上に影響しない | 同seed・同発注で配置を変え、経路・待ち時間・購買の差を見る |
| 客と店員が通路で止まり続ける | 狭い通路、棚移動、行列、出口付近の混雑を検証する |
| 全自動でも毎回最適になる | 自動化はプレイヤーの指定を実行するものとし、予測と投資判断は残す |
| 手作業が忙しすぎる | 同じ発注やシフトを繰り返し設定せず30分遊べるか確かめる |
| 商品を増やすほど単調になる | 商品数より、客層・価格・鮮度・棚面積の異なる選択を増やす |
| 長期プレイで経済が破綻する | 複数seedで1年分を回し、複数方針でのクリアと再建を検証する |
| 誰でも放置でクリアできる | 初期設定維持・全品均等発注・最安値固定と、需要に対応する方針を同seedで比較する |
| 難しいが理由が分からない | 実際に操作し、店内とレポートから失敗原因と次に試す変更を読み取れるか確認する |
| ネタが名前と説明だけになる | 無音で店内を見ても、商品や客の動きから笑いどころが伝わるか確認する |

### 初期プレイ版の受け入れ基準

- 10分以内に「この人はこれを買う人だ」と認識できる住人がいる。
- 最初の10分以内に、商品か住人の動きにコミカルな場面がある。初期版のネタ商品4種と繁忙イベント1件が通常プレイに登場する。
- 配置、商品構成、シフトの各変更が、実際の客の行動とレポートに反映される。
- 再会した住人に前回の関係・購入履歴が残り、セーブ後の再開でも一致する。
- 商品は納品・棚・かご・販売・廃棄のどこかにあり、在庫が負数にならない。
- 同じ入力列を通常速・倍速で再生した最終状態が一致する。
- 黒字化、資金不足、救済、目標達成、継続、再挑戦まで操作で辿れる。
- 新規、読込中、保存成功、保存失敗、資金不足、配置エラーを確認する。
- 375・768・1024・1440pxで実際に操作し、文字欠け・重なり・誤選択を確認する。
- 1日の朝昼夜と混雑状態をスクリーンショットで確認する。
- 実装環境に合ったテスト、lint・静的解析、型チェック、buildを実行し、未対応の検証は記録する。

### 本編の攻略性を判定する追加基準

- 固定した10seed以上で、初期設定維持・全品均等発注・最安値固定の各方針と、需要に対応する方針を比較する。前者が大半のseedで五つ星を取れるなら難易度を再調整する。
- 各検証seedで期限内クリアに至る有効な操作列を少なくとも1つ確認し、seed群全体では朝型・スイーツ型・定番型それぞれの成功例を確保する。乱数だけで解けない状況を排除する。
- 繁忙日には「在庫を増やすだけ」では解けない処理能力の課題があり、導線・補充・レジの改善が数字に現れる。
- 最終審査の各条件について、未達・達成・分母不足・期限切れを個別に検証する。過剰値引き、客の排除、無制限の借入で審査を迂回できない。
- プレイ検証では、情報を見て方針を修正した経緯を記録する。成功時にも分析と組み替えが必要だったかを見る。
- リトライで学びが効き、同じ失敗の原因を説明できることを確認する。数値の仮置きだけで「攻略が必要な難易度を達成済み」とは扱わない。

## 16. ゲーム体験の品質基準

「Steamで販売されているゲームのクオリティ」は、**見た目に惹かれ、触ると気持ちよく、遊ぶほど攻略の深さと愛着が増すこと**を目標として扱う。判断の対象は、実際に画面に出て、操作でき、体験できる内容とする。

### 一本のゲームとして作り込むところ

| 領域 | 目指す状態 | 確認する場面 |
| --- | --- | --- |
| ゲームの核 | 経営の組み方で結果が変わり、自分の工夫で店が育ったと感じられる | 欠品・行列の原因を見つけ、配置や担当を変えて改善する一連のプレイ |
| 本編の充実 | 序盤から終盤まで新しい判断と住人の出来事があり、最後の目標と結末がある | 各季節の需要変化、増床、常連の変化、五つ星への挑戦 |
| 再プレイ | 朝型・スイーツ型・定番型、異なるseedで品揃えと配置を組み直す価値がある | 複数方針での攻略。商品数やプレイ時間だけで充実度を判断しない |
| ドット絵 | 床・設備・人物・商品・UIの密度、角度、輪郭、光源が統一されている | 昼夜・四季・増床前後・混雑時。仮素材や素材間の不自然な差を残さない |
| 人物と笑い | 常連を見分けられ、行動に合うポーズや商品に結び付くネタが自然に起きる | 長いパンを持つ客、激辛好きの常連、ヒーローの昼休み。短文を読まなくても状況が伝わる |
| 音 | 環境音、操作音、購買音、達成音、昼夜のBGMが店の雰囲気とリズムを作る | 1倍・4倍の繁忙時。音割れ、ループの継ぎ目、通知音の過密を抑える |
| 操作感 | 選択・配置・取消・発注・比較を繰り返しても気持ちよく操作できる | 棚の設置から商品設定まで。反応の遅れやクリック判定のずれを残さない |
| 説明と情報 | ゲーム内の表示から次に何を試せるか分かり、必要な説明を読み直せる | 初回導入、発注画面、配置エラー、日次レポート。攻略の正解を丸ごと表示せず判断材料を出す |
| 演出の仕上げ | 成功・失敗・成長に合う短い反応があり、操作を止めずに結果が伝わる | 常連化、増床、レジ列の解消、目標達成。数字と演出を一致させる |

### 触り心地と画面の完成度

- タイトル、新規開始、続きから、設定、ヘルプ、結果画面まで同じビジュアルと操作ルールで揃える。デバッグ表示・仮文言・操作できない予告メニューを残さない。
- 棚は選択→設置先→確定が自然につながり、費用・向き・利用面・通路への影響を確定前に見られる。取消で迷わず戻れる。
- 住人を選ぶと、その場の目的と買い物の理由をすぐ読める。名前や吹き出しが店内全体を覆わない。
- 音量、UI拡大、演出の軽減、主要ショートカットなど、遊びやすさに直結する設定を揃える。
- 色だけに頼らず、形と文字でも欠品・選択・エラーを伝える。重要な情報は小さなドット文字だけで表示しない。
- 日本語の説明と会話を整え、同じ冗談の連発を避ける。笑いの直後にも必要な経営情報を読めるようにする。

### 完成度が足りないと判断する状態

1. 客や店員が詰まり続ける、会計が誤るなど、経営の因果関係が崩れている。
2. 序盤を抜けると放置で勝てる、万能商品で全課題を解ける、失敗の理由が読み取れない。
3. ネタが名前と説明だけで、人物の動きや商品に表れていない。
4. 中盤以降は同じ発注を繰り返すだけになり、新たな判断や住人の変化がない。
5. 店内とUIの絵柄が揃わない、音や演出が仮のまま、主要操作がもたつく。
6. 最初の15〜20分だけが作り込まれ、その後の画面・音・内容が急に薄くなる。

第15章の動作・攻略検証に加え、実際に一連のプレイを行い、画面・音・操作・経営判断のつながりを確認する。品質を高める作業は、問題のある場面を見つけて小さく直し、同じ場面を再確認する手順で進める。
