# v0.2 試遊記録

## 2コースを走った結果

Godot 4.7.2の縦画面で、ナギを操作して夕焼けコンテナヤードの内側を完走した。加速して集団に入り、水路では通常のタップで踏み切り、空中でもう一度押して吊り足場に着地した。この走行は落水0回、43.31秒で2位。録画にはゲームの操作イベントを使った。原画とモデルの比較画像は別に掲載している。[レース中の映像（17秒・音声あり）](v02-yard.mp4) · [Blenderモデルの動き](../../modeling/review/sport-motion.webp)

iPhone 17eのiOS 26.5シミュレーターでは、Safariのタイトルから夕焼けコンテナヤードに入り、ドラッグ、加速、空中での再タップ、一時停止と再開を試した。右の固定桟橋を回って45.29秒で完走し、同コースでの再挑戦と潮風ふ頭への切り替えを確認した。スタートの横断幕を高くし、ゴールカメラを桟橋の内側へ回してから、外側でゴールしたナギの顔が柱に隠れないことを再確認した。[水路の分岐](v02-yard-safari.jpg) · [ダイブ中の画面](v02-dive-safari.jpg)

画面の大きさは390 × 844ポイント。Safariの表示領域は390 × 699 CSS pxだった。デスクトップのブラウザでもコース選択、キーボード操作、完走後のコース変更を確認した。

## 飛距離とルートの差

同じ踏み切り位置・速度から、平坦な床に着地するまでの距離を走行テストで測った。通常ジャンプは3.33 m、頂点付近のダイブは4.08 m、踏み切り直後のダイブは1.11 m。6秒間の平地走行では、通常走行が23.52 m、頂点付近で毎回ダイブする走りが22.43 mだった。

ヤードの分岐では吊り足場を左端・中央・右端からそれぞれ動かし、同じ速度で入って合流までの時間を比べた。内側を渡り切ると14.17〜14.18秒、外側は14.78秒。内側で落ちて復帰すると22.20秒だった。5人のライバルを含む全区間のテストでは、外側を走るナギが加速とジャンプを使わず45.46秒で完走した。

## モデルと操作画面

6人のGLBをGodotに読み戻し、各モデルの19本の骨、1枚のスキン付き描画面、10個の動きと加速・ダイブ・立ち上がりの再生を確認した。Blenderに読み戻したモデルで見ると、スライドの接地直後は前腕、0.14秒後は胴、0.308秒後は片足が最も低くなる。ナギの側面の輪郭を同じ高さにそろえて原画と重ねたとき、重なった面積を両方の輪郭が占める面積で割った値は0.841から0.895になった。[計測方法とモデルごとの結果](../../modeling/README.md)

`npm run check` で走行の107項目、6人のモデル、画面遷移と配置の91項目を確認し、Web版を書き出した。配置のテストは320 × 568、390 × 800、1024 × 760の3サイズ。コース選択とプレイ中のボタンが44 px四方以上あり、重ならず画面内に収まることを確認した。

## iPhone向けの描画

iPhone 17eシミュレーターのSafariで、6人が密集するスタート直後の3.5秒、浮き橋または水路の分岐付近の4.45秒、ゴール付近の3.5秒を調べた。試遊用ページでブラウザの画面更新間隔を記録し、各区間の95パーセンタイルを33.3 ms以内に収めることを目標にした。計測用の処理は公開版に含めていない。

昼の潮風ふ頭では、遠くの小さな金具を省き、回転バーの向きに合わせて動く影を床に描く。画面の解像度が高いタッチ端末では3Dに使う画素数を抑え、文字と操作ボタンは端末本来の解像度で表示する。

実物のiPhoneでの操作感と描画時間、初めて遊ぶ人が2周目に自分で別のルートを選べるかは未確認。
