# Ball Catch / Spatial Hand verification (2026-09-27)

## Implemented

- 12球のキャッチラウンド。次の落下位置の光るガイド、得点、ミス、残数、終了、再挑戦、Sandbox復帰。
- カメラの追跡が消えると進行を止める。ゲーム判定は手のひら中心を使い、指の入力を要求しない。
- Hand Landmarker の21点の相対3D形状を透過した手に描画。手の画面座標に加え、見かけの大きさから相対奥行きを推定して配置する。`RECENTER DEPTH` で中央位置を更新する。

## Verified

- `npm run check`: 10テスト、lint、型検査、Vite build が成功。ゲームのキャッチ・ミス・終了・追跡なしでの停止、奥行き再中心合わせと前面鏡像をテスト。
- ローカルブラウザの Mouse Mode: 最初の落下球をキャッチして加点、12球の終了画面、`RETRY` で 0/12 へ戻ることを確認。
- 375×812: 開始画面、ゲーム待機、得点、終了、再挑戦でHUDとボタンが画面内。768×900、1024×900、1440×900 の開始画面も確認。
- ローカル静止画像を MediaPipe モデルで検出し、21点を立体的な手として描画した。前面鏡像の向きと画面中央への投影を確認。
- Pages 用の静的サイトを組み立て、日付URLをローカル HTTP で開いて Mouse Mode へ進めた。モデルファイルは HTTP 200 / 7,819,105 bytes。静的版での Ball Catch ボタン以降はブラウザ自動操作がタイムアウトし、完走は未確認。

## Not yet verified on hardware

- 実際のカメラ入力で手の向きと前後移動を変えたときの精度、遅延、キャッチ成功率。
- iPhone Safari の前面・背面カメラ、タッチ操作、長時間の性能。ブラウザ Mouse Mode と静止画像の smoke は実機操作の代用にならない。

単眼カメラの見かけの幅からは実距離を一意に復元できない。手の回転や画角でも推定値が変化するため、ゲーム判定は奥行き方向に余裕を持たせている。
