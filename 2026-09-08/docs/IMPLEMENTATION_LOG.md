# 16面再設計の実装記録 — Issue #106

## 作業範囲

- Goal: 承認された16面の判断を、部材・支持・荷重・接触によるステージとして実装する。
- Context: `STAGE_REDESIGN.md`、PR #105、`game/core/world.gd`、旧16面。
- Constraints: 見えない正解順フラグを使わない。既存の操作と画面構成を保つ。旧記録を新面のクリアにしない。公開タグは作らない。
- Done when: 16面のデータと必要なギミックをゲームへ接続し、確認用Web出力を用意する。全解法の成立・難易度の採用判断はユーザーの確認を待つ。

## 実装

- PR #105をマージし、Issue #104を完了。Issue #106 / `feat/106-rescue-mechanisms` で実装。
- `campaign.gd` に16面、任意ヒント、基準操作列、誤解法の試行列を定義し、`Levels.all()` を切り替え。
- 梁の質量・寸法・摩擦・複合形状、吊りかご、開く底板、受け鉢、動く箱を追加。
- 綱は両端の距離と相対速度から張力を計算。固定滑車の経路を画面に描き、部材の回転にも力を伝える。操作列・ステージ番号・経過時間による駆動はしない。
- GrooveJoint2Dのガイド、部材間のピン接合、接触する支持台を追加。部材を切った後、残る接合の衝突除外が失われる問題を補正。
- 少数の可動剛体は休止を無効化し、長く待った後の解放でも案内台が途中で止まらないようにした。
- 緩衝材にも衝撃上限を設け、深い落下が箱に入れば無条件に成功する状態を変更。
- 箱の位置から収容範囲を追跡し、箱と全陶器が落ち着いてから成功。収容した陶器の質量は維持する。
- 保存形式をv3に分離。v1/v2のファイルは削除・上書き・自動移行しない。
- 新しい面に合わせて `tests/run.gd` を更新。解法・待機時間の延長・誤解法・全切り・未操作を別々に判定する。開発用の一時プローブは除去。

## 機構を配置へ落とした際の変更

- 06: 陶器が吊りかごから離れると受け橋の荷重が変わる配置。先に別の支えを入れる判断を残した。
- 09: ガイド付きの台車で梁を下階へ送り、受け側を台車より張り出させた。下階の案内面と開口の寸法は設計時の模式図から変更。
- 10: 受け座との接触を保つため梁の下面に叉を追加。支点は自動接着しない。
- 13: 一つの梁の二つの受け座という案を、外側・内側へ下ろす二本の支柱の取捨選択へ変更。支持位置が箱の通過を妨げる判断を表現。
- 16: 箱を昇降台に載せ、出口が開くと重力で梁へ移る構成。箱をレール間で瞬間移動させない。重りの二段目は下の受け鉢と綱を介して出口のてこへ力を伝える。

## 実際に確認したこと

追加チェックを止める指示より前の途中版で、01〜07の基準解法・待機時間変更・誤解法・全切り・未操作試行が通った。08は荷重と箱の位置を調整した後、基準解法の成功と逆順の破損を個別に確認した。これは現在の16面全体の検証ではない。

09の途中版では、下階への展開時の引っ掛かりと受け渡し時の破損を確認した。その後に梁の張り出しと配置を変更したが、最終配置は再試行していない。10〜16はデータ・接続を実装した段階で、解法が成立するか未確認。

ユーザーから「チェックはこっちでするので、実装が完了したら教えて」と指示を受け、追加のプレイ試験・ブラウザ操作・画面幅別確認を停止。最終変更後はWeb出力を生成するための `npm --prefix 2026-09-08 run build` のみ実行し、Godot 4.7.2のエクスポートが成功した。
