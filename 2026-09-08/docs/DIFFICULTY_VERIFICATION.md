# 16面版の設計と検証 / Issue #102

## 判断と変更

前8面は基準解法が安定して成立していたが、ユーザーの実プレイでは簡単すぎた。解法成立と難易度は別である。今回、支点の選択→経路の組合せ→受け止める時間→合流と多段搬出の順に16面を構成した。

最初の4面は導入として残し、旧04/05/06を新05/06/04へ並べ替えた。旧最終面を08「橋を渡る、二作品」に改名。9面で橋と折返しを組み合わせ、10面以降に水平な受け皿を残して待つ判断を加えた。後半は陶器の数・鏡写しだけでなく、出発前の合流、小台の運搬、受け皿の解放、最下段の準備を組み合わせる。

切断上限、タイマー、順序の正解フラグは追加していない。意図した解法と異なっても実剛体で救出できれば成功する。常時表示から「切断の目安/最少」の重複を外し、最少記録は台帳で確認する。演出低減のスイッチを削除。OSのprefers-reduced-motionはWeb起動時に内部で反映する。

以下の切断数はテスト用基準解法の数であり、最小手数の証明ではない。設計上の順序であり、人間の難易度評価を測定したものではない。

## 物理で確認した事実

- 全16面×10回、開始時刻を0/0.1/0.2秒、陶器の初期Xを-1/0/+1ずらして基準解法が成功。物理は120Hz。基準解法の所要時間は約1.7〜15.6秒。
- 10〜16面で基準解法の全切断を0.5秒へまとめると、すべて接触破損。正しい箇所だけを全部先に切る方法では解けない。
- 同じ7面で工程の時間を逆順にすると成功しない。受け皿の解放を省略しても成功しない。
- 待機後の工程を3秒遅らせても7面すべて成功。待機中に一時停止・観察でき、狭い反射神経の窓を要求しない。
- 全接合点を最初に切る検査では、導入03だけが成功。未切断で30秒置くと全16面で無傷・未成功。剛体の非有限座標も検査。
- 11は受け皿の片側を残す2切断の別解が成立。12/14/15/16でも小台や中段の片側を残す別解を観測した。これらは削除せず、11の別解を回帰テストにした。
- 15は最下段の準備を省くと成功しない。一方、13の単体陶器は下段を先に傾けても、受け渡し後に傾けても成功する。

試作では受け皿と背面の小さな壁が交差し、梁が跳ねる候補を棄却した。板を載せただけで早切りが安全になる箱蓋案も棄却。見た目の部材数や手数だけを増やすことを採用理由にしなかった。実行時は面データの`solution`を読まず、物理と箱内の安定判定だけで勝敗を決める。

## 演出と操作の調整

- 切断: 二つに割れる真鍮の留め具、22本の火花、拡張する輪、短い金属音。
- 着地: 梁の接触速度に応じた粉塵と打音。クールダウンで静止時の連発を抑える。
- 破損: 28個の大きさの違う陶片と衝撃輪。破損点・軌跡は残す。失敗文を「先に道を」から、着地場所と切る時機の見直しへ変更。
- 成功: 蓋が閉じ、印が押され、紙片と上昇する和音で締める。描画だけの演出で、剛体の位置・速度・破損しきい値を変更しない。演出終了を待たずリトライ・次の面へ進める。
- 16面の密集箇所に対応し、44pxのタップ領域を模型内に置く。陶器の初期位置と受け皿の待機位置を避け、物理的な接合点へ引出線を付ける。移動中にボタンを追従させず、押す位置を固定。
- 台帳を表示したままデスクトップ→スマホへ縮小すると、旧列数の最小幅が残って右列が欠けた。列数を先に変更してから幅を指定する順へ修正し、回帰テストを追加。
- 保存はv2。v2がまだない場合のみv1の8面分を対応表で移行。旧保存ファイルを消さず、未クリアの新面をクリア扱いにしない。型・番号範囲・手数・版・最大ファイルサイズを検証。

- Godot 4.7.2 import/型検査、Web Compatibility・シングルスレッドrelease build成功。
- 物理234チェック、UI3,857チェック、root npm test 37件成功。独立したGDScript lintは未設定。
- UIは375/600/768/1024/1440px、短い375×667、Retina 2xを実シーンで検査。16面、操作領域、待機位置の遮蔽、保存移行、ヒント、停止中の切断、成功/失敗/再挑戦、台帳往復と最終面遷移を含む。
- Webの1440×900で16面を手動クリア。途中の台に長時間置いてから次の工程へ進め、8切断で二作品を梱包し、Nで16面台帳へ進めた。
- Webの1024×768で10面を先に②③で切り破損。Rで戻し②で受け止め、待機後③で救出。失敗理由・破片・成功表示を目視。
- Webの768×1024で最終面、375×667で最終面の44px操作・文字・スクロール・台帳を確認。375pxの番号ボタン操作でも7切断の別解で最終面を救出し、台帳へ進めた。受け皿の待機位置に陶器が見えることも目視。
- Godotネイティブでも16面版を起動、既存8面の記録移行を表示で確認し、番号キーで切断→救出→梱包を実操作。

共通サイト build:site --prebuilt、git diff --check成功。apps.jsonとroot READMEの説明を全16面に同期。CIとPRマージの結果はGitHubに記録する。公開タグは作成しない。

## 限界

ユーザーの新16面に対する難易度・演出の評価はまだ得ていない。特に01〜08は導入・復習として比較的易しい。自動検査で後半の工程と失敗が区別できることは確認したが、「十分難しい」「面白い」と証明したことにはしない。スマートフォン実機Safari/Android・効果音の聴感バランスは未検証。以前からの背景タブ進行・盤面読み上げは対象外。
