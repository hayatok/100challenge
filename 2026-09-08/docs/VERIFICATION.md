# 検証・判断記録

## 確認済みの実装判断

- 2026-09-08、Godot 4.7.2.stable.official.ed1daf0bf（macOS）を確認。
- 120HzのGodot 2D剛体、CCD shape、質量比1:3、反発ほぼ0、24 solver iterations。床はピン接合を外して動き、描画用アニメーションで位置を誘導しない。
- ピン角度制限の試作は意図した停止を示さなかった。可視の石膏の受け柱に床を着地させる構成へ変更。設定だけで安定したと扱わず、実際の接触で確認。
- 陶器の破損は接触法線方向の相対速度390px/s超。接触法線は実測でワールド方向を返すことを確認し、陶器の回転を二重適用しない。箱の緩衝材との接触は破損対象外。
- 成功は全陶器が箱の内側に入り、速度55px/s未満の状態が0.65秒継続した時。箱に一瞬触れただけでは成功にしない。
- 初期案の「橋を先に」は唯一の解法ではなかった。逆順と同時切断も成功したため別解として保持。後半の07は折り返しの坂と箱の庇を設け、準備の遅れが破損につながる面へ調整した。
- 03では片側だけの切断でも救出可能。目安2を達成上限にせず、1切断の工夫を認める。
- 狭い模型で44pxの接合ボタンが重なる問題を発見。引出線を付けて間隔48pxを確保し、全8面・5幅のUI回帰検査へ追加。

## 実エンジンの自動検証

- 物理106チェック成功。全8面の意図した解法を各10回、初期X位置±1pxと切断時刻0〜0.2秒差で検証。
- 全切断は03以外の7面で失敗。01の誤った支点切断、07の下流準備の遅れ（②を0.5秒、③を6.5秒）は実接触で破損。
- 07の同時切断、03の片側切断は別解として成功。
- 未切断状態を全8面20秒ずつ観察し、破損も自動成功もない。
- 不正な接合番号、重複切断、終了後切断、破損/不正な保存データを検証。
- UI581チェック成功。375/600/768/1024/1440px × 全8面の枠内配置、接合点44px以上、接合ボタンの非重複。
- 実UIの停止中切断→再開→成功→次面、失敗で停止、再試行で復元、二段階ヒントを検証。UIテストはユーザーの保存データに書き込まない。

## 実画面の確認（進行中）

- Godotネイティブ画面で模型、切断操作、床の傾斜、箱への救出、成功表示を目視。
- Web 375pxでタップ切断→救出→次の模型を操作。成功時の停止ボタンの長い文言がはみ出したため「完了」に変更。
- 残りのWeb幅・エラー・保存再読込・最終スクリーンショットを継続確認中。

## 限界

自動テストと開発者によるプレイは、第三者の初見プレイテストの代替ではない。判断を学べる構成を実装し解法を検証したが、初見の楽しさ・難易度の評価は未実施。スマートフォン実機のSafari/Android、端末間の完全な物理決定性、スクリーンリーダーによる盤面読み上げは未検証/未対応。Webの背景タブ進行は対象外。

公式参照: [PinJoint2D](https://docs.godotengine.org/en/stable/classes/class_pinjoint2d.html)、[PhysicsDirectBodyState2D](https://docs.godotengine.org/en/stable/classes/class_physicsdirectbodystate2d.html)。APIの一般説明と、この版での実測結果は区別した。
