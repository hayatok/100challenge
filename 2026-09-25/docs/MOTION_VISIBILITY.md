# 動きが伝わる表紙への調整（2026-09-25）

## Goal

すべての表現で、6秒のループアニメーションが見た目にも分かるようにする。静止した1フレームの美しさと日本語の可読性を維持する。

## Context

- ユーザーの「アニメーションはマスト」という実画面での指摘。
- 既存のプレビューは描画回数を30fpsの時刻に換算しており、5枚のcanvasを描く処理が遅いと6秒ループ自体が引き伸ばされる。
- 既存MP4を180pxに復号した0秒と0.75/1.5/2.25秒の比較では、H4「切る」、H6「響く」、H8「張る」の最大RGB平均差がそれぞれ1.69、2.50、1.66/255と小さい。4時刻の見比べでもほぼ静止して見えた。

## Constraints

- `drawScene(recipe,time)`をプレビューとPNG/MP4で共有し、recipe・IndexedDB・JSON形式を変えない。
- 文字は全フレーム読める状態にし、全面点滅や急な明暗反転を使わない。6秒・30fpsの書き出しと自然なループを維持する。
- reduced-motionでは自動再生せず、明示的な再生操作でだけ動かす。

## Done when

- プレビューの6秒が実時間と一致し、表示できるフレームが少ない端末でも再生速度が変わらない。
- H4/H6/H8の0秒から離れた位相を復号動画とスクリーンショットで目視し、どの表現も動きの方向が分かる。主文字は欠けない。
- 代表構図と追加構図の実MP4を再生成し、PNGと同時刻で一致し、最後と最初が自然につながる。
- ブラウザの操作・reduced-motion、375/768/1024/1440px、lint、テスト、型チェック、buildを確認する。

## 実装順

1. プレビュー時刻を単調時計から計算し、停止・再生の状態を維持する。
2. 変化が小さい3表現の形・残像・線群をそれぞれ異なる周期運動へ調整する。
3. 実動画とブラウザで再生速度、フレーム差、文字、ループを確認する。
