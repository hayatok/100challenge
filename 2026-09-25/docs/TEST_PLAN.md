# テスト方針・完了判定 v1

## 1. 検証の分担

作品の美しさはunit testで代替できない。一方、ランダム生成と保存の正しさを目視だけに任せない。次の3層を必須にする。

1. Vitest: 境界検証、乱数、生成、固定、履歴の純粋ロジック。
2. Playwright: 実フォント・Canvas・IndexedDBを使う操作、描画と出力の統合。
3. 実ブラウザの目視: 3表現の違い、文字組み、1ループの気持ちよさ、実際にダウンロードした動画。

この文書は設計時の判定基準。実装後の結果と未検証項目は [RESULTS](verification/RESULTS.md) に記録する。

## 2. 自動テストの必須項目

| ID | 対象 | 合格条件 |
| --- | --- | --- |
| U01 | 入力/schema | 1/32文字を受理、空/33文字/4行/補助49文字/絵文字/危険制御文字を拒否。結合文字は1書記素。LF/CRLF正規化 |
| U02 | 乱数 | 既知seedの出力列、namespace独立、seed 0を含む再現性。描画順・保存時刻がrecipeへ影響しない |
| U03 | 初期候補 | 100seed×2比率でおまかせに3表現を含む。4案が重複せず、4枚目は同じ表現の別構図。指定表現なら2構図・2配色以上 |
| U04 | 固定 | 16通りの固定組合せ×各表現。固定domainが親とdeep equal、変更domainは1〜2個。文字・比率・family不変 |
| U05 | 探索限界 | 全固定は0件で状態不変。未固定値の選択肢が少ないと1〜3件を返し、32試行で終了。重複や見かけだけ4件を作らない |
| U06 | 履歴 | A→B→A→CでBも残る。戻ると候補順/文字/選択/固定を復元。上限50、削除された参照の扱い、お気に入りの独立保持 |
| U07 | 編集 | 未適用draftは元recipeを変更しない。取り消しは完全復元。適用は新recipe。固定項目の手動変更と生成時固定が矛盾しない |
| U08 | JSON | roundtripで描画設定を保持。未知版、未知キー、不正composition、巨大ファイル、NaN相当・範囲外、URL参照を拒否 |
| U09 | 保存順序 | 連続更新を直列化。失敗時dirty維持、revision競合は勝手に上書きしない |

### 実Canvasと操作

| ID | 対象 | 合格条件 |
| --- | --- | --- |
| B01 | 初回 | sample4案が表示され、ロード中に偽フォントの完成品を見せない。console errorなし |
| B02 | 主要導線 | タイトル入力→4案→選択→色/文字固定→派生→親へ戻る→お気に入り→再読み込み→復元が通る |
| B03 | IME/入力 | composition中に生成されない。未反映入力を明示、生成失敗で既存作品が残る |
| B04 | フォント/layout | 3表現×2比率×入力ケースでbboxがsafe area内、行数3以下、補助文非重複。フォント取得を遅延/失敗させた時の再試行 |
| B05 | レンダラー | 同じrecipe・同じ時刻を順不同で描いて同じ画像。同じhostでA→B→AでもA一致。描画が前フレームに依存しない |
| B06 | 動画の動き | H1〜H3の0/1.5/3/4.5秒が静止画の複製ではなく、少なくとも3つの異なるフレームを含む |
| B07 | 継ぎ目 | t=0と6の位置・画像が一致。5.9667→0の差が通常隣接フレーム差の分布から突出しない。前後の位置微分も連続 |
| B08 | プレビューとPNG | 同じサイズ/時刻に揃えた描画とPNG復号結果が一致。表示用CSSの変形や低解像度maskを持ち込まない |
| B09 | 永続化 | 実IndexedDBで再読み込み、上限、保存失敗表示。2ページ同時更新で古いrevisionの保存が拒否される |
| B10 | ライフサイクル | mount/unmount、候補50回変更、出力3回でhost/RAF/observerが増え続けない。出力後も生成できる |
| B11 | レスポンシブ | 375/768/1024/1440pxで横はみ出しなし。長いラベル、dialog、縦長canvas、focusを確認 |
| B12 | アクセシビリティ | キーボードで主要導線完了。dialogのfocus移動/戻し、ラベル、選択状態、reduced-motion停止と明示再生 |
| B13 | 通信・復元 | 外部originへ入力を送らない。必要資産読込後にofflineにして既存文字と同梱字体の未使用文字で生成・PNG・JSON保存が通る。フォント取得失敗は明確なエラー |
| B14 | 非同期の競合 | 古いフォント/compile完了で最新候補を上書きしない。二重生成で重複セットを作らない |

画像比較は同じOS/ブラウザ/フォントの固定環境で実行。クロスブラウザのピクセル完全一致を要求しない。ゴールデン画像は完成度を確認した後に採用し、差分が出たから自動更新して通す運用をしない。

B07では周期の式だけをテストして合格としない。実際のcompile結果の位置・角度を1/30秒刻みで調べ、ラップ区間の差を通常区間の95パーセンタイルの2倍以内（丸め誤差許容を加える）として判定。閾値に落ちたときは継ぎ目の目視を行い、実装不具合か閾値不適合か記録する。t=0と6が同じだけでは直前のジャンプを検出できない。

### 実出力の検証

- **E01 必須:** Chromiumの実codecで720px・6秒の動画を生成。ファイルが空でないだけでは不十分。生成物を再読込し、幅/高さ、映像track、30fps相当の180フレーム、尺6秒±1フレーム、音声なしを検査する。
- **E02 必須:** 0/1.5/3/4.5秒を復号し、同じrecipeの正解画像と比較する。非可逆圧縮を許容し、黒画面・別候補・文字欠落・静止画の複製を検出する。初期基準は同サイズ画像の平均絶対RGB誤差12/255以下。3作品の実出力で閾値を確定し記録する。
- **E03 必須:** デスクトップChromeでAVC/MP4の実書き出し・再生。CIのChromiumでAVCを使えない場合、CIは実WebMを検証し、MP4はローカルの実結果を別に記録。どのcodecも使えないCIでは動画統合テストを黙ってskipせず、環境整備か失敗理由を明示する。
- **E04 必須:** 開始直後/90フレーム付近/最終化付近でキャンセル。Blobを完成品として渡さず資源解放、再試行可。codec能力がtrueでも途中失敗するケースを注入し復帰を確認する。
- **E05 必須:** codec非対応時のPNG/JSON導線、1080非対応時のサイズ選択、エラー時の理由が出る。能力検査のモックはこの分岐確認にだけ使用し、実動画成功の証拠にしない。
- **E06 必須:** H1〜H3×2比率を720pxで出力し目視。1080縦長はH1で実出力し、メモリ・時間・読みやすさ確認。

動画再読込にはMediabunnyのInputとVideoSampleSink、または手元のffprobe等を利用できる。通常のアプリ動作に外部CLIを要求しない。codec実装を同じライブラリで読み戻すだけで終えず、ダウンロードしたMP4/WebMをブラウザvideo要素またはOSプレイヤーでも再生する。

## 3. 文字入力ケース

`tests/fixtures/text-cases` に明示的な期待を持たせる。

- 「あ」: 極短文でも過度に拡大せず成立。
- 「余白の、その先。」: 通常の日本語。
- 「まだ、\n途中です。」: 明示改行。
- 「PLAY\nWITH TYPE」: 英文と改行。
- 「生成する2026 / PLAY」: 和欧混植。
- 「『つづき』は、ここから。」: 括弧と句読点。
- 32書記素の日本語、32書記素の空白なし英単語: 上限と折り返し。
- 結合濁点を含む文字: 書記素を分離しない。
- 空白のみ、4行、33書記素、絵文字: 入力エラーと修正導線。
- 補助文0/48書記素: 空領域の除去と最大2行の配置。

## 4. 目視の品質ゲート

各3構図、計9構図について、標準の日本語と英語を正方形・縦長で確認する。すべてのパラメータ組合せの動画を作る必要はなく、各表現の密度最大・動き最大・32文字の組合せを追加のストレスケースにする。

次の項目は0=不可、1=要改善、2=合格で記録。**各項目2**になるまで修正する。

| 観点 | 2点の条件 |
| --- | --- |
| 静止構図 | 位相0だけでも表紙として使える。主役、余白、補助文の順序が分かる |
| 日本語 | 見切れ・意図しない豆腐・不自然な字間がなく、3秒見ればタイトルを読める |
| 動き | 6秒を2周見ても接続点が分からず、動きと停止の強弱がある |
| 統合 | 文字と帯/面/セルの関係が動きによって見える |
| 違い | 3表現をモノクロでも区別でき、各構図も単なる色違いになっていない |
| 探索 | 選んだ案からの派生に親らしさが残り、何が変わったか説明できる |
| 出力 | 保存した動画に文字欠落・ぼけ・速度変化・黒フレームがない |

見た目の根拠はH1/H2/H3のコンタクトシートとループ動画。静止画を撮っただけで動きの合格を付けない。

## 5. 実機・性能・状態の確認記録

デスクトップChromeを必須対象にし、Safari/Firefoxは少なくとも生成・PNG/JSONと能力表示を確認。モバイルは375pxの画面確認を必須、iOS/Android実機がなければ「実機未検証」と明記する。

`docs/verification/RESULTS.md` に次を記録する。

- 日時、commit、OS/機種/ブラウザ版、viewport、DPR。
- 実行コマンドと結果。モックによる分岐テストと実codec結果を分ける。
- 4候補生成、選択応答、30秒連続プレビュー、720px出力時間、1080縦長出力の実測。
- loading/empty/error/success/disabled/focusの画像。お気に入り空、履歴空、font失敗、保存失敗、動画不可を含む。
- 375/768/1024/1440pxの代表画像を目視確認したか。
- 美術7項目の判定、既知問題、未検証対象。未計測を0msや合格にしない。

## 6. 完了条件

- unit・ブラウザ統合・lint・型チェック・buildが通る。
- 実MP4、実PNG、JSON再読込が通り、3表現の品質ゲートが合格。
- 4案→固定して派生→親へ戻る→お気に入り→再開の導線が実操作で通る。
- 4画面幅とreduced-motionを確認し、出力が失敗しても制作を再開できる。
- サブパス配信と一覧リンクが機能。公開する場合は別途本番URLを確認。
- 未検証のブラウザや端末を「対応確認済み」と書かない。
# 表現拡張時の適用範囲

上記の初版計画にある「3表現・9構図」は、表現拡張後は「6表現・18構図」と読み替える。日本語・英語、正方形・縦長の構図確認、実MP4/PNG比較、選択・固定・履歴・保存、4画面幅の操作を追加の3表現にも適用する。実施結果は [検証結果](verification/RESULTS.md) の「表現拡張の追加検証」に記録する。

## 造形見直し時の適用範囲

今回の追加後は「9表現・27構図」として同じ品質ゲートを適用する。新H7〜H9についても2比率の実PNG/MP4、4時刻の同一描画比較、復号動画の継ぎ目、日本語・英語の可読性を確認する。初回4案の変更は既存IndexedDBの復元に影響しないこと、9個の見本から各表現の4案を選べることを追加で検査する。実施結果は [検証結果](verification/RESULTS.md) に追記する。
