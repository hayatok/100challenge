## 実Macで操作した範囲

macOS配布物を起動し、タイトル、新規開始、広場の保存から再開、WASD移動、固定アンカーと敵への接続、打ち上げ、斬撃、被弾、敗北、再挑戦、ポーズ、設定を操作した。主人公と軽兵の色・向き、剣、攻撃予告、体力と残りダッシュの表示を実画面で確認した。

Safariでは読み込み、新規開始、開始足場から広場・巨像の下段までの移動と接続、ポーズ、敗北・再挑戦、再読み込みを操作した。Chromeでも読み込み、開始、移動、ジャンプ、ワイヤー、ポーズを確認した。最終Web出力でSafariとChromeの保存地点からの再開とEscによる停止を確認し、Chromeでは再開後の移動と再停止も確認した。音声開始後にブラウザの音声再生表示が出たが、聴感を確認した証拠にはしない。

確認中に見つかった問題は次のとおり。

- 白い床の上で体力表示を読みにくかったため、HUDに暗い背景と文字の縁取りを追加した。
- 肩の側面へワイヤーが衝突したため、上方の接続点と下段アンカーを調整した。自然な着地点から再接続できることを経路テストで確認した。
- Chromeの最初のEscでポインター固定だけが解除される場合があったため、Webの固定解除をポーズへ接続した。修正後のSafariとChromeで停止を確認した。
- 3体の軽兵が同時に攻撃を始めたため、予告・攻撃への参加を同時1体に制限した。敵の位置を示す「!」と方向音を予告へ結び付けた。

操作ツールはShift単独を送信できず、マウス固定中の相対視点操作や素早い連打も十分に再現できなかった。ダッシュ・滑走や素早い空中連係、肩からの通常操作完走を実操作確認済みとはしない。実機での基本動作と、下記の自動経路検証を区別する。

macOSの最終配布物は960×540のウインドウでも起動し、保存地点からの再開、ポーズ、設定を確認した。タイトル・メニューと操作表示に文字の欠落・重なり・はみ出しは見られなかった。主な確認サイズはmacOSが1280×720、WebがSafariのCSS 1710×984／ChromeのCSS 1192×779（いずれもDPR 2）。ブラウザの描画ピクセル数はCSSサイズと別に記録する。

## 自動検査

`npm run import`、`npm test`、`npm run build`、`npm run build:mac` が成功した。ルートの `npm test` も38件が成功した。Godotの終了コードだけでなく、SCRIPT ERROR／ERROR／FAILも検査する。

`game/tests/run.gd` では、空中ダッシュ上限と撃破による補充、同じ敵への接続履歴、死亡・遮蔽時に別の対象へ飛ばないこと、薄い壁を越えないこと、核の距離・重複命中、落下した敵の復帰、予告済み攻撃の視点変更と遮蔽、攻撃人数制限、ポーズ中の位置・速度・行動の保持、再挑戦の初期化を確認した。

`game/tests/route.gd` は敵のいない経路の回帰検査。開始位置から、固定アンカー3点、動く肩、上段へ実際のプレイヤー制御で移動し、通常斬撃3回で核を破壊する。通常移動とジャンプ、急降下を使って広場へ戻る。経路の途中では位置を直接書き換えない。肩の両端位置は独立した初期配置で追加確認する。時間切れや接続・着地の失敗は終了コード1にする。

経路テストの入力とカメラはスクリプトで制御しており、人による試遊や配布物の通常操作完走ではない。実Macで描画した画像も `route-render/` に分けて保存する。素材単体の画像は `art/*_preview.png` にあり、プレイ画面とは区別する。

## 残る評価と実装

- G1の造形・モーションを完成見本として評価する。現在は面を生かした造形と骨単位の重みが中心で、AnimationTreeによる連続的な混合、布の仕上げ、地上・空中の専用モーションはこれから。実カメラでの足滑りと剣・衣装の接触を続けて確認する。
- 肩のカメラ視認性を通常操作で評価する。経路fixtureの `shoulder.png` では主人公に極端に近づき、足元と次の接続先が見切れている。スクリプトの視点設定による画像なので通常操作の欠陥とは断定できないが、視認性を確認済みとはしない。
- 通常操作で、狙った対象と着地点を選んで巨像を往復する。壁際、空中連係、動く足場からの切り返しを含め、人による初見試遊を行う。
- 1080p・60fpsの重い戦闘5分、60分の継続プレイ、メモリ推移、入力遅延を測る。今回の短いサンプルで性能目標を達成したとはしない。releaseで取得できないメモリ値はnullと記録する。
- スピーカー／ヘッドホンの聴感、パッド、スリープ復帰、保存不可、署名・公証と新規取得後の起動を確認する。
- キー再割当、文字拡大、音量の個別調整、パッドの対象切替、戦闘評価、追加の敵・本編・完成ボスは未実装。

`apps.json` は未登録。試作の評価とLinux側の再現手順が揃ってから公開カタログへ加える。既存のVerify siteは登録済みアプリを選ぶため、そのCI成功を天砕のGodot検証の代わりにはしない。

## 記録の対応

- `verification/mac-build-info.json` と `web-build-info.json` は今回の最終出力。両方のゲームソースmanifestは `72aa6c946a2590c392a406f5c8746edd969facbdc2464e19d6982792c880335f`。未コミット状態で書き出したことも記録している。
- `verification/native-small/` と `native-small.log` は最終macOS出力。01はタイトル、02はポーズ、03は設定のF8による実viewport画像で、各960×540。
- `verification/native/` と `native-final/` は開発途中の実機操作記録。フォルダ名のfinalは当時の候補名で、上記の最終出力を示すものではない。
- `verification/web/final.jsonl` は2026-10-24 02:58:36 JST以降の最終Web出力によるChrome／Safari記録。`preliminary.jsonl` はそれ以前の候補による記録。通常URLは記録を送信せず、検証時だけ `?qa=1` とループバックの専用受信口を使った。ブラウザのツールバーを含む画像はリポジトリへ含めない。
- `verification/route-native.log` と `route-render/` はMetalで描画した敵なしの自動fixture。通常UIと敵を含むプレイ画面や、人による完走の証拠ではない。

短い性能サンプルには同時に動作する別のビルドやブラウザの影響がある。Chromeで60fpsの区間も見られたが、1080pの重い戦闘や長時間の安定性は未検証。最終Webログのstdout／stderrを保存し、この実行範囲ではSCRIPT ERROR／ERRORの出力はなかった。
