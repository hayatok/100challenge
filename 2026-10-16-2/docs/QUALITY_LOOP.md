# 箱庭日本：観察体験の改善

## Goal / Context / Constraints / Done when

- Goal：眺めて分かる年代の変化、続きが気になる住民の日常、1900年から探せる統計と歴史を作品の中心へ戻す。
- Context：公開v0.2は資料保持・操作確認を通したが、年代の街並みの差、行動の種類と連鎖、歴史の密度と閲覧性、グラフの操作が不足していた。実画面の1900/1965/2020を同じ位置で記録した。
- Constraints：歴史と原統計は変更しない。欠測・対象・分類・地域・観測年を保持。数値がない年に新しい数値を作らない。政府統計の新規取得はestatを使う。架空の日常は作者の設定として明示。調査正本と無関係な制作物は保持する。
- Done when：同じ町の1900/1925/1945/1965/1985/2005/2026を見比べて意匠・密度・道路・移動・道具が見分けられ、住民の出発→用事→交流→帰宅が見える。全557系列と原値・欠測・出典がインタラクティブに読める。1900年の人口と出生・死亡を表示し、1975年以後の系列へ固定しない。歴史の全期間/年代/テーマ/地域/言葉をたどれる。複数回の実画面評価で残った主な問題を直す。

## 改善を評価する順序

1. 街の年代差、住民の日常、全期間グラフ、歴史の密度を実装する。
2. 代表年代の絵と90秒以上の連続観察、1900年代の値の選択、歴史検索、人物追跡を実操作し、次に見る理由が生まれるか評価する。
3. 評価で見つけた弱点を修正し、同じ観察コースでもう一度確かめる。機能の数だけで品質を判定しない。
4. 原値保持・史実/マクロ不変・分類境界・欠測・再現性・ルーチン適合を確認してから更新する。

PCの観察体験を主に検証する。小画面の網羅テストや配備作業に改善時間を偏らせない。公開済み作品の更新は既存Pagesで行い、元のアプリ以外を変更しない。

## なぜ前回見逃したか

資料の件数と形式、欠測の保持、操作可能性を主に判定して、年代ごとの絵の差と連続観察の報酬を受け入れ条件にしていなかった。サイドバーに死亡済みの人物が残り、町の現在と人物が離れる状態も見逃した。今回は年代比較画像、進行中の用事と目的地、1900–2026のグラフ、探す→読む→その年へ移る一連の流れを評価対象にする。

## 反復記録

改善前：1900/1965/2020の風景は家の屋根と数の小さな差に留まり、島の余白が大きい。人物は季節内で同じ行動を繰り返し、死亡後の選択も残る。統計グラフは点だけの画像で操作できず、人口の対象系列を切り替えると過去の系列が見えない。資料は長いダイアログの検索に集約され、時代全体をたどりにくい。

### 1回目：年代・日常・資料の骨格

7年代の建物と交通、朝から夜までの行動予定、全557系列のグラフ、独立した歴史一覧を実装。1900年の人口43,847,000と1975年の対象切替を原値のまま表示した。実画面では年代差が読めた一方、奥の建物が一列に並び、人物が小さく重なり、会話が相手のいない説明に留まる弱点が残った。

### 2回目：眺めて分かる用事と相手

建物を奥の街区・中段の店・手前の住宅/畑へ混在させ、地域ごとの果樹・茶畑・浜・灯台・橋を描いた。住民を大きくし、行き先と移動経路を表示。交流時には実際に生きている親族・同級生・近所の人を同じ場所と時間へ集める。一日の途中で年や予定が変わらない進行へ改め、通常速度で約96秒以上連続観察し、教える仕事→用事→顔なじみとの交流→翌年を確認した。

この評価で、毎年が冬のままになること、行動が8つの一般的な区分名に隠れること、死亡済みの追跡人物が現在の町と離れることを検出した。全期間グラフには四半期/半期の位置、空の期間から範囲外へ飛ぶ選択、比較時に横座標だけで点を選ぶ問題があり、いずれも修正した。

### 3回目：続けて見る理由と読みやすさ

年が進むと次の季節へ移り、人物の具体的な用事と時刻が予定表に並ぶ。存命の家族へ追跡を引き継ぎ、相手のいる交流、夜の灯り、夏の景色を実操作で確認。1900/1925/1945/1965/1985/2005/2026の同じ町をDOM実測1440×900で比較し、7つの意匠を記録した。

統計の選択値をグラフの上へ置き、ドラッグで1925–1970へ絞る→全期間へ戻す→1900年の町へ移る流れを実操作。1900年の出生1,420,534・死亡910,744の比較と、1945年の出生の原観測がない表示を確認した。歴史は追加210件で合計394記録とし、1970–2026の空白年を一次資料で補った。文化・道具・ゲーム・通信・働き方を含む。件数は独立した事件の数を意味せず、元の台帳の重複記録も保持する。

ファミリーコンピュータの検索→1983年の任天堂の沿革、1937年の小平の旅先→手紙を出す人物→大久保家の覚帳と確認限界、を実操作。歴史を読む間は停止し、同じ年の史実を月に隠さない一覧へ変更した。CSPで拒否されるHTML内のstyle指定もDOMのstyleプロパティへ変更し、正常系console warning/errorは0件となった。

### 4回目：公開画面でも観察を続ける

v0.3の公開画面で1985年夏18:39を再評価すると、交流グループを全て中央の狭い範囲へ置き、全住民に同じ白い会話印を描いていたため、人物の違いが再び読み取りにくくなっていた。公開成功を終了条件にせず追加修正した。

2〜4人の組を町全域の14会場へ振り分け、家々の前・庭先・店先・小広場で実際に同席させる。予定と移動の目的地そのものを分散し、会場名を行動と説明に反映した。全員の吹き出しを撤去し、会話印はグループごとに1つ、全体で最大4つ、互いの距離も確保する。見守る人物と実際の相手は向き・腕の反応・足元の輪と線で読めるようにした。

同じ1985年夏の交流を実画面で比較し、中央の密集がなくなり、石川誠と石川健が西の家々の前で向き合い、ほかの組が町の各所に分散することを確認。原史料の場面や全国模型の人数を変更していない。グラフにはドラッグ中の範囲の帯と年ラベルを追加し、実ドラッグで1925–1970へ拡大し、選択表示が残らないこととconsole warning/error 0件も確認した。比較画像は `verification/v03/pass4-distributed-meetings.png`。

## 今回の到達点と限界

65テスト・参照検査・build成功。全15,728原観測を55件のestat CLI取得記録と直接照合し、元のarchiveと統計の値・記号・対象は変更していない。新たな統計の取得は行わず、調査済み系列を閲覧できるようにした。建物の意匠、人物の一日と交流は作者の設定であり、実在地域の復元や個人追跡統計ではない。

主な確認対象はPCの観察体験。別ブラウザエンジン・実機スマートフォン・長時間のメモリ推移・第三者の継続プレイ評価は今回未確認。公開後を含む4回の評価で検出した主要問題を解消した段階を区切りとし、楽しさや品質の上限をテスト件数で証明したとは扱わない。

比較画像と実操作記録は `verification/v03/`、詳細な全画像はGit管理外の `evidence/browser/quality-loop/`。公開配備後のrunと同run成果物の照合結果は [Issue #175](https://github.com/hayatok/100challenge/issues/175) に記録する。
