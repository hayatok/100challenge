# まちの続き

## Goal / Context / Constraints / Done when

- Goal：家・店・道を配置し、住民の移動と時代ごとの目標を通じて、目的が分かる小さなまちづくりゲームを新規実装する。
- Context：ユーザーは「時代のとなりで」を使って何をすればよいか分からないと評価し、新規ゲームを依頼。方向の質問に「町の変化：家や店を配置し、時代ごとの課題を乗り越えるまちづくり」を選択した。
- Constraints：既存の調査台帳・閲覧アプリを保持。ローカル実装と検証まで、公開・配備・タグ作成なし。政府統計はestat取得値とreceiptを使う。史実と架空の町のゲームルールを区別する。UIに実装・台帳の作業文言を出さない。
- Done when：最初の一手が分かり、配置と道の接続に効果があり、3つの年代をクリアして結果と再挑戦へ至れる。グラフィック、住民の移動、配置前の費用と効果、失敗理由、戻す操作を備え、実ブラウザで完走する。

## 体験と構成

仮題「まちの続き」。最小版は架空の町の1955 / 1973 / 2000年。9×7の斜め視点の町を育て、店・仕事・通院・憩いの場所まで道をつなぐ。時代はプレイヤーが目標を達成して進める。現実の町の人口や家計を再現した統計モデルとはしない。

HTML/CSS/ES modules、手描き風の自作SVGグラフィック、Node標準のサーバー/build。新しいnpmライブラリは追加しない。ゲームモデルは純粋関数、描画は別ファイル。`npm run dev` / `npm run check` / `npm run build` を実装する。

game-design skillのframeworks / critique / systems / onboarding / guidance-and-feedbackを使う。グラフィックだけで楽しさを保証したと扱わず、目的・行動・結果が分かるか実操作で確認する。

## UIとゲームの検証

共通 `--ui-*` 配色を操作に使い、町は河川の青、屋根の朱、草木の緑のミニチュア画風。本文16px/1.6、44px以上の操作面、3pxフォーカス。タイトル・町・時代の達成・全体結果・ポーズ/設定の画面を一式で作る。フォントは端末の日本語システム/明朝体、配布フォントなし。

住民の行動、達成、予算不足、配置不能に文字と絵で反応する。自動進行や隠れた災害抽選は入れない。減らす動き・フォーカス喪失・ポーズで演出を止める。戻す/章やり直しを用意する。

1440pxと375pxを主に、1024/736/320pxでも表示と操作を確認。通常・予算不足・接続なし・配置不能・達成・再挑戦・保存/復元・不正保存を確認。テストは道の経路、予算/返却の不変条件、年代進行と実在データ照合に絞る。

## 分担

親エージェントが仕様・画面・統合・最終検証を担当する。独立した絵、モデル、既存史料の整理を並行担当に割り当てる場合は、ファイルを明記し同時編集しない。
