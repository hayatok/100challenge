# こはくの造形を元イラストへ合わせ直す

- Goal: 元のImageGenイラストの顔、髪型、体型、長い珊瑚色コートを3Dキャラクターへ反映する。
- Context: v2は細部が増えても美的品質が不足。ユーザーが求めるのは『空の軌跡 the 1st』『原神』『NTE』のような繊細で美しいアニメ調の人物。基準画像は`game/assets/yofukashi.png`の中央の女性。`art/reference/kohaku-turnaround-v3.png`はそこから作ったImageGen制作資料で、3Dモデルのレンダーではない。
- Constraints: コアゲームとマップは維持。Web/nativeを維持。元イラストの個性を優先し、参照ゲームのキャラクターを流用しない。既存blendと未保存セッションを保持。ユーザー指定のアニメ美少女の方向性は共通のコミカル表現より優先。
- Done when: 実際のBlenderモデルを正面・斜め・横顔と全身で比較し、元絵との相違を確認する。画像生成結果と実モデルを混同しない。採用できるモデルのみGodotへ組み込み、Web/nativeで描画と既存ゲームを検証する。

## 見逃した原因と再発防止

v2ではポリゴン数、パーツ数、ビルド成功を重視し、元絵と同じ人物に見えるかを合否条件にしていなかった。立体の目・鼻を貼り付けた顔、丸い毛束、短い丈の服で、別のキャラクターになっていた。

今後の人物制作では、ゲーム固有のアート指針で次を確認する。

1. 元絵と正面・斜めの顔を同じ大きさで比較する。目の突出、顎、鼻、目の間隔、髪の分け目を見る。
2. 正面・横・後ろで輪郭を確認する。前髪の厚み、頭と体の比率、コート丈、足元の重さを見る。
3. 材質は画像のようなアニメ表現を目指し、強いプラスチック反射で形状を覆わない。
4. 画像生成の制作資料、Blenderの実レンダー、Godotの実画面は区別する。
5. 構造検証・ビルド成功は美的品質の合格根拠にしない。ユーザーに却下されたモデルを「高品質な完成品」として扱わない。

この是正はLOOP EATER固有のため本書に記録する。編集中の共通`docs/DESIGN.md`は上書きしない。

## 現在の実装と残る差

- 新正本: `art/source/kohaku-v3.blend`。元絵に合わせた顔、短い前髪とまとめ髪、小さな円形アクセサリー、長い珊瑚色コート、暗いインナー・スカート・脚部。
- `game/assets/textures/kohaku-face-v3.png`と`kohaku-hair-v3.png`はbuilt-in ImageGenで生成。顔は連続したメッシュへUV投影し、髪は頭の丸みに沿う細い曲面へ描き込みを対応させる。プロンプトは`art/reference/PROMPTS-V3.md`。
- 輪郭・首・鼻筋・髪の側面を実レンダーで修正。EEVEEのプレビューとGodotのキャラクター専用シェーダーは、決まった方向の光に対して柔らかな段階状の陰影を付ける。照明全体は街のv2を継続。
- Godotの`?qa=portrait`をdebug専用の顔確認に追加。`?qa=art`は全身。releaseではQA指定は無効。
- 人体ベースも比較したが、顔つきが元絵から離れたため不採用。試験ファイルは無視対象の`.cache/`内のみ。配布モデルに第三者のキャラクターメッシュ・テクスチャは含めていない。

今回のモデルは造形改善の試作。元絵の繊細な髪の分かれ方、自然な衣服の折れ方、靴の構造・描き込み、表情の豊かさにはまだ差がある。参照された商用作品並みの完成品質とは評価していない。骨格スキニングと表情モーフも未実装で、移動は従来の分割パーツによる動き。

## 実画面で修正した書き出し・描画の問題

顔のUV名が`UVMap`、髪が`HairFlow`のままメッシュを結合すると、Godotで髪がUV0の同じ一点を読むため描き込みが消えた。エクスポーター内で有効なUV名を統一し、髪・顔のUVの範囲が一定以上あることも素材検査で確認する。UV属性の存在確認だけでは見逃せる不具合だった。

薄い両面の襟・毛束に反転したメッシュによる輪郭線を適用すると黒い面が前を覆った。輪郭用の追加描画は閉じた肌の面だけに限定した。これらはビルド成功後のGodot近景で検出した。

## 正本と書き出し

`create_kohaku_v3.py`は初回構築用で既存の正本を上書きしない。`refine_kohaku_v3.py`、`finish_kohaku_v3.py`、`finalize_kohaku_shading.py`、`refine_kohaku_profile.py`は今回の造形修正の記録であり、日常的に繰り返して適用するものではない。以後は保存済みblendを編集する。

`export_kohaku_v3.py`はblendを変更せず、Godot向けにUVと材質入力を変換してGLBを出力する。`review_kohaku_v3.py`は正本を変更せず正面・斜め・横・全身の実レンダーを保存する。

## 検証結果

- `npm run check`: 素材構造・保存原本ハッシュ・UV範囲・Godot構文解析・コア32項目・Web releaseが通過。`verification/v3-checks.txt`に結果を保存。
- `npm run build:debug`: 顔と全身のQA表示を確認。`npm run build:mac`: macOS release成功。
- Computer UseでWebの顔近景、全身、囲み成立→三択→回復選択→陣地・通常描画を確認。1024×768と1440×900。375×667と768×1024では既存の横向き案内の収まりを確認した。縦画面でのゲームプレイは対応していない。
- Webの読み込み表示、停止、強化、ゲーム状態とスクリーンショットを目視確認。確認中のconsole warning/errorは検出されなかった。
- macOS版を起動し、新モデルの通常描画、撤収、タイトル復帰を確認。ネイティブでの今回の近景比較は未実施。
- Blenderの原本を材質表示で開き、顔・髪の描き込みを確認。正面・斜め・横・全身の保存画像はすべて実メッシュのEEVEEレンダー。ImageGenの三面図とは別物。
- macOSの梱包用クリーンコピーはアドホック署名検証を通過。ZIPを更新。配布用の公証は未実施。

Safari/Firefox、モバイル実機、ゲームパッド実機、600体の長時間性能は今回未確認。美的品質は依然として改善中で、描画・ビルド検証と区別する。

macOS実行ログでもMetal 4.0 / Forward+ / Apple M5を確認。原本を開いた際に材質付きで見られるようBlenderの表示状態も保存し、その正本からGLBと両ビルドを再出力した。
