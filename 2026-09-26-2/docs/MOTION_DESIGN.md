# 演出仕様と品質基準

## 1. 比較対象

基準は[CELESTIAL CUT 02](https://hayatok.github.io/100challenge/2026-09-26/)。最初の版は「作例と比べると弱い」と指摘され、改訂版は「だいぶ良くなった」と評価された。この評価は、どの文章でも自動で高品質になることや、他モデルと同等の制作能力を証明するものではない。

参考投稿: [ユーザー提示のAya氏の作例](https://x.com/aiehon_aya/status/2103403361022419005?s=20)、[文字・図形の展開例](https://x.com/stephanlivera/status/2103315922098470926)、[UIの連続変形例](https://x.com/twoclipping/status/2103273003555402193)。視覚表現を分析するための参照であり、コード・音源・画像を取得して素材として組み込まない。投稿者が説明するモデル、制作回数、fpsなどは第三者の主張で、実装検証済みの仕様ではない。

## 2. 良くなった理由を機能に変える

| 避ける状態 | 必要な設計 |
| --- | --- |
| タイトルが出た後、数秒止まるだけ | 出現→展開→転換に役割を分ける。読む時間を保ちつつ、主役の大きさ・位置・形が変わる。 |
| 毎回同じワイプで切り替える | ハードカット、画面を覆う文字、連続する図形の変形、粒子の再集合を使い分ける。 |
| 星や月が背景の飾りにすぎない | 星が文字を作り、太陽が月になり、数字の一部が次のタイトルに残る。 |
| 粒子数や光で派手に見せるだけ | 文字の可読性、余白、明暗・大小の落差、カメラと文字の関係を先に整える。 |
| 一つの見た目を色替えで量産 | 場面構成、主役の位置、動く方向、密度、読みの間が異なる三つの構成を用意する。 |

## 3. 最初の一本の構成

120BPM、48拍、24秒。比較しやすいよう、初回のデータ化ではこの尺と大きな流れを維持する。境界の重なりは0拍。太陽→月などの連続変形はまずモジュール内で再現し、後に場面間のつなぎへ一般化する。

| 時刻 | 拍 | モジュール | 見せ場と読みの位置 |
| --- | --- | --- | --- |
| 0–4秒 | 0–8 | impact-type | THINKが縦に広がる→BEYONDが画面を使う→粒子が次のASTRAを予告。 |
| 4–8秒 | 8–16 | particle-flight | ASTRAを読ませる→輪郭の残像と接近→文字の内部を抜けて星空へ。 |
| 8–14秒 | 16–28 | radial-pulse | SOLのOと太陽が重なる→放射運動→日食と明暗反転。 |
| 14–18秒 | 28–36 | slice-orbit | LUNAの帯状組み立て→月相→奥行きのある軌道。 |
| 18–20秒 | 36–40 | three-up | ASTRA / SOL / LUNAを分割画面で再提示→回転するシャッター。 |
| 20–24秒 | 40–48 | particle-lockup | 粒子が6になる→6を残してGPT–6が組み上がる→名前と終止形。 |

既存コードにあるASTRAや6の直書きを、任意の文字列・強調文字の指定へ置き換える。同一フレームのバイト一致は要求しないが、見せ場、読める間、転換の滑らかさを失った簡易版では完了しない。

## 4. 演出モジュール

六つとも時刻だけで任意フレームを描ける。基本の文字レイアウト・配色・図形・seedを共通にし、演出の組み合わせに個性を持たせる。

| ID | パラメータ化する表現 | 入力条件と代替 |
| --- | --- | --- |
| impact-type | 複数語のサイズ・方向の切り替え、次場面の文字への粒子化 | 1〜3語、各12文字以内。長文は見出し2行の型へ切り替えるか編集を促す。 |
| particle-flight | 全文の字形マスクへの粒子集合、文字への接近、奥行きの流れ | 見出し1〜2行。読める区間を確保してから移動。ラテン文字以外も全文マスクを使う。 |
| radial-pulse | 太陽・同心円・放射状の変形と文字の掛け合い | 指定した一文字を円と関連付ける。Oがなければ指定文字の隣に独立した円を置く。円形文字を捏造しない。 |
| slice-orbit | 文字の帯状再構成、円・月相・投影された軌道 | 長い日本語は2行配置。上下が欠ける帯を最終状態に残さない。 |
| three-up | 3つの語句・図形を分割して提示、連動して閉じる | itemsはちょうど3個、各12文字以内。縦型は横3列ではなく縦3段。 |
| particle-lockup | 一文字へ集合→その位置を保ったまま見出しを構築 | 強調するgraphemeを一つ指定。文字が変わって範囲外になれば修正を要求。 |

モチーフは `celestial` と `geometric`。後者は点・円・線・面を使い、天体と関係のない内容にも使える。自由な画像・ロゴの取り込みや任意の輪郭同士のモーフは対象外。

## 5. 三つの構成レシピ

- **天体のティザー:** 大きな導入→対象ごとの紹介→三者の再提示→締め。接近と奥行き、円の継承を中心にする。CELESTIALが検証用の初期作例。
- **文字の宣言:** 二行の強い見出し→帯状の分解・再構成→短い主張→最後の一語へ集約。星空飛行を連打せず、面と文字の比率・改行・静かな余白で差を作る。
- **リズムで紹介:** 複数の短い特徴を拍ごとに見せる→放射と分割で比較→締め。位置を交互に変え、短いカットと読みの長いカットを組み合わせる。

構成レシピはコンパイル時に明示的な場面・演出・尺へ変換され、保存後はそれが正となる。同じモジュールが3回以上連続する案や、全場面が同じ位置・同じ倍率の案を初期提案しない。内容や文字量の適合条件を優先し、不適合な型を無理に適用しない。

## 6. つなぎの契約

モジュール内の演出と、場面間のつなぎは区別する。初期版の場面間つなぎは `cut` と `circle-match` の二つ。大量のトランジション一覧を先に作らない。

`circle-match` は、前場面の円と次場面の円を共通の正規化アンカーで結び、中心・半径・色を補間する。円を同時に二つ描かないよう、両場面の該当オブジェクトをマスクしてつなぎ側が描く。対象オブジェクトを持つ `radial-pulse` と `slice-orbit` の間だけを初期対応にする。0%と100%で通常描画につながり、境界で位置・大きさが跳ねないこと。

時間の計算は[データ契約](DATA_MODEL.md)に一本化する。モジュール側は `incomingTicks` / `outgoingTicks` を受け取り、入場演出を二重に行わず、読む区間を残す。非対応ペアに変更するときは、カットへの変更と尺の変化を表示して適用する。

## 7. 読み・比率・品質

- 基本は画面端から短辺の6%を読ませる文字の安全域とする。意図したクロップや通過は転換中だけ許容し、全文を読める区間を別に置く。
- 見出しの静かな読みの時間は最低0.7秒を目安とし、長い日本語では増やす。補足文が読めない尺なら警告し、読了速度を保証する表現はしない。
- 日本語の禁則・改行、英単語の分割、濁点・結合文字・絵文字の単位を考慮する。非対応グリフは出力前に知らせる。
- 各モジュールが比率ごとのレイアウトを持つ。9:16では余った高さを活かし、文字を縮めただけの中央の小さな作品にしない。
- 点滅の連打を使わず、明暗の切り替えは意味のある場面境界に限定する。強さ設定で密度・移動量を調整する。
- エクスポート時の残像は必要な場面だけに用いる。時間をずらした数サンプルの描画による表現で、全フレームを重くすることを品質と取り違えない。

最終レビューでは各場面を最低3時刻と転換前後で確認し、さらに実時間で一本を通して見る。静止画だけでリズムや演出の完成を判断しない。
