## 2. 自動テスト

実装に似せたテストを大量に作るより、破綻すると映像や保存が失われる境界を重点的に確認する。

- **schema:** 型、範囲、重複id、未知version、oversize、items数、強調文字の範囲、末尾transition、不正な総尺を拒否。
- **時間:** 重なりなし/あり、BPM端数秒、境界の半開区間、全体終端、三場面重なり拒否。フレーム数と音声長の丸めが一貫する。
- **文字:** 日本語、Latin、改行、長文、結合文字、範囲外グリフ。フォント準備前に出力できない。変更した文字の再ロードを検証。
- **決定性:** 同じrendererで6.75秒→15.2秒→6.75秒が一致。別rendererでも同じ条件で一致。プレビューと出力の同時使用で混線しない。同じ環境でのpixel比較とし、OS間の字形ラスタライズ差は区別。
- **編集:** 一操作のUndo/Redo、並べ替え、削除、再構成、履歴上限、スライダー一操作化。本文を再構成が勝手に変更しない。
- **保存:** JSON round-trip、不正入力時の現状維持、遅い旧revisionの上書き防止、複数タブ競合、quotaエラーからJSON退避。
- **出力:** キャンセルとfinalizeの競合、source失敗時の解放、重複開始防止、音声codecなし時の明示的選択、再試行。
- **HTML:** `</script><script>…`、引用符、`<img onerror=…>`等の文字列が表示データのままで、実行されない。外部asset URLが残っていない。

## 3. 実ブラウザ・実ファイル

最低基準は一つの実デスクトップChromium環境。ブラウザ版、OS、画面、CPU/RAM、codec、出力設定を記録する。他ブラウザは実測と未確認を区別する。

1. 375 / 768 / 1024 / 1440pxで、文章入力、場面追加、並べ替え、調整、保存、出力を操作する。文字欠け・重なり・横あふれ・主要操作の到達性を確認し、スクリーンショットを実際に見る。
2. Canvas内の16:9 / 9:16はUIの画面幅とは別に確認する。演出ごとに出現・読み・転換の3時刻以上を撮り、境界の直前・直後も見る。
3. Space・矢印・Tab、入力欄のキー操作、Undo/Redo、reduced motion、タブ移動、全画面を確認する。
4. MP4をダウンロード後に開き、ffprobe等でcodec、幅/高さ、duration、fps、frame count、audio trackを確認する。複数時刻の画像を復号し、プレビューとの相違を点検する。圧縮出力にpixel完全一致を要求しない。
5. 音付き作品を実際に聴く。冒頭、各場面境界、シーク後、終端のクリック・音割れ・同期ずれを確認する。数値の波形テストだけでは聴感を通過にしない。
6. HTMLはローカルHTTP、ネットワークを切った状態、可能ならfile://で開く。file://がツールに拒否された場合は制約を記録し、回避を試みない。必要な実機確認を未確認として残す。
7. キャンセルは準備中・中盤・finalize直前で試す。完了との競合時には最終状態が一つだけとなり、次の出力ができる。

音画の同期はタイムライン由来のcue時刻を基準に確認する。AAC等のencoder primingやmuxの時間表現を考慮し、聴覚上のずれと実タイムスタンプを両方記録する。単純なファイルサイズの一致を同期の証拠にしない。

## 4. 入力fixture

- 基準: CELESTIAL / ASTRA / SOL / LUNA / GPT–6。
- 短い日本語: 「ひらめきを」「動かそう」「言葉が、映像になる」。
- 長め: 「まだ見たことのない景色へ」＋補足文。「文字の宣言」の複数行で読む時間を確認。
- 英文: `MAKE IDEAS MOVE`、幅の違う `IIII` / `WWWW`。
- 結合文字・記号: `Café`、`GPT–6`、引用符、全角括弧、改行。
- 非対応確認: 絵文字、稀な漢字、未知のフォント指定。表示できると決めつけず検出・警告を確認。
- 総尺: 4秒の最小、24秒の基準、60秒の最大、上限超過、BPM 123の端数フレーム。

## 5. 性能と品質

基準機で720pプレビュー30fpsを目標にする。frame処理のp95と長い停止、字体準備時間、24秒/60秒の出力時間、ピークメモリを記録する。単に「高速」と書かない。プレビューだけ粒子数や残像サンプル数を下げる場合も、配置・時刻・文字を変えない。

1080p動画の残像サンプル数を増やす前に、まず1サンプルで通す。必要な場面に最大4サンプルなどの上限を設け、生成時間と改善を比較する。WebCodecsに渡す前に必要以上のフレームを保持しない。

目視レビュー項目: 全文が読めるか / 主役が分かるか / 同じ出方ばかりでないか / 場面をまたぐつながりがあるか / 読む時間と動く時間の対比があるか / 別の文章でも同じ質を保てるか。元作品より明らかに弱い点は不具合として残し、演出数だけで完了判定しない。

## 6. コマンドの契約

新アプリのpackage.jsonに以下を用意し、その実在と役割をREADMEに書く。

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
```

`npm run check` は当該アプリの上記検証をまとめる。ブラウザ依存やfixture準備が必要ならsetup手順を明示する。rootの `npm test` は共有スクリプトの検証であり、このアプリの動作証明にはならない。

資料だけの現在の変更では、リンク、JSON構造・尺、差分の整合性を確認する。アプリ用のbuildやE2Eがないため、それらの実行成功を報告しない。
