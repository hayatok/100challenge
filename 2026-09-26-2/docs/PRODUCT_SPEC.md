# プロダクト仕様

## 1. 作りたい道具

短いコピーと場面構成から、文字・図形・カメラ・場面転換が連動した4〜60秒の動画を作る。完成した一本を複製して文章や色を替え、新製品のティザー、イベント告知、動画のオープニングなどに使う。

「同じ文字箱の背景を替える」「文章を順にフェード表示する」だけでは目的を満たさない。文字の見え方、画面内の位置、場面の密度、図形との関係が時間とともに変化し、読み取るための静かな時間もあること。

## 2. 初回の利用手順

1. 「作例を編集」または「文章から作る」を選ぶ。初期画面で作例を再生できる。自動再生はしない。
2. 動画の名前、画面比率、場面ごとの見出し・補足文を入れる。場面は「導入・紹介・まとめ・締め」の役割を選ぶ。改行区切りの貼り付けも可能だが、一行一場面として確認してから取り込む。
3. 「天体のティザー」「文字の宣言」「リズムで紹介」の演出構成から一つ選び、「映像を組む」を押す。
4. 一つの案をすぐ再生する。場面の文章、長さ、演出、色、強弱を調整し、順番を変える。
5. 全体再生で読みやすさとつながりを確認し、HTMLまたは動画を書き出す。JSON保存と作品の複製もできる。

初期版は**ルールで演出を組み立てる**。入力文の内容を理解するAIや、自由な指示から未知の演出を発明する機能は含まない。「AI生成」と表示しない。文章から作るとは、入力した場面の役割・文字量・選択した構成に応じて、用意された演出を選び配置すること。

## 3. 初期版の範囲

| 項目 | 必須仕様 |
| --- | --- |
| プロジェクト | 新規、作例から作成、複製、名前変更、削除、自動保存、JSON書き出し・読み込み |
| 構成 | 2〜12場面、全体4〜60秒。BPM 60〜180の整数。場面ごとの長さは2〜32拍、0.5拍単位。秒表示も併記する。 |
| 入力 | 日本語・英語の見出し、任意の補足文。例外的に三分割・導入で複数の短い語句を使用。文字数・適用条件はデータ契約に従う。 |
| 演出 | 6種類の演出モジュール、3種類の構成レシピ。少なくとも一つの図形の連続変形でつながる場面転換。 |
| 調整 | 場面の追加・複製・削除・並べ替え、文章、演出の選択、長さ、全体BPM、パレット、動きの強弱、文字サイズの範囲調整、改行 |
| 再生 | 再生・一時停止、最初から、シーク、場面ジャンプ、全画面、音ON/OFF。既定は音OFF。 |
| 履歴 | Undo/Redo。最大50操作。スライダーの一回のドラッグは一操作。再生位置と選択場面は履歴に入れない。 |
| 比率 | 16:9と9:16。文字・図形を各比率用に再配置する。横長映像の中央を切り取る方式にしない。 |
| 音 | 無音または独自シンセの一種類。BPM・切り替え・アクセントと同期。外部の音楽ファイルは初期版に含めない。 |
| 出力 | 単体HTML、MP4、選択時刻のPNG、プロジェクトJSON。対応外環境でWebMを代替提案する。 |

動画の標準は30fps。16:9は1920×1080、9:16は1080×1920。軽量出力として1280×720 / 720×1280も用意する。60fps、正方形、透過動画、4Kは後続候補。

## 4. 構成を作り直すときの扱い

- 「映像を組む」は新規草案を作る。入力した文章を勝手に言い換えたり、補足文を追加したりしない。
- 生成後の編集は確定したプロジェクトデータに対して行う。保存・再読み込みのたびに演出を抽選し直さない。
- 再構成は現在の編集を置き換えるため、変更点を示して適用する。取り消し可能にする。変更のない初回に確認ダイアログは不要。
- 一場面の演出変更は他の場面の文章・色・長さを保持する。不適合のつなぎは警告を表示し、カットへの変更と尺の差を明示する。
- 同じ文章・構成・seedなら同じ初期案になる。「別案」はseedを明示的に変えた新しい案。大量の候補を同時自動再生しない。

## 5. 画面

デスクトップでは、左に文章と場面リスト、中央に大きなプレビュー、右に選択場面の設定、下に場面単位の時間軸。主操作は「再生」と「書き出す」。タイムラインは場面の長さ・つなぎを見せるためのもので、初期版にレイヤートラックやベジェカーブ編集は設けない。

375pxではプレビューを上に置き、下を「文章 / 場面 / 調整」の切り替えにする。書き出し操作を常に探せる位置に置く。場面の並べ替えにはドラッグだけでなく「前へ / 後ろへ」を提供する。768px、1024pxでも設定欄と再生操作を押しつぶさない。

UIはルートの共通方針に従い、読みやすいシステムフォント、明瞭な輪郭、フラットな面、最小限の硬い影を使う。文字の版を差し替える「編集机」をモチーフにするが、常時動く飾りは置かない。既存アプリのトークン・操作部品を確認してから実装する。

**作品のCanvas内は別の表現領域。** 大きな文字、画面外からの進入、粒子、反転、2.5D表現は作品の目的に必要な例外として許容する。エディタのフォームまで映像と同じように揺らさない。

## 6. 状態と回復

| 状態 | 表示・回復 |
| --- | --- |
| 空の入力 | 作例と入力例を提示。「映像を組む」は必須の見出しが揃うまで無効。 |
| 文字が収まらない | 対象場面を明示。「改行」「複数行対応の演出」「文を短くする」を提示。無断の省略や極端な縮小をしない。 |
| フォント準備中 / 失敗 | 準備状況を表示し、描画確定・出力を待つ。失敗時は再試行。別フォントへの変更はユーザー操作にする。 |
| 保存中 / 保存済み / 保存失敗 | 自動保存状態を表示。失敗しても編集データをメモリに保持し、JSONで退避できる。 |
| 不正なJSON / 未対応バージョン | 理由を提示し、現在の作品を維持する。元データを上書きしない。 |
| 出力準備中 / 出力中 | 形式、解像度、音声の有無、進捗、キャンセルを表示。二重開始しない。 |
| MP4や音声codec非対応 | 実際の機能判定後、無音MP4・WebM・HTMLなど可能な選択を提示。勝手に音を削除しない。 |
| キャンセル / メモリ不足 / 失敗 | 中途半端なファイルを成功扱いで渡さない。処理を解放し、低解像度や別形式で再試行可能にする。 |
| 完了 | 実ファイルのダウンロード操作と形式・尺・サイズを表示。再生確認しやすくする。 |

reduced motionではUIの動きを減らし、作品も自動再生しない。明示的に再生した場合は作品本来の動きを表示する。画面を離れたらプレビューは停止。音声開始はユーザー操作を必要とする。入力欄でSpaceや矢印を押したときに再生ショートカットが割り込まない。

## 7. 含めないもの

初期版にログイン、共同編集、クラウド保存、LLM API、動画素材の編集、ナレーション、外部BGM、任意JS/HTMLの実行、自由な図形・パス・キーフレーム編集、SNSへの自動投稿は含めない。将来の生成AI連携は、同じ検証済みJSONを受け取る入口として追加できる設計に留める。

GitHub Pagesへのアプリ公開は開発完了とは別作業。この資料では公開を実行・承認していない。
