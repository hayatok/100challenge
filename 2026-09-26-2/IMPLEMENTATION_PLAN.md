# 実装計画 — 一本の完成を先に証明する

各段階の実行内容・実測・スクリーンショット・実ファイル・未確認事項は [検証結果](docs/verification/RESULTS.md) に記録した。この文書は実装前に決めた順序と通過条件を残す。

## M0: 現物を理解する

1. ルートのAGENTSとデザイン文書、本資料を読む。git statusと作業対象を確認する。
2. 公開CELESTIALを実際に再生し、場面・文字・転換・シークを確認する。元のfilm.js / score.js / player.jsと対応させる。
3. Moving Cover Studioのfonts・動画出力・保存・UI部品を読む。再利用するロジックと、今回変える必要のある責務を短く記録する。
4. 新アプリ内に最小のVite/React/TypeScript構成と固定依存を作る。既存の作品は変更しない。公開登録はしない。

**通過条件:** 起動、型チェック、空のアプリbuildが通る。次に何を再現するか、既存コードとの差が明確。多数のダミーUIを先に作らない。

## M1: 編集可能な一本と、本物の出力

1. データ契約、整数ticksのコンパイラ、フォント準備、インスタンス型rendererを実装する。
2. CELESTIALの六つの場面をデータ駆動へ移す。最初は16:9・120BPM・24秒で固定して品質を比較する。
3. 開発用の最小画面で文字を書き換え、再描画・シークできるようにする。全文の文字マスク、強調文字、次場面の予告をデータから解決する。
4. 単体HTMLと30fps無音MP4を出す。続けてPCM合成と音声付きMP4を通す。エンコードだけでなく、ファイルを開いて全編を確認する。
5. CELESTIAL以外の日本語コピーに置き換えた一本も、同じ経路で出力する。

**通過条件:** JSON→描画→HTML/MP4が通り、文字差し替え後も読み・転換・終止形が成立する。元作品の粒子・接近・日食・帯文字・6の継承を、単なるフェードや静止画に簡略化していない。プレビューと動画を比較した証拠がある。

この段階で質が弱い場合は演出と文字レイアウトを修正する。編集パネルや演出数を増やして品質不足を埋めない。

## M2: 文章から構成を作り、つなぎを編集する

1. 役割・文字量・選択構成からProjectを作るdirectorを実装する。文章は変更しない。
2. 三つの構成レシピを実装。同じ文章を三構成で作り、配置・動き・尺の差を確認する。
3. 場面の追加・複製・並べ替え・削除、BPMと長さ変更を実装する。
4. radial-pulse→slice-orbitにcircle-matchを実装し、重なり時間、アンカー、音のcueを統合する。
5. 9:16のレイアウトを全モジュールに実装。日本語の短文・長文・改行の調整と警告を揃える。

**通過条件:** 別の内容・尺・比率でも編集できる。24秒の作例以外に、15〜30秒の日本語作品と、60秒の上限作品を出力できる。場面を変えても音やシークが旧位置のまま残らない。

## M3: 日常的に使える編集体験

1. 文章入力、場面リスト、大きなプレビュー、調整欄、場面時間軸を組む。
2. Undo/Redo、複製、IndexedDB自動保存、JSON round-trip、保存失敗の退避を実装。
3. 文字あふれ、フォント失敗、非対応codec、進捗、キャンセル、復帰をつなぐ。
4. キーボード、reduced motion、375/768/1024/1440pxの操作を確認する。

**通過条件:** 初見でも文章入力→調整→出力へ進める。保存・復元・出力失敗で作品が失われない。再読み込み後に同じ作品を再編集できる。

## M4: 品質と出力の受け入れ確認

[TEST_PLAN.md](docs/TEST_PLAN.md)を実行する。特に全編再生、実ファイルの復号、音声の聴感、別文章、縦型、キャンセル後の再出力を省かない。各チェックをpass/fail/未確認で記録する。対応端末・実際のcodec・残る制限もREADMEに書く。

**通過条件:** 必須条件を満たし、既知の制限が説明されている。実装済みと言える根拠が揃う。公開はまだ実行しない。

## M5: 後続の候補（初期版の範囲外）

優先候補は外部BGM一曲の取り込み、JSONを出力するLLMとの接続、演出モジュールの追加。自由なキーフレーム編集、画像/ロゴ、ナレーション、4K/60fps、透過、クラウドレンダリングは利用を見て判断する。初期設計を先回りして大きなプラグイン基盤にしない。

## 品質上の主要リスク

| リスク | 先に確かめること |
| --- | --- |
| 文字を変えると映像が崩れる | M1で日本語を含む別コピーを使う。ASTRAや6専用の座標・タイミングを残さない。 |
| 綺麗な作例だけ作れて量産できない | M2で役割と文字量から三構成を作り、編集しても破綻しないか確認する。 |
| HTMLだけ動いてMP4が出ない | M1の時点で実ファイルを出す。対応判定だけを完了条件にしない。 |
| 音声と映像のmuxが停止する | まず短尺の音付き出力で採用APIを確認し、24秒と60秒へ広げる。 |
| プレビューと出力が違う | 同じrendererを使い、同時刻のフレームを比較する。フォント完了前に出力しない。 |
| 画面全体が編集ツールの設定だらけになる | 基本操作を文章・場面・調整に限定し、詳細パラメータを先に大量公開しない。 |

判断を変えた場合は「変更理由 / ユーザーへの影響 / 代わりの検証」をこのフォルダに残す。承認済みの制作入口やHyperFrames不使用を黙って変えない。
