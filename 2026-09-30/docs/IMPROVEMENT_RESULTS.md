# 暮らしと自然をつなぐ改善の確認記録

2026-10-01。対象は [IMPROVEMENT_PLAN.md](./IMPROVEMENT_PLAN.md)。初版のRESULTS.mdとscreenshotsは今回の挙動の検証証拠ではない。

## 実装

- 活動人口に住まいと道路で届く働き先・買い物先を割り当て、連続した位置、経路、滞在、到着を保持。道一区間の往復演出を廃止。世帯ごとに朝の出発、仕事の滞在、午後の買い物の時刻をずらし、一斉に道が空になる動きを抑える。
- 通勤到着、来店、定員と到達性、土の水分・養分、作物の生育と収穫を家の活力・建物の維持・新築需要に結び付けた。収穫には到着した働き手が必要。
- 建物は需要が続いたときに拡張し、使われ維持される建物は年数だけでは消えない。工事を進捗として示す。草から若木へ緑が回復する。
- 4週続く天候、滑らかな年間気温、土の水分と肥沃度。150秒の一日の生活時計と、4秒/週の土地更新を同じ固定更新ループ内で進める。
- 丸い樹冠と春の花、パステルの屋根、庭の柵と花、帽子・かばんを持つ住民。建物や木の画素ごとの前後関係を使って住民を遮蔽する。季節色は週数に応じて補間。
- 住民の追跡と経路表示、職場・住まいの観察、雇用と食・来店の表示。初期表示は集落を拡大し、「全体を見る」で俯瞰へ戻れる。
- V1の町の記録を検証してV2へ移行。新形式は土と暮らし、住民の旅と単調増加する番号も保存する。

## 実施した確認

- アプリの `npm run lint` 成功。
- アプリの `npm run build` 成功（内部の `npm run typecheck` も成功）。
- 別担当による読み取りレビューで、家の跡地が変わったときの保存不可、家を失った住民の雇用割当、住民番号の再利用、無人の畑からの収穫を指摘し修正。修正後の読み取りレビューで当該問題なし。
- 最初のActionsで保存後の比較1件が失敗。復元した内容は同じでもJSONの項目順が異なっていたため、保存時の項目順を固定する処理を追加した。
- 既存テストを新しい住民時計と保存形式・維持方針へ更新。ユーザーの以前のテスト不要という指示を尊重し、ローカルのテストランナーと長期実測は実行していない。

- 改善コミット `af9d626` の [GitHub Actions](https://github.com/hayatok/100challenge/actions/runs/36816660886) で、共有38件・アプリ16件のテスト、lint、型チェック、build成功。

- 改善版の実画面、デスクトップ/モバイル表示、住民の連続した歩行の見え方、追跡操作、写真保存、実際のストレージ移行、背景タブの復帰は未確認。型チェック・ビルド成功を操作確認の代わりに扱わない。
- 長期の人口と食のバランス、端末での速度、Safari/Firefox/スマートフォン実機は未確認。第三者による観察の楽しさの評価も未実施。
- 働き手は世帯人口のおよそ半分をモデル化。食は収穫と消費の量の目安。住民の年齢、賃金や価格、商品の個別配送、河川の物理流体計算は含まない。街と自然の因果関係を観察するための小さなモデル。
- 公開、リリースタグ、PRのマージはこの改善作業の対象外。
