## 目指す遊び

**「恵みも災いも与えられる、小さな世界の神様」**。勝敗や最高人口の達成は求めない。小さな一手から、住民の移動・生活・建物・自然へ波及する変化を見届ける。

循環は「町を見る → 場所と力を選ぶ → 世界に働きかける → 住民と土地の反応を見る → 別の未来を試す」。雨を押せば人口が増える、といった直結ボタンにはしない。雨は土を潤すが、人が来ない畑は収穫できず、橋が壊れた地区へ食料は届かない。

同じ雨でも、乾いた高台と、すでに浸水している川沿いでは結末が変わる。同じ隕石でも、働き先を失う町と、橋を失って孤立する町では荒廃の順序が変わる。違いを見つけることを繰り返し遊ぶ理由とする。

自由な実験では、力を縛って「正解」を作るより、世界の反応を深くする。信仰・マナ・課金・ランキング・義務的なミッションは今回の案へ入れない。制約付き復興チャレンジは将来候補へ退ける。

## 天候・災害の構成

地震と隕石は天候とは別の災害として扱う。雷は空全体の天候名だけではなく、雷雲から地面へ起こる地点イベントにする。自然発生も神の介入も、同じ水分・風・損傷・火災などの状態へ作用させる。

| 現象 | 目に見える変化 | 暮らしと自然への作用 |
| --- | --- | --- |
| 晴れ | 日差し、影、乾く地面、外出 | 蒸発が増える。適量の水分なら作物が育つ。晴れ続きは乾燥・収穫減 |
| 曇り | 雲が流れ、影と色が柔らかくなる | 蒸発が抑えられる。雲量と気温で作物の生育が変わる |
| 雨 | 局地的な雨雲、濡れた屋根、水たまり、傘 | 土の水分回復、作物の成長、外出の減少。続き過ぎると浸水・作物被害 |
| 雪・寒波 | 積雪、白い畑、窓の明かり | 作物の休眠、歩行の遅れ、生活負担。既存の雪を維持して深化 |
| 嵐・豪雨 | 風向きのある雲、揺れる木、増水、倒木 | 作物・建物への損傷、道路封鎖、橋の破損、避難。濡れた土地は回復に時間がかかる |
| 雷 | 落ちる地点の閃光、焦げた木、局所火災 | 建物損傷と着火。乾燥・風・燃料で延焼。雨や川で火が弱まる |
| 地震 | 地面の揺れ、ひび、屋根と橋の崩れ | 建物状態と地盤に応じた倒壊、経路分断、住居・職場喪失。天気に関係なく起こせる |
| 隕石 | 空から軌跡、着弾、クレーター、煙 | 半径と距離に応じた破壊、火災、土地の変化。大規模なら街全体の生活が崩れる |
| 終末規模 | 巨大隕石や隕石群、広域の火災、灰が積もる空 | 全人口・全建物の喪失も許す。その後も自然と時間は進む |

軽度・中度・大災害・終末は、現象ごとの原因計算から共通の損傷・通行・避難状態へ作用させる。規模・持続時間を変えて結果を広げるが、「雨量を上げれば地震になる」という共通強度にはしない。異なる現象ごとに、効果範囲・強さ・期間を持つ。

自然発生の標準設定は穏やか。日常の天候とまれな局地災害がある程度とし、何も操作しない観察を成立させる。「自然災害なし／穏やか／荒れる世界」などの設定を提案する。無予告の滅亡級災害は標準にしない。荒れる世界で終末級の自然発生を有効にする場合も、設定で選べるようにする。

## 神様の操作

操作の共通形は「力 → 場所 → 範囲・強さ・期間 → 実行」。日常の観察、住民選択、ドラッグ移動との誤操作を避けるため、力を選んだときだけ介入モードへ入る。Escapeや「観察へ戻る」で解除。

| 力 | 用途 | 効果が出ない・逆の結果になる条件 |
| --- | --- | --- |
| 恵みの雨 | 土を潤す、作物を育てる、火を消す | 働き手がいないと収穫できない。過剰な雨は洪水になる |
| 日差し・雨雲を払う | 土や道路を乾かす、降雨を終える | 乾燥を強めると作物が枯れ、火災の危険が増える |
| 嵐を呼ぶ・風を動かす | 広い範囲の自然と街の反応を試す | 地形・道路の依存関係で、離れた地区も孤立する |
| 雷を落とす | 局所の損傷・着火を観察する | 濡れた場所では火が広がりにくい |
| 地を揺らす | 崩壊と避難、交通の変化を観察する | 建物状態や橋への依存で被害と復興が異なる |
| 隕石を落とす | 小さな穴から世界規模の破壊まで試す | 直接の着弾範囲外にも火・物流断絶・移住が波及する |
| 芽吹きを与える | 草・若木と土の再生を後押しする | 植林だけでは人も資材も家も復活しない |
| 新しい入植者を迎える | 滅亡後、回復した土地に暮らしを再開する | 入植者は食・仮住居・道具を持参する。危険な土地や、持参した備蓄を使い切るまでに自給できない場所では定住が難しい |

制限のない使用を前提とするが、結果を無視した万能回復にはしない。雨・地震・隕石を重ねれば、その量が実際の状態へ積み重なる。同じ場所への入力は結果が変わらない操作に限って性能のためにまとめられる。非線形な延焼・倒壊を勝手に加算へ置き換えず、見かけ上の使用回数制限や隠れた無効化にはしない。

範囲は地図上の円・領域で表示し、直接影響する家・畑・橋の見込み数を出す。二次被害まで確定値として約束しない。タッチでは場所を選んでプレビューし、常に同じ位置の「ここへ使う」で実行。デスクトップも同じ操作を基本にし、ドラッグとの競合を避ける。

通常の使用で確認ダイアログを繰り返さない。選んだ力と設定を保持し、観察へ戻るまでは次の地点へ同じ力を続けて使える。隕石の終末規模は明示的な強さの選択と範囲表示で区別し、不用意なタップで選ばれない。力の解除は世界の巻き戻しとは別操作。

適用直前の世界を保存し、「前の介入の適用前へ戻る」で、その後の未来全体を巻き戻せるようにする。未適用の予約取消は命令の除去。停止中に複数の力を予約した場合、同じ固定ステップで適用される一組を復元の単位とし、範囲・予約件数と「この組の前へ戻る」を表示する。各命令の順序は固定し、予約取消と世界の復元を混同しない。

## 暮らしのシミュレーション

### 人口と住民

目標は人物1人を住民1人として扱うこと。総人口は「住まいに属する人＋避難中・仮住まい・移住途上の人」の集計とし、住宅のレベル変更から直接人口を書き換えない。住宅段階は収容人数・快適さ・修繕負担へ作用する。

最初に必要なのは住まい、働き先、食の充足、安全、健康、現在の行動。名前と同じ住民IDを保持して、家がなくなった人を追えるようにする。年齢ごとの複雑な人生・人間関係・細かな家計は後段へ回す。まず働く人と扶養される人を区別し、人口全員を常時通勤させない。

出生・流入・流出・死亡は別の出来事として集計する。「人口が減った」だけでなく「住宅不足で転出」「避難して隣の地区へ」「食不足が続き健康が悪化」「倒壊被害」を説明できるようにする。被害は人物の消失だけでなく、避難・休業・生活の立て直しで見せる。かわいい画風を保ち、損傷と喪失を流血表現へ頼らない。

### 食・仕事・資材

資源はまず食料と修繕資材の二つ。農地は実際に届いた労働と水分・気温・土から食料を作り、工場は労働で修繕資材を作る。小さな倉庫・店は備蓄と購入を扱う。物流は道路の接続と所要時間に制約され、橋が切れれば川向こうの在庫を無条件に使えない。

購入は在庫があって初めて成功する。来店・購入・供給不足を分けて記録。住民が食事をすることで食が減り、食不足が続くと健康・労働・定住が順に弱る。最初の不足で一斉に消える仕様にはせず、備蓄と猶予を設ける。移住先も不足していれば移住が常に成功するとは扱わない。

各区画の在庫をAで導入し、接続地区間の輸送と分断時の配給停止をBまでに実装する。その後Cで可視化する搬送役を追加する。初段階の地区内分配は抽象化と明記し、運送まで個別に再現したとは扱わない。旧来の世界共有の食料箱は、橋を壊す実験ができる段階までに置き換える。

修繕・建設は需要だけで進めず、到着した作業者・資材・安全な通路を必要とする。利便性が高く食の供給が安定した地区へ住民が移り、その需要で住宅・店・道路が育つ。飢饉・仕事喪失・汚染・孤立が続く地区では転出、休業、修繕の停滞が起きる。

生産・消費・輸送・移住候補は同じ更新前状態から求め、最後に一括で反映する。資源の総要求量は在庫以下へ公平に配分し、同量の要求の順序は安定したIDなどで固定する。生産・消費・損失・輸送中の資源を記録して収支を一致させる。セルの並び順で、同じ週の収穫を受け取れる家と受け取れない家が生まれる現在の問題をなくす。

### 発展・荒廃・復興の見え方

| 状態 | 街の絵と住民の行動 |
| --- | --- |
| 発展 | 足場と資材、建物の増築、住民の到着、店に並ぶ商品、庭と灯りが増える |
| 不調 | 店の商品と客が減る、畑の働き手が減る、外壁が傷む、仕事を探す人が移動する |
| 被災 | 浸水・煙・崩れた屋根・壊れた橋、危険を避ける人、避難所へ集まる人 |
| 荒廃 | 窓の灯りが消える、屋根が欠ける、休業看板、草の生えた道、地区の人口が抜ける |
| 復興 | 水が引く、瓦礫を運ぶ人、橋の修復、仮住まい、店の再開、帰還する住民 |
| 自然の再生 | 焼け跡から草が生え、若木が育ち、クレーターに水が溜まり、森へ戻る |

建物段階は今の最大3からむやみに増やす前に、生活の活動と傷みを描き分ける。住宅を高層化することだけを成長にしない。町ごとに農業・商業・工業の活動が異なる景観になるようにする。

## 災害後の因果と滅亡

代表例は「嵐 → 増水 → 橋の損傷 → 道路が使えない → 仕事と食が届かない → 避難・休業 → 修復 → 帰還」。破壊が起きた瞬間と、後から弱る地区を区別する。雨が止んでも、道路や家が即時に新品へ戻ることはない。

損壊した家の住民は、健康な近隣住宅・仮の避難拠点・域外の順で行き先を探す。安全な場所へ歩けなければ立ち往生として記録し、存在しない道を歩いたり、家の削除と同時に瞬間移動したりしない。隕石直撃などで亡くなった住民と、避難した住民を分ける。

全滅は自由な実験の正当な結果として許す。「世界滅亡」はこの箱庭の社会が消滅することと定義し、実行ループが止まることとは分ける。人口0でも水・火・植生は更新する。勝手に新住民を生み、被害を帳消しにすることはしない。

滅亡後は「災害前へ戻る」「自然の回復を見る」「新しい入植者を迎える」「別の町を作る」を選べる。入植者は最低限の食・資材・仮住居・道具を持参し、神が選んだ地点から暮らしを始める。住民がいないから収穫できず、食がないから入植できない循環にはしない。危険な地点も事前に説明し、到着後の生存と定住は通常の因果へ委ねる。植林・雨・土の再生を通じた再出発にも観察の余地を残す。元の町の記録は新しい世界の作成だけで無断に上書きしない。

現行AGENTSの「全滅して停止する吸収状態を避ける」は、実装時に「自然と操作は全滅後も継続し、神の介入または明示的に選んだ終末自然災害による社会の滅亡を許す」と具体化する。今回のユーザー依頼が従来の全滅回避・観察のみという範囲を拡張している。

## 土地・時刻・更新の契約案

- 地形は基礎の標高・土と、浸水・火・積雪・瓦礫の上層状態を分ける。浸水した住宅を即座に`water`へ置換しない。隕石のクレーターは標高と地表へ作用する。
- 水は簡易な格子モデルで低い隣接地へ移動し、河川流出・浸透・蒸発を持つ。雨→水量→浸水→損傷の関係を確認する。実河川の物理流体予測を名乗らない。
- 道路の存在と通行可能性を分ける。破壊・水深・火災により使えなくなった区間を再判定。セル間を移動中なら、歩行進捗と危険から安全な側への短い退避・その場待機・被害を決める。現在地から迂回できない人物には待機・退避先を持たせる。古い経路の機械的な逆走はしない。
- 暦・生活・災害を共通の固定ステップ時計で進める。時間倍率は全系統へ同じく作用し、停止・背景タブでは災害だけが進むこともない。
- 一日は仮に実時間30〜60秒、季節は8〜12日のゲーム内暦を候補として比較する。この候補なら1年16〜48分で、現行の3分12秒より大きく遅くなる。建設・劣化・植生を暦の日数へ機械的に比例させず、最初の変化までの所要時間も比較する。短い暦は観察用の圧縮で、現実の年の再現ではない。初期の生活と街の変化が見える速さをプロトタイプで決める。150秒の生活と4秒/週を並存させる現行仕様からは移行する。
- 神の操作は`id / atStep / source / kind / target / radius / intensity / duration / seed`を持つ命令として受け付け、確定した固定ステップで適用。停止中も力を使え、命令と範囲を予約する。「雨を予約した」「予約範囲・件数」「再開／一歩進める」を表示し、取消・重ね掛けができる。予約であることを示さず、押しても作用しない状態にはしない。
- 災害・街の意思決定・外観の乱数を分ける。粒子の描画回数で隕石の被害や人口が変わらない。同じセーブと同じ時刻の命令列で、同じ未来を再現できるようにする。同時刻の相反する介入も命令ID順などで順序を固定する。
- 重ねた雨は水量を加算、風は合成、火は残る燃料と水分へ作用するなど、現象ごとの合成ルールを持つ。範囲外や負の強度など不正な入力は処理前に排除する。

## 保存と負荷

保存V3には住民と世帯、在庫、資源の輸送、避難先、継続中の災害、命令キュー、乱数状態、固定ステップ時刻、土地の通行性を保持する。説明用の短い街ログを再現用命令履歴の代わりにしない。

V1/V2の移行では地形・建物・既存人口を保持する。活動人口だけだった旧人物と、残りの人を区別して新モデルへ補う。家を失って帰宅途上にある旧人物も含め、単純に人物数を2倍せず新旧の人口総数を照合する。全員が突然飢餓になる初期化は避け、補った在庫・健康などの項目と移行猶予を明示する。旧`age`・`changedAt`・滞在`timer`には単位の変換を定義し、旧暦の履歴は旧日時として保存する。経路が壊れた災害途中の保存も、旧経路の存在だけで拒否せず、正しい現在位置・待機・避難状態として読み込めるようにする。

復元点は命令を消すだけでなく、世界全体・乱数・キューを戻す。少なくとも直前の適用バッチの前を保存し、後段で名前付きの分岐記録を検討する。保存領域の失敗は通知し、元の有効なセーブを先に消さない。

地図上の短い範囲の更新、道路の接続グループ、住居・仕事の索引、経路の共有を使い、人物ごとの全セル探索を避ける。表示負荷を下げる際も、住民数の帳尻や旅行中の人物を勝手に変えない。48×48、人口500・1,000・2,000を負荷測定候補とし、上限と12×での挙動を実測で決定する。保存形式が受け付ける最大値を性能保証として扱わない。

## 画面・ドット絵の方向

街を主役にした現在の画面を使う。キャンバス付近に「観察／恵み／災い」の操作を置き、力を選んだときだけ範囲・強さを開く。モバイルは画面下の小さな操作トレイにし、地図全体を覆わない。直接の都市建設メニューは初段階に追加しない。

天候は「次に来る雲」と現在の降水・風を簡単に示す。地図の補助表示は食・仕事への接続、浸水、火、避難先を切り替える。常時大量の数値や色を重ねず、選んだ介入に関係する危険と影響を優先する。

記録は「あなたが雨を降らせた」だけでなく、「水分が戻った畑」「収穫された量」「食の不足が改善した世帯」と、短期・中期の結果をつなぐ。予測と実測を区別し、選んだ家の不調の理由に食・雇用・安全・建物損傷を表示する。

整数座標・限定パレットのかわいいドット絵を継続。人物は傘、食料かご、修繕道具、避難の荷物で行動を見分ける。雲、雨、屋根の欠け、瓦礫、芽吹きを複数段階で描き、派手な全画面エフェクトが因果を隠さないようにする。低モーションでは閃光・揺れを減らし、同じ被害と状態が文字や地面の絵から分かるようにする。

## 段階的な開発順

| 段階 | 作るもの | 到達条件 |
| --- | --- | --- |
| A: 暮らしの土台 | 共通時計、住民と人口の整合、地区在庫、食の成功/不足、労働と生産、資材修繕、V3の基礎 | 雇用だけ良ければ食0でも繁栄する抜け道がなく、不足と回復を住民行動で読める |
| B: 最初の神の実験 | 晴れ・曇り・雨・雪、乾燥・浸水、恵みの雨、雲を払う、局地豪雨、橋の通行性、地区間輸送と分配停止、避難と復旧、復元点 | 乾いた畑を助ける／雨を続けて地区を孤立させる／水が引いた後に暮らしが戻る、を一つの町で操作できる |
| C: 災害と暮らしの幅 | 風・嵐、雷と延焼、地震、小さな隕石、搬送役の可視化、移住と再建の可視化 | 同じ力でも地形・道路・備蓄で違う結果。人数だけでなく人の行動と町の姿が変わる |
| D: 世界を終わらせ、また育てる | 大隕石・隕石群、広域被害、滅亡後の自然、芽吹き・入植、未来の分岐比較 | 全滅後も観察・復元・新しい生活の開始ができ、被害と復興の記録が残る |

最初の試作はA/B全体ではなく、「雨 → 作物 → 一地区の在庫 → 食べる住民 → 家の不調／回復」を一続きに触れる狭い範囲にする。ここで共通時計・資源決済・保存の基礎を確かめ、その後A/Bを広げる。Bまで到達したら豪雨と避難・復旧を実際に触って確かめる。災害の種類を揃えてから生活の反応を後付けする順は避ける。C/Dを落とす計画ではなく、ユーザーの全要望へ到達するために因果と保存を先に固める順。

## 検証と面白さの判断

今回は設計文書のみのため、テストランナー・buildは実行しない。実装時は適切なコア検証と、ユーザー指定のアプリ内ブラウザなどで実画面の操作確認を行う。localhostが保存済み拒否設定でブロックされる場合、承認されたURLだけを使い、未確認と公開済みの確認を混同しない。

最低限、以下のシナリオで作用と見た目を対にする。

1. 同じ初期世界へ、雨なし／恵みの雨／豪雨の命令列を与え、水分・収穫・食の充足・人口の差と理由を比較。
2. 畑は濡れているが働き手が来ない場合、雨だけでは収穫できない。店の在庫0では購入失敗を記録。
3. 橋が壊れたときに通勤・輸送を止め、避難・待機・迂回を確認。壊れた橋の逆走や瞬間移動がない。
4. 食不足が続いた場合に猶予→健康低下→活動減→移住等が起き、食の回復後には途中の状態に応じて立て直せる。
5. 水や火の範囲・量、建物損傷と人口の出入りが負値・重複・不正な参照を生まない。死亡と移住を二重計上しない。
6. 災害直前／最中／避難中／滅亡後の保存復元が同じ世界へ戻る。同じ命令列とフレーム速度の違いで未来が変わらない。
7. 1×/4×/12×、停止、背景復帰で全系統の時間が整合。連続する介入でも処理落ちで見えない命令の欠落が起きない。
8. 1280px以上、768px、390px/320pxで介入・取消・復元を操作。地図ドラッグと力の発動が競合せず、状態を色だけに頼らない。
9. 無操作でも町の発展・不調・自然の回復が見え、救済を連打しないと観察できない調整になっていない。

面白さは別に確認する。「雨の効果と限界を自分の言葉で説明できる」「災害後に一人の住民を追いたくなる」「同じ力を別の地区で試したくなる」「滅亡後の再出発を自分で選べる」をプレイ観察の問いとする。数値の増減や静的レビュー成功だけを面白さの証拠にしない。
