# まちの呼吸 — 開発計画

制作開始: 2026-09-30（Asia/Tokyo）。開発前にユーザーの承認済みコンセプトを具体化した計画。

## 目指す体験

小さな町が自分で育ち、にぎわいの中心が移り、古い場所に緑が戻る様子を眺める。操作は観察のために使う。資金管理・建設メニュー・勝敗・LLM連携は初版の範囲に含めない。

中心の仕組みは「周囲の暮らしが次の暮らしを生む」。観察の循環は「変化に気づく → 地点を選ぶ → 理由を知る → 時間を進めて結果を見る」。建物の成長と環境負荷、にぎわいと老朽化の拮抗が町の世代交代を生む。

## 仕様

| 項目 | 初版 |
| --- | --- |
| 土地 | 48×48マス。川、草地、林、二つの小さな集落、初期の道路・橋。シードで再現可能 |
| 建物 | 家、商店、農地、工場。成長段階、人口、築年、活力。空き家から草地へ戻る |
| 更新 | 固定ステップで近隣の状態を集計し、古い状態から次の状態を決める。1ステップ=1週、48週=1年、12週=1季節 |
| 速度 | 通常は実時間2秒で1週。一時停止、1×・4×・12×。10〜20分で複数世代の変化が見える |
| 見た目 | 斜め見下ろし2Dドット絵。屋根、窓、庭、畑、看板、木、川、橋、影を描き分ける |
| 小さな動き | 道路上の人、煙、水面、昼夜と窓明かり。昼夜は観察用の短い演出周期、季節・築年はシミュレーション時間 |
| 観察 | 建物や土地を選ぶと現在の状態と理由を表示。街の変化ログ、人口推移、建物数、環境を表示 |
| 操作 | 停止、倍速、ズーム、ドラッグ移動、全体表示、町の再生成、直前の町に戻す、写真保存 |
| 続き | localStorageで現在の町を保存。破損・旧形式・ストレージ拒否でクラッシュせず、理由を表示 |

## シミュレーションの因果関係

1. 道路沿いで仕事と生活施設に届き、環境が良い土地に住宅が生まれる。
2. 人口の増加が商店の需要を生み、農地・工場が仕事を供給する。
3. 道路は近隣の人口と活動から伸びる。川を越える箇所は橋として描画する。
4. 工場の排出、密集、古い建物の維持負担で活力が下がる。商店も客不足で衰退する。
5. 活力の低下が続くと空き家になり、一定期間後に草地へ戻る。緑が環境を回復させ、条件の良い場所で再び住宅が生まれる。
6. 地域ごとの需要と季節変化を補助要因にし、単調な飽和を避ける。建物の発生・消失を無条件のランダム置換にしない。

近隣集計の半径と更新量を制限してモバイルでも描画と更新が両立するようにする。最初の30〜60秒で新しい建物が見えること、長期に全滅・工場一色・静止状態にならないことを測定して調整する。

## 画面と操作設計

- 紙のような淡い背景、読みやすい日本語、街の大きなキャンバスを主役にする。
- 上部にタイトル、現在の年・季節、再生成。キャンバス下に停止・速度・拡大縮小・全体表示を置く。
- 右側に地点の観察、人口推移、街の記録。モバイルはキャンバスの下へ移す。
- 選択前には「建物を選ぶと、変化の理由が見えます」。空き地・川も専用の説明を持つ。
- キャンバスはキーボードフォーカス可能。矢印で地点を移動、Spaceで停止、+/-でズーム。フォーム操作中のキーを奪わない。
- 再生成は元の町に一度戻せる。写真保存はPNG。通常の観察中にダイアログを挟まない。
- prefers-reduced-motionでは細かな動きを抑え、停止・速度の状態は文字でも示す。

## 技術選定

TypeScript + Canvas 2D + Vite。既存アプリで使われるTypeScript/Vite/oxlintを開発用依存に採用する。型・高速な開発サーバー・静的検証のため。描画や状態管理の実行時ライブラリは追加しない。Canvasの自作ピクセル描画で、実際の状態と素材の見た目を一致させる。

## 分担と実装順

1. メイン: ルートAGENTS.mdのモデル選定更新、この計画とアプリ固有方針、共有型、package設定を作成。
2. Sol 6.1（シミュレーション担当）: `src/simulation.ts` と `tests/simulation.test.ts`。シード生成、局所ルール、理由、統計、保存復元、長期検証。
3. Sol 6.1（描画担当）: `src/renderer.ts`。地形・建物・生活のドット絵、カメラ、座標変換と地点選択。共有型と計画を参照。
4. メイン: `index.html`、`src/main.ts`、`src/style.css`。UI、固定ステップ、選択、保存、写真、アクセシビリティを統合。
5. メイン: 実ブラウザで操作と画面を確認し、必要な調整後、README・apps.json・検証記録・カバー画像を整える。

ファイルの同時編集を避ける。必要ならLuna 6.0に読み取り専用の軽いレビューを任せる。重い実装をSol 6.1に割り当て、Astraを自動選択しない。

## 完了条件と検証

- 同一シードで同じ初期状態・更新結果。別シードで地形や町が変わる。
- 水域に住宅が生まれない。人口等がNaN/負値にならない。出生、成長、衰退、再生、道路発生が実際に発生する。
- 複数シードで数千週進め、全滅や単一種類への収束がないことを測る。シミュレーションの時間・人口・建物数のサンプルを記録する。
- 停止中は街の週数が変わらない。4×/12×で進行速度が変わる。背景タブから戻っても追いつき更新を大量に実行しない。
- 保存と復元で町が一致。破損保存、書込拒否は画面に状態を示して観察を継続できる。
- デスクトップ1440×900、タブレット768px、モバイル390px/320pxで主要操作・画面の欠落や横はみ出しを確認。
- Chromiumで実際の停止・倍速・地点選択・ズーム・再生成・復元・PNG保存を操作。コンソールエラーなし。
- アプリの `npm run check` とルートの `npm test`、登録したアプリのcheckを実行。静的配信で相対パスが動く。
- ブラウザ確認の画像と結果を `docs/` に保存。Safari/Firefoxや実機未確認は明記する。

## リスクと調整方針

- 更新が見えない: 最初の集落と道を置き、最初の変化までの週数を測る。
- 成長だけで平坦: 老朽化、需要不足、環境回復、地域需要の変化を含め、履歴で世代交代を確認。
- 雑然として読めない: 建物のシルエットと屋根色を分け、余白のある緑地と川を残す。数字はDOMに置く。
- 原因が伝わらない: 各セルの直近の変化理由を状態に保存し、クリックで読めるようにする。
