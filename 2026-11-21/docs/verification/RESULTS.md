# 試作の検証結果

## 配置とキッカー

改修前の本番ビルドを Chrome で1周した。ピンの種類は違っても列と間隔が両面で似ており、次に通したい場所を予測して狙う手掛かりが少なかった。第1面は直接落とす場所とキッカーから中央のピン群へ送る場所を分け、第2面は高さと向きの違うキッカーを2か所置いた。

初版の通し操作では、面が替わったときに前の照準が壁際に残り、キッカーの初手を見つけづらかった。各面でキッカーに照準を合わせ直した。初版では衝突直後の反応も追いづらかったため、キッカー本体の縁と矢印を光らせ、飛んだ方向へ伸びる光と球の軌跡を伸ばした。Chromeで実際に当て、発光と向きが合うことを途中のフレームでも確認した。

レビューと追加計測では、第2面でも上段のキッカーに初期照準を置くと、固定シードの初球だけで両方の強化がノルマに達した。初期照準を下段に移して横への反発を体験し、次の球で別のルートを選ぶ流れにした。

固定シードで初球だけ落とし、その球と追加球が盤面から落ちきった時点の得点と連鎖をシミュレーションで比較した。

| 面・強化 | 投球位置 | 初球の得点 | 一投の連鎖 |
| --- | ---: | ---: | ---: |
| 第1面 | 520 | 91 | 13 |
| 第1面 | 480 | 6 | 3 |
| 第2面・青 | 440 | 595 | 34 |
| 第2面・青 | 520 | 325 | 25 |
| 第2面・黄 | 440 | 136 | 16 |
| 第2面・黄 | 520 | 276 | 23 |

第1面の2か所はいずれもキッカーに当たり、後続のピンが変わった。第2面の比較では青なら440、黄なら520のほうが得点が高かった。24シードで第1面の初期照準から落とすと、全試行でキッカーに当たり、22試行で6連鎖以上になった。

- 本番ビルドを Chrome のマウス・キーボード、320px幅のタッチ、動きを減らしたタッチで操作し、3周とも2面クリアと再挑戦を確認した。第1面の初球から13連鎖して2球補充。第2面を下段から始めると青15点・黄6点で、2球目の位置を変えると青450点・黄216点に伸びた。同じ初手を3回続けて失敗することもルールテストで確認した。
- キッカーが左右へ球を送り、発光と大きい連鎖表示が出た。動きを減らした設定では発光・紙吹雪・大きい連鎖表示が出ず、同じ入力でタッチ版と同じ点数になった。
- `npm run check` でルールテスト11件、型チェック、本番ビルドが通った。スマートフォン実機、音の聴感、初見プレイヤーが次の狙いを自分で見つけられるかは未確認。

## 補充直後の投球

改修前の本番ビルドを Chrome で開き、マウスと320px幅のタッチエミュレーションで各1周した。中央に3球落とし、手持ち0球の間にレールを右から左へドラッグした。補充されると最後に落とした中央に球が戻り、押さえていた操作を解除しても手持ちは1球のままだった。4球目を放すには狙った場所を押し直す必要があった。

補充待ちのドラッグを受け付け、狙った位置に空の照準を表示した。0球から補充されると同じ位置に球と短い光の輪が出る。補充中もシミュレーションを進め、押さえたままの操作を離すとその位置から放てるようにした。

- 同じレール操作をマウス、320px幅のタッチ、動きを減らしたタッチで再試行した。3周とも前の球が残る中、補充された1球を押し直さずに放ち、第2面をクリアして同じ配置で再挑戦した。第2面は青強化で308点、黄強化で251点だった。
- 別の試行では補充前に指を離すか Space を押し、補充後も手持ちが1球残ることを確認した。その後、タッチのキャンセルでは球が減らず、改めてタップか Space で球が落ちた。
- 手持ち0球でレールを押さえたまま失敗画面に入ると、押下が解除された。指を離しても失敗画面のままで、再挑戦は3球から始まった。
- 320px幅でも空の照準、補充後の球、レールの文言を確認した。通しプレイ中のコンソールエラーはなかった。`npm run check` のルールテスト8件、型チェック、本番ビルドが通った。スマートフォン実機と、初見で次の一球を放ちたくなるかは未確認。

## 盤面内のUIに改修

改修前の Chrome では、PCで盤面の横、スマートフォン幅で盤面の下に、遊び方と結果が並んでいた。一台の筐体に組み直し、手持ちと得点は上枠、投球の案内はレール、強化と結果は盤面の中央に置いた。

初版を実際に操作すると、320px幅の失敗画面で下側の再挑戦ボタンが盤面からはみ出た。1440×900と844×390では筐体の下端まで表示するのにスクロールが必要だった。強化は青と黄を横並びにし、結果は得点と再挑戦を一段ずつに組み直した。短い通知をレールに移し、筐体の上下枠と余白を含めて高さを設定し直した。

- 本番ビルドを macOS の Chrome で開き、1440×900のマウス・キーボード、320×568と844×390のタッチエミュレーションで第1面から再挑戦まで通した。全幅でスクロールなしに強化と再挑戦を選べた。320px幅での失敗画面でも2つのボタンが盤面内に収まり、それぞれ44px以上の高さを確保した。
- 3球の連投から補充された4球目を放ち、青強化で第2面308点、黄強化で251点を取った。強化後に手持ち3球で投球に戻り、結果から同じ配置での再挑戦と別配置への切替も操作した。キーボードで選択後にレールへフォーカスが戻り、左右キーと Space で投球できた。
- 動きを減らしたタッチ操作で失敗、再挑戦、補充球の投球を確認した。WebGL 2 を意図的に無効化すると、盤面内にエラーと対処が出てレールが無効になった。別にプレイ中の描画を一時停止・復帰させ、手持ちを保った状態でレールにフォーカスが戻り、投球を再開できた。実機のタッチと、初見の人が案内だけで狙い方を理解できるかは未確認。
- `npm run check` でルールテスト8件、型チェック、本番ビルドが通った。既存の JavaScript サイズ警告は継続している。

## 補充のタイミング調整

第1面の25シードに6通りの投球を組み合わせ、最初の3球から補充が起きるかをシミュレーションした。初回までの秒数は、補充が起きた試行の中央値。

| 補充する連鎖数 | 補充が起きた試行 | 投球開始から初回補充まで |
| --- | --- | --- |
| 6 | 131 / 150 | 1.72秒 |
| 8 | 116 / 150 | 2.17秒 |
| 10 | 81 / 150 | 2.53秒 |

第1面の初回補充が遅れにくい6連鎖を採用した。実画面では320px幅で盤面上の補充バッジがピンに重なったため、手持ちの数字の横に移して再確認した。

### 通常操作での結果

macOS の Chrome で本番用ビルドを開き、中央に3球連投した。手持ちが0の間は投球できず、連鎖で1球戻ったら、先の玉が残っている間に4球目を左寄りから放せた。4球目を放つ直前の44点から、第1面のノルマを超える89点まで得点が伸び、再び手持ちが増えた。第2面は手持ち3球で始まり、青強化で308点、黄強化で251点を取り、両方でクリアできた。

### 確認した範囲

- Node.js 24で `npm run check` のルールテスト8件、型チェック、本番用ビルドが通った。盤面の玉が残っている間の補充と4球目の投球、一投の中で6連鎖と12連鎖で補充すること、ピンが尽きた面の終了をテストした。Vite は約586 kB（gzip 約151 kB）の JavaScript にサイズ警告を出した。
- 320px幅のタッチエミュレーションで、補充表示が手持ち欄に収まり、補充した4球目を放てた。390px幅で動きを減らす設定を有効にすると、カウンターと補充のお知らせが更新され、動くバッジなしで4球目を放てた。通し操作でコンソールエラーは発生しなかった。
- Chromeで全ピンを倒した後、手持ち4球を残してレールが閉じ、待機の案内が出た。盤面の玉が落ちきると強化選択に進んだ。
- Codex 内蔵ブラウザを更新し、手持ち3球と補充ルールが表示された。

連鎖の気持ちよさ、効果音の聞こえ方、プレイヤー自身が強化に応じて狙いを変えるかは、人による試遊で確かめる。スマートフォン実機と Chrome 以外のブラウザも未確認。
