# CodexのAI Slopレビュー

このリポジトリでは、ファイルを変更したタスクの完了前に、Astraの `ai_slop_reviewer` が今回の成果を確認する。対象、実施条件、修正後の再確認はルートの `AGENTS.md` に定める。

AI Slopを「依頼の目的、題材、根拠、実際の動作との対応が薄く、定型的な文章・装飾・実装で完成したように見せている出力」と捉える。確認基準と報告形式は `.codex/agents/ai-slop-reviewer.toml` に置く。

## 進め方

1. 親エージェントが実装と対象に適した検証を行う。
2. `ai_slop_reviewer` を起動し、依頼の目的と制約、今回の変更範囲、開始前からある変更、関連仕様、検証結果と未確認範囲を渡す。Gitがcleanでも、タスク中にコミットした変更は対象に含める。
3. レビュアーは対象と必要な周辺実装を読み、根拠・影響・修正案・再確認方法を返す。ファイルの編集は親が行う。
4. 親が指摘を判断し、必要な修正と検証を行う。修正した差分と影響範囲をレビュアーに再確認させ、採用しなかった指摘には理由を残す。
5. 親がレビュー担当と実際のモデル、指摘への対応、残る問題と未確認事項を含めて完了報告する。

カスタムエージェントを選択できないクライアントでは、`gpt-6-astra` を明示した新規サブエージェントに、定義ファイルの `developer_instructions` と必要な資料を渡す。モデルを切り替えられない履歴継承モードは使わず、必要な文脈を明示する。Astraが使えない場合は、未実施の理由を報告し、レビュー済みと扱わない。

## 設定と制限

- 定義はプロジェクト内の `.codex/agents/ai-slop-reviewer.toml` に置く。ユーザー共通の設定や他プロジェクトは変更しない。新しい定義や `AGENTS.md` の反映は、このプロジェクトの新しいチャットで確認する。
- `model = "gpt-6-astra"`、`model_reasoning_effort = "low"` を明示する。モデルの利用可否はアカウントとクライアントに依存する。レビュー回数と渡す情報の量に応じて追加の利用量を消費するため、対象と必要な周辺実装に範囲を絞る。
- レビューは親エージェントが起動して結果を受け取る。`AGENTS.md` は実施を求める指示であり、未実施での終了をプログラムで阻止する仕組みではない。
- レビュアーの「編集しない」は行動指示であり、独立した読み取り専用サンドボックスを与える設定ではない。カスタムエージェントは親の権限を継承する。
- 指摘なしは、全ての誤りやAI Slopが存在しない証明ではない。実画面、別ブラウザ、公開環境、出典や実体験の確認は、実施した範囲だけ報告する。既存のテストや必要な実操作の確認も引き続き行う。
- この運用のためのCodex hook、外部CLIの入れ子起動、独自API呼び出しは置かない。`AGENTS.md` やskillの自動更新も行わない。

公式仕様: [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。
