# Web フロントエンド共通指針

この文書は、日付フォルダ内の Web UI に共通する実装上の指針を定める。共通の配色・文字・部品の基準は `docs/DESIGN.md` を使い、アプリ固有の画風や追加部品、画面仕様は対象アプリの文書と実装に従う。

## 実装

- 変更前に対象アプリの画面、構成、既存部品、データの形を確認する。
- 共通トークンとアプリ内に再利用できる部品を使い、同じ意味の UI に別の振る舞いを作らない。
- コントロールの種類とラベルは操作の意味に合わせる。ボタンとリンクを使い分け、アイコンだけの操作には分かる名前を付ける。
- 新しい要素や装飾は、情報理解や操作に必要な理由がある場合に追加する。
- loading、empty、success、error、disabled など、実際に起こる状態ごとに次の行動が分かるようにする。

## 画面幅とアクセシビリティ

- 対象アプリが対応する最小・最大の画面幅と、その間の代表的な幅で実画面を確認する。
- 文字、ボタン、入力欄、ナビゲーション、長いデータが欠けたり、重なったり、意図せず横にはみ出したりしないようにする。
- hover だけに操作の意味を持たせず、タッチとキーボードでも主要操作を使えるようにする。
- フォーカスを見えるようにし、フォームのラベル、エラー、画像の代替テキストを適切に用意する。
- 色のコントラストと、色以外での状態の伝達を確認する。
- アニメーションを使う場合は、操作や読解を妨げず、動きを減らす設定に対応する。

## 変更後の確認

1. 実際のブラウザで主要な操作と必要な状態を確認する。
2. 対象端末の幅で文字、レイアウト、入力方法を確認する。
3. 対象アプリの実行コマンドと検証コマンドを確認し、必要なものを実行する。
4. 確認できなかったブラウザ、端末、状態を報告する。
