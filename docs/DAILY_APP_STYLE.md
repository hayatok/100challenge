# Daily App Visual Style

この文書は、100日チャレンジで毎日作るミニアプリの共通ビジュアル方針を定義する。

基準となる実例は `2026-09-01/` の「やってる感」。ただし、画面や配色をそのまま複製するためのテンプレートではない。アプリごとの題材に合わせて色やモチーフを変えながら、同じ視覚言語と温度感を保つ。

個別アプリについて承認済みのデザイン方針や、ユーザーから明示された別の方向性がある場合は、そちらを優先する。

## Character

目指すのは、整いすぎた業務SaaSではなく、内容に合わせて少し大げさに演出された「触って楽しい道具」。

- 一目で用途が分かる
- 真面目に使えるが、見た瞬間に少し笑える
- 人が作ったポスター、チラシ、雑誌、ゲーム画面のような手触りがある
- 装飾は題材や操作の意味と結び付いている
- ジョークのために読みやすさや操作性を犠牲にしない

## Visual language

### Shape

- 主要な面、入力欄、ボタンには太く明瞭な輪郭線を使う
- 角丸を習慣で付けず、原則は直線的で少し武骨な形にする
- 影はぼかさず、印刷物を重ねたような硬いオフセットシャドウを使う
- 重要な要素に限り、1〜3度程度の傾きやわずかな位置ずれを使う
- すべてを傾けない。本文、長文入力、主要フォームは安定させる

### Color

- アプリごとに3〜5色程度のフラットなパレットを決める
- 明るい背景色、暗いインク色、主アクセント、補助アクセントを役割として定義する
- 色相は毎回変えてよい。黄色・赤・水色の固定テンプレートにはしない
- 装飾的なグラデーション、半透明の光球、ガラス表現、発光は原則使わない
- 状態や意味を色だけで伝えず、輪郭、形、文言も併用する

### Typography

- 主見出しは太く、短く、ポスターのように扱う
- 補助情報や番号には等幅書体を使い、印刷物や機械ラベルの雰囲気を出してよい
- 本文とフォームは読みやすいシステムフォントを優先する
- 大見出し、本文、注釈の差を明確にし、中間サイズを増やしすぎない
- 日本語の不自然な改行、詰めすぎ、過度な英字装飾を避ける

### Imagery

- 抽象的なAI風イメージより、題材を具体的に見せる人物、物、図を優先する
- 面白さの核になる画像は、原則として1画面に1つの主役に絞る
- 画像にはラベル、額縁、切り抜き、傾きなど、内容に合った編集意図を持たせる
- 意味のない絵文字、汎用的な3Dオブジェクト、青紫の抽象背景で空間を埋めない

## Interaction and motion

演出は、操作の結果を説明するための短いリアクションとして使う。

- 主操作、再試行、コピーなど、意味の異なる操作には異なるリアクションを割り当てる
- 題材に合う比喩を選ぶ。例: 印刷、ハンコ、紙の差し替え、メーター、くじ、スタンプ、物理的な跳ね返り
- 通常の演出はおおむね150〜700msで完了させ、次の操作を待たせない
- loading中の反復動作は控えめにし、進行状況を隠さない
- hoverだけに意味を持たせず、pressed、success、errorも設計する
- `prefers-reduced-motion` では移動、回転、点滅を停止または簡略化する
- 演出によるレイアウト移動、フォーカス喪失、文字の読めない時間を作らない

## Copy and tone

- 文言は短く、具体的で、人が口にする言葉にする
- 説明しすぎたAI風のコピーや、意味の薄い横文字を増やさない
- ジョークは一文で伝わるものを優先し、UI全体で同じネタを繰り返さない
- 装飾のためだけに新しい文言を追加しない
- ユーザーが承認した文言は、見た目の変更を理由に書き換えない

## Avoid generic AI UI

以下を初期案にしない。

- 青紫のグラデーションを背景にした中央寄せのヒーロー
- 薄い境界線、淡い影、大きな角丸を全要素へ一律に適用したカード群
- 理由のないピル型ラベルとステータスバッジの大量使用
- 抽象アイコンだけで機能を説明する構成
- どのサービスにも転用できる無個性なダッシュボード
- 派手だが操作結果と関係のない常時アニメーション

## Implementation checklist

- [ ] 題材に合う視覚的なジョークまたは比喩が1つある
- [ ] 3〜5色の役割が定義され、コントラストを確認した
- [ ] 太い輪郭と硬い影が、主要な階層を分かりやすくしている
- [ ] 主操作が最も目立ち、補助操作と区別できる
- [ ] 操作演出が結果と結び付き、短時間で終わる
- [ ] reduced motionでも状態が分かる
- [ ] 375px、768px、1024px、1440pxで確認した
- [ ] loading、empty、error、success、disabledを必要に応じて確認した
- [ ] 文言や機能を、デザイン都合で勝手に変更していない
- [ ] スクリーンショットで文字欠け、重なり、横スクロールを確認した
