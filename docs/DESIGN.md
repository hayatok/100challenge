# 共通デザイン原則

この文書は、今後作るアプリの UI に共通する判断基準と、操作部分の最小限のデザイン定義を定める。対象ユーザー、目的、作品部分の画風・素材・画面構成は各日付フォルダの文書で決める。既存アプリへの遡及変更は求めない。

## 目的と情報の優先順位

- 画面を見た人が、何を理解し、何を操作できるかを明確にする。
- 最も重要な情報と主操作を見分けられるようにする。補助情報や装飾がそれらを妨げないようにする。
- 情報量と余白は用途に合わせる。画面の種類だけを理由に装飾やカードを増やさない。
- 実際のデータ、操作、状態に合う文言と素材を使い、意味のない仮素材を完成版に残さない。

## 一貫性と表現

- 一つのアプリの中では、同じ意味の操作や状態に同じ表現を使う。
- 操作部分には以下の共通定義を使う。作品やゲーム画面に必要な独自の表現、共通定義からの例外は、日付フォルダの文書に理由とともに記録する。
- 装飾や演出は、意味、階層、状態、題材の表現に役立つ場合に使う。
- アニメーションは操作を妨げず、動きを減らす設定を尊重する。
- 色だけで状態を伝えない。文字、形、配置なども使う。

## 共通 UI トークン

色は役割で参照する。Web では以下の CSS 変数名を使い、他の環境では同じ役割と値に対応させる。

| 役割 | 変数名 | 値 |
| --- | --- | --- |
| 画面背景 | `--ui-canvas` | `#F4F0E8` |
| 入力欄・操作面 | `--ui-surface` | `#FFFDF8` |
| 本文・強い輪郭 | `--ui-ink` | `#20201E` |
| 補助文 | `--ui-muted` | `#5B5A54` |
| 控えめな区切り | `--ui-line` | `#C9C4BA` |
| 主操作・フォーカス | `--ui-accent` | `#B73529` |
| 成功 | `--ui-success` | `#245B3D` |
| エラー | `--ui-error` | `#A52E25` |

- 本文はシステム UI フォントを基本とし、日本語は `Noto Sans JP` など利用可能な書体へフォールバックする。本文は 16px・行間 1.6、補助文は 13px を基準にする。
- 余白は 4px を単位に、8 / 12 / 16 / 24 / 32px から選ぶ。基本の角丸は 4px、入力欄と操作部品の輪郭は 2px とする。
- アプリ固有の色は題材や作品部分に追加できる。操作部分の意味色を変える場合は、日付フォルダの文書に対応関係を記録し、文字と背景のコントラストを確認する。

## 共通コンポーネント

| 部品 | 基本形 |
| --- | --- |
| 主ボタン | 高さ 44px 以上、濃い輪郭 2px、角丸 4px、`--ui-accent` 背景と白文字。主操作にだけ硬い 3px のオフセット影を使う。 |
| 通常ボタン | 主ボタンと同じ高さ・輪郭・角丸。`--ui-surface` 背景と `--ui-ink` 文字。主ボタンより目立たせない。 |
| 入力欄 | 高さ 44px 以上、輪郭 2px、角丸 4px、`--ui-surface` 背景。ラベルを常に表示し、エラー時は文言と `--ui-error` を併用する。 |
| 情報のまとまり | 関連する内容を囲む必要がある場合だけ面や輪郭を使う。区切りだけなら余白か `--ui-line` を使い、カードを重ねない。 |
| 状態表示 | 成功・失敗の色に加えて状態の文言と次の行動を示す。必要なら左側に 4px の状態色の線を使う。 |

- キーボードフォーカスは 3px の `--ui-accent` 輪郭と 3px のオフセットで見せる。アイコンだけのボタンも 44px 四方以上の操作面と名前を持たせる。
- 無効状態は操作できないことを形と文言で伝え、色や透明度だけに依存しない。

## 状態と利用環境

- そのアプリで起こり得る初期、読み込み中、空、成功、失敗、入力エラーなどの状態を設計する。存在しない状態を形式的に追加しない。
- 対象端末と入力方法に合わせ、文字の可読性、操作のしやすさ、フォーカス、画面幅による変化を確認する。
- 参考画面は見た目の模写だけでなく、情報の優先順位、余白、操作、状態、画面幅への対応を読み取る。
- 設計上の仮説と実際の利用・操作で確認した結果を区別する。
