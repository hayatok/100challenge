# このプロジェクトのCodex品質hook

## 目的と範囲

AI Slopを「依頼の目的、題材、根拠、実際の動作との対応が薄く、定型的な文章・装飾・実装で完成したように見せている出力」と捉え、終了前に今回の変更を確認する。

- Goal: 今回変更した文章・実装について、具体的な品質確認を一度行う。
- Context: ルートと対象アプリのAGENTS.md、DESIGN.md、FRONTEND.md、依頼内容と実際の変更。
- Constraints: 既存の未コミット作業を保持する。単語や色だけで違反としない。追加API・依存関係・グローバルhookを使わない。
- Done when: 誤りがあれば必要な範囲だけ修正・再検証し、未確認の範囲を最終報告に残す。

## 有効化

設定はリポジトリ内の `.codex/hooks.json` にある。`~/.codex/hooks.json` とユーザーの `config.toml` は変更しない。このリポジトリを開いたCodexでのみ読み込まれ、アプリの配布物には含めない。

1. このプロジェクトを開いているCodexを再開するか、新しいチャットを始める。
2. プロジェクトが信頼済みであることを確認し、Codexのhook確認画面で `UserPromptSubmit` と `Stop` のコマンドを確認して信頼する。CLIの場合は、このリポジトリで `codex` を起動し、`/hooks` を入力する。
3. `.codex/hooks/quality.mjs` を実行する2つのhookが有効になっていることを確認する。以後は通常どおり作業を依頼する。

Codexは未承認のhookをスキップする。定義を変更した場合も再確認が必要。作成しただけのhookや、この文書の手順だけを根拠に「実際に発火した」と扱わない。

必要な実行環境はGitとNode.js。CIではNode.js 24を使用する。コマンドはGitのルートを基準にスクリプトを解決するので、日付フォルダからの起動にも対応する。

公式仕様: [Hooks](https://learn.chatgpt.com/docs/hooks)。`command` handlerとJSON出力を使用する。`Stop` の `decision: "block"` は、理由をCodexへ渡して作業を続けさせる。

## いつ何をするか

| タイミング | 処理 |
| --- | --- |
| UserPromptSubmit | 確認基準をCodexへ渡し、開始時のHEADと既存の差分のハッシュを記録する。同一turnの重複イベントで記録を上書きしない。 |
| 最初のStop | 開始時の内容と現在を比べ、今回の変更があれば対象一覧と確認項目を返して一度だけセルフレビューへ戻す。途中でcommitしてcleanになった変更も対象に含める。 |
| 再度のStop | 同一turnの記録、または `stop_hook_active` によって継続中だと分かる場合は、再度差し戻さない。 |

変更のない相談は差し戻さない。新しい人間の依頼では、新しい開始時点を記録する。開始前からある未変更のファイルと、同じファイルの既存行にある候補語を今回の問題として挙げない。開始後に追加した行は、行ハッシュの個数を比較して抽出するため、既存行の順序変更は文字列の新規候補にならない。

## 確認基準

| 対象 | 確認すること |
| --- | --- |
| 説明文 | 実装済みの入力・操作・結果が読めるか。同じ結論の反復や、中身のない宣伝がないか。 |
| 根拠と報告 | 数値・体験・完了の主張に根拠があるか。未実施の検証を実施済みと報告していないか。 |
| 画面と操作 | 主操作を不要なカードや指標で隠していないか。操作が実際の結果につながるか。 |
| データ | 出典・単位・対象期間が分かるか。欠測を実測のゼロと混同していないか。 |
| 題材 | 題材を通じて何を理解できるか。作品に必要な笑い、雰囲気、操作への反応を保持しているか。 |
| 実装 | 追加した設定・抽象化・依存関係が現在の依頼に必要か。 |

文字列検査は、未完成の印、空のイベント処理、移動先のないリンク、抽象的な宣伝、欠測をゼロにする可能性を確認候補として示す。候補の件数は品質の点数ではない。引用、ドキュメントの説明例、固有名詞、意図した入力例を機械的に削除しない。テスト・fixture・evidence内の例文は文字列検査から除外する。

各指摘は、場所・観測事実・利用者への支障・最小限の修正・再確認方法をそろえる。根拠のない機能・数値・効果を修正文に足さない。テストや制約を弱めて通さない。

## 保管と制限

- 実行状態はOSの一時領域の `100challenge-quality-<uid>-<リポジトリ実パスのハッシュ>/` に保存する。`.codex/` が書き込み保護される環境でも動作し、Gitの変更に混ざらない。新規ディレクトリは0700、新規ファイルは0600。リポジトリ・セッション・turnごとに分離する。
- 保存内容はHEAD、パス、ファイルと各行のハッシュなど。ソース本文、会話、プロンプト、transcriptは保存・収集しない。候補の出力にも原文を転載しない。
- 記録の有効期限は24時間。古い状態は次回のhook実行時に削除する。OSによって一時ファイルが削除された場合も、今回の検査を省略した警告を返す。
- 対象は5,000ファイルまで。1ファイル256KiBを超える場合はサイズ・更新時刻による変更検知にとどめる。文章・コードの候補検査は合計80,000行までとし、上限を超えたファイルは候補検査を省略したと表示する。JSON・CSV・検証記録はハッシュで変更を検知し、文章の候補語では判定しない。ファイル件数・状態サイズの上限を超えた場合や状態が壊れた場合は、今回の検査を省略した警告を返す。
- 依存関係・build出力・lockfile・バイナリ・既知の秘密情報ファイル・シンボリックリンク先・入れ子のリポジトリは本文検査の対象にしない。別リポジトリのcwdを渡された場合は何もしない。
- 外部AI/APIや別エージェントによる独立レビューではない。現在のCodexへセルフレビューを要求する仕組みで、確認の質や修正の成功を保証しない。
- hook自体はアプリのtest・lint・build・ブラウザ操作を実行しない。Codexが対象アプリのコマンドと実画面で確認する。配色、情報階層、使いやすさ、架空データ、誤った出典などを文字列検査だけで合否判定しない。
- 再開後のhook読み込みと信頼操作、ユーザーによる中断、Codex側の失敗などにより発火しない場合がある。警告や候補0件を検証成功として報告しない。
- AGENTS.md、skill、hookの自動書き換えは行わない。再発した問題は既存の作業方針に従い、共通・アプリ固有の範囲を確認して記録する。

## 検証と停止

```sh
node --test .codex/hooks/quality.test.mjs
```

テストは一時Gitリポジトリで設定と同じコマンドを実行し、開始・変更・終了、既存作業の除外、commit後の変更、再入、他リポジトリ、シンボリックリンク、壊れた状態を確認する。これはイベントJSONによる実行試験で、Codexがこのチャットでhookを読み込み発火したことの証明とは分ける。

このhookだけ停止する場合は、`/hooks` で該当2つを無効にする。他のプロジェクトや他のhookを止める設定は必要ない。設定ファイルを削除して停止する場合は、次のチャット開始・再開時に反映を確認する。
